# analytics/

> L2 | 父级: ../CLAUDE.md

阅读量计数服务。独立于前端与 server/ 之外的第三块，部署在 Cloudflare Workers。

它存在的唯一理由是**宿主形态的限制**：站点托管在 GitHub Pages，是纯静态的，
页面自身没有任何地方可以记录「这篇被读了多少次」。server/ 那个 Express 只在
本地开发时起，线上并不存在，因此也接不了这个活。

## 一条必须先说清楚的设计前提

**阅读量只给站主看，不展示给读者。**

因此 `POST /hit` 返回 204 空响应，不回传任何数字——前端拿不到，也不需要拿到。
这不是省事，是刻意的：一旦数字回传到页面，下一步必然是显示出来，
而新站初期公开个位数阅读量对写作者没有任何好处。

读数有两条路，都要口令：

- `GET /stats?token=…` 返回 JSON，给 curl 和脚本用
- `GET /` 是一张网页面板，给人用。口令**不放在 URL 里**——那样会留在浏览器历史与书签中；
  页面首次打开时问一次，存进 localStorage，此后自动带上。面板本身不含任何口令，
  它只是空壳，数据仍要凭口令向 `/stats` 取。

面板存在的理由是摩擦：为看一眼数字而开终端、翻口令、敲一长串 curl，
这种代价会让人三天后就不再看，功能等于白做。

## 成员清单

src/counter.js: Worker 全部实现，四个端点。`GET /` 是内嵌的网页面板（含样式，
配色取自博客本体），带 noindex 不被收录。`/hit` 校验 slug 形如 `YYYY-MM-DD-slug`
后累加 KV——端点地址随前端产物公开，任何人可 POST，不校验则 KV 会被垃圾键塞满，
而免费额度按键数算。`/stats` 在 `STATS_TOKEN` 未配置时一律拒绝，绝不默认放行：
「忘了配置」不应该等于「对全世界开放」。CORS 只回显 `ALLOWED_ORIGIN` 单一来源，
不写 `*`——写 `*` 等于允许任何站点替你刷数。`/forget` 是清理通道，同样凭口令：
slug 只校验格式不校验文章是否真实存在（Worker 不掌握文章清单，让它去核对就成了
反向依赖前端），代价是任何人都能塞进格式合法却不存在的条目，因此必须有清理手段，
且它得在面板上点得到——**只能用命令行清理的通道，等于没有通道**。

test/counter.test.mjs: 28 项断言，`node test/counter.test.mjs` 直接跑，无框架无依赖。
用内存对象顶替 KV，因此不碰网络、不需要 Cloudflare 凭据——**部署前必须先跑通这个**。
这个 Worker 部署一次要走登录、建 KV、存 secret、deploy 四步，把逻辑错误留到那时候
才发现，代价远高于在这里跑一遍。覆盖的是行为而非实现：204 不回传内容、累加而非覆盖、
外站来源被拒且不写库、爬虫回 204 但不计数、非法 slug 不污染 KV、
未配置 STATS_TOKEN 时一律 401。

wrangler.toml: 部署配置。`ALLOWED_ORIGIN` 与 KV 绑定写在这里，
`STATS_TOKEN` 刻意不写——本文件入库，写进来的口令等于公开发布，必须走 secret。
KV 的 id 是醒目的占位串而非留空，好让未替换时在部署第一步就明确失败。

## 与前端的契约

前端只认一个环境变量 `VITE_VIEW_COUNTER_URL`（见 `app/.env.example`）。

**未配置时前端完全不发请求**，不是发了再吞错误——没部署的状态下不该产生任何网络噪声。
配置后，`pages/BlogDetail.tsx` 在文章加载成功后发一次，用 sessionStorage 按文章去重，
失败静默。计数失败绝不能影响文章阅读，这是主次关系。

## 已知的精度边界

KV 是最终一致的，并发写会丢计数。对个人博客的量级这是可接受的误差；
要精确得上 Durable Object，那是为这个数字付出的不相称的复杂度。
爬虫过滤只挡最廉价的噪声，不可能穷尽。
端点公开意味着数字可被人为灌水——它是给站主看趋势的参考，不是可信的统计口径。
