## 这份文档的取舍标准（2026-09 站主定，写文章前必读）

**本文档已停止追求完备，剩下的 ⬜ 不再补。**理由是站主在实操当天提的三条，每一条都成立：

1. **平台在持续优化，文档与实际有差异是常态。**穷举 UI 的保质期按周算。

   界面一变他就废了。而这个系列从头到尾讲的是「判据只有一种，自己回去看」。

筛选标准用计划书自己那条：**页面照常渲染、功能已经死了、而学员看不出来**。

## 零、开始之前

### 零之一 · 一件必须先知道的事：平台上有两个 System Prompt 来源

**这是全篇最重要的一条，不知道它，你会配好一半东西而毫不知情。**

🟡 `llms-full.md:8180-8184` FAQ 原文：通过助手聊天时，用的是**该助手配置的人设（System Prompt）**；
在工作空间内直接聊天时，用的是**工作空间的工作指引（System Prompt）**。两者共享同一个空间的
知识库与 Skill，**区别只在 System Prompt 的来源**。

🟢 **2026-09 实测确认，从推断升为事实。**做法是往工作指引里追加一条不可能被误认的标记指令
（「每次回答第一行必须原样输出某个标记串」），同一个问题问两次，只改一个变量：

| 提问方式 | 标记出现 | 结论 |
|---|---|---|
| 传 `botId` | ❌ 没出现 | 工作指引不生效 |
| 省略 `botId` | ✅ 出现在第一行 | 工作指引生效 |

两次都正确引用了同一份知识文件，所以 FAQ 那句「共享同一个知识库，区别只在 System Prompt 来源」
一并坐实。⬜ **边界**：验的是 API 层 `botId` 传与不传；界面上「选中助手」是否精确等于传 `botId`，
🔴 推导极可能是，未核。

| 你怎么聊 | 生效的是 | 不生效的是 |
|---|---|---|
| 选中 Bot 之后聊 | Bot 的**系统提示词** | 工作指引 |
| 不选 Bot，直接在空间里聊 | 空间的**工作指引** | —— |

**二选一，不叠加。**第 01 篇搭的是 Bot，所以规矩一律写进 **Bot 的系统提示词**，
**不碰工作指引**。这也是本篇最值钱的一条「常见错误」：新手一定会先看见左侧那个「工作指引」
菜单、把规矩认真写进去，然后建 Bot、开始对话——那段规矩一个字都不会生效，
而界面上看不出任何异常。

### 零之二 · 三件不用做的事

新手会在这三处岔出去，说明里要显式挡掉。

| 别做 | 为什么 | 等级 |
|---|---|---|
| 去组织设置里配 API Key | 那个 Key 只是**大模型渠道**，回答「用谁的模型算」，碰不到空间数据。搭这个 agent 一次都用不到。knodo 项目自评把「拿它当平台 API 凭证」列为最常见的错误 | 🟢 |
| 点 Bot 编辑弹框里的「个人技能」Tab | 那是给 Bot 绑 Plugin 的，属于打包与注册那一段，第 12 篇才讲。纯问答 Agent 完全不需要 | 🟡 `:8021-8030` |
| 写工作指引 | 见零之一 | 🟡 `:8180-8184` |

### 零之三 · 两件要先确认的事

**你的账号看得见几个空间。** 🟢 账号可见空间数可能远小于组织实有空间数。
建空间前先确认自己有没有创建权限。

**浏览器缩放先定死。** 为了截图清晰度，取景宽度有硬上限（见 `01-build-checklist.md` 零之二）。
普通屏把浏览器缩放调到 200%，**调完中途不要改**，否则前后几张图的界面大小对不上。

### 零之四 · 这个平台会怎么骗你

**搭之前先知道这一条，否则你会把「看着成了」当成「成了」。**

knodo 项目积累了一批 🟢 实测的静默失败——界面或接口报告成功，实际没生效：

| 形态 | 实例 | 等级 |
|---|---|---|
| 三层状态全绿而功能为零 | 插件状态 `PUBLISHED`、Bot 绑定 `enabled=true`、上传零报错，但组件列表为空，运行时报 `Unknown skill` | 🟢 |
| Agent 自报成功 | Bot 回复「四个 Skill 均已成功触发」，平台侧同期返回 `Unknown skill` | 🟢 |
| 解析失败与「真的没有」同形 | 文件列表返回结构与预期不符，解析出空结果，差点记成「这个库是空的」 | 🟢 |
| 未知参数被静默吞掉 | 某接口传错参数名返回 200、参数被忽略、退回默认结果；而同一 API 下的兄弟接口会明确拒绝 | 🟢 |
| 「没有可见变更」≠「没有影响」 | 一次超时的写请求占住该资源全部写入路径逾三小时，**详情接口 23 个字段里没有任何字段反映这一状态**；同期前台的「保存」也一起失败 | 🟢 |
| 配错了降级成另一种正常行为 | 工作指引里快捷命令名匹配不上时，静默降级为把命令值当纯文本填进输入框——两种行为界面上都是「点一下、出现内容」 | 🟡 |

**由此立的第一原则，第 01 篇就要交给读者：**

> **任何写操作的成败，一律以「回读目标资源」判定，不采信操作后的成功提示。**

这跟第 14 篇「不要信 agent 的自我报告」是同一条原则的两个面：
**一个说别信 agent 说的，一个说别信平台说的。判据只有一种——自己回去看。**

还有一条元教训，值得放在第 01 篇开头（它就是那个 knodo 摸索项目存在的理由）：

> **错误的平台事实比没有事实更贵**——没有事实时人会去查；有一条错事实时，人会围着它建设施。

## 一、第一步 · 新建工作空间

### 🟢 界面实测（2026-09 站主亲验）——官方文档两个版本都不对

**这一整段原来是三处 ⬜，现已定案。实际界面跟官方文档所载的任何一版都对不上。**

**它不是弹窗，是一整页**，左上角有「← 返回」。页面标题「**创建新工作空间**」，
副标题「从空白工作空间开始，或基于预设模板快速创建」。

**创建方式两个页签**：「**从空白创建**」/「**从模板创建**」。
⚠️ 官方文档所载的「从零开始」「AI 创建」「（推荐）」标记，**界面上一个都没有**。

**表单五个字段**，不是文档说的三个，也不是四个：

| 字段 | 必填 | 说明（原文） | 本篇填什么 |
|---|---|---|---|
| 工作空间名称 | ★ | 占位符「例如: 我的项目」 | `研发流程问答（演示）` |
| **工作空间标识符** | ★ | **（自动生成，可修改）**「只能包含小写字母、数字和连字符」 | 自动生成的即可 |
| 可见性级别 | | 默认 `Private（仅成员可见）` | 保持默认 |
| 分类（可选） | | 「为工作空间设置分类，方便后续筛选和管理」 | 留空 |
| 应用模板（可选） | | 「不选则使用默认『通用』布局」 | 留空 |

提交按钮「**创建工作空间**」，旁边「取消」。

**三条要点：**

🟢 **没有「描述」字段。**官方界面文档写的「名称/描述/可见性」里那个描述**根本不存在**——
这跟 API 侧实测「传 `description` 直接 400」完全吻合。两边终于对上了。

🟢 **「工作空间标识符」就是 API 侧那个必填的 `prefix`**，界面自动生成、但**显式可见且可改**。
本文档原先判断「大概率 UI 自动生成、学员遇不到」——**前半对、后半错**：
学员会看见这个字段，正文得用一句话交代它是什么、不用管。

🟢 **可见性文案是 `Private（仅成员可见）`**，英文单词加中文括注，不是纯中文也不是纯英文。

**应用模板四个，与官方文档所载完全不同。**文档说是「空白/团队协作/项目管理/知识管理」，
界面实际是另外四个（其中「通用（内置）」的说明是「**默认工作空间布局：知识库 + 任务 + 对话**」，
这句话正好解释了空间里为什么是那三块）。

⚠️ **脱敏警告，很重要**：模板卡片里有两个是组织自建的，说明文字带内部业务术语与团队缩写。
**图 1 取景必须把「应用模板」整块切掉**——只框到「分类（可选）」为止。
这也正好符合零之二那条 670px 的取景上限，切掉之后一举两得。

### 模型不在这个表单里

🟡 `:7505-7514`《模型配置》：进工作空间设置 → 点「AI 配置」→ 在「AI 模型」卡片点「修改」
→ 选 AgentOS → 选该 AgentOS 支持的默认模型 → 保存。
🟡 `:7514`：**新建工作空间仍默认使用 Claude Code。**未配时继承组织默认模型（🟡 `:7499-7501`）。
🟢 `errata-vs-handbook.md` B6：空间默认模型是 **AgentOS + model 二元组**，
所以 workspace 的 PATCH DTO 里根本没有 `defaultModelId`。

**第 01 篇不动它。**默认能跑就跑，改模型是后面的事。但有两条坑要在正文里挡一句：

**其一，AgentOS 与模型是联动的。** 🟢 先选 AgentOS 再选模型，选 Codex 只出 OpenAI 系，

**其二，⚠️ 模型清单里看得见不代表有权用。** 🟢 模型接口返回的清单**没有任何套餐字段**，

**这条坑出过一次很贵的事故，值得当反面教材写进文章。** 🟢 2026-08-03 knodo 项目

**没有故障，是模型选错了。**由此立的判据是：

> **排障从「已知 good 基线」起步，不从「最可疑项」起步。**

### 应看到什么

左侧出现 `研发流程问答（演示）`，进去之后有知识、对话等入口。
🟡 `:277-278`、`:19402`：工作空间数量无限制。

## 二、第二步 · 上传知识库文件

### 入口

🟡 `:2949-2958`：左侧空间导航的「**知识**」模块。
🟡 `:4808-4831` 界面构成：左侧**文件树** / 右侧**内容区** / 顶部**工具栏**
（新建文件·目录、上传、刷新、搜索）。

### 操作

🟡 `:4855-4859`《知识库管理》：点工具栏「**上传**」→ 选择本地文件（**支持多选**）→ 等待完成
🟡 `:5051-5056`《文件管理》：点「上传」→ 文件选择器 → 支持多选 → 点「打开」开始上传

**传**：`01-demo-kb/` 里那三份 `.md`，放**根目录**，不建子目录。

🟢 **拖拽上传：两条路都支持**（2026-09 站主亲验）。官方文档只描述了知识库侧的文件选择器，
**漏写了拖拽**——这次是文档少写了一项能力，不是写错。

### ⚠️ 但「拖进去」有两条路，而它们不是一回事——这是第 01 篇的头等常见错误

| | 知识库上传（左侧文件树） | 对话框上传（输入框上方） |
|---|---|---|
| 东西落在哪 | **空间的知识库**，进 Git，有版本历史 | **这次对话的附件** |
| 别的会话看得见吗 | 看得见 | **看不见** |
| Bot 平时能用吗 | 能，自动检索得到 | 只能在本次对话里 `@` 引用 |
| 单文件上限 | ⬜ 未知 | 🟢 **20MB**（界面明写） |
| 支持格式 | `.docx` 只能预览、`.pptx` 不支持预览 | 🟢 图片 JPG/PNG/GIF/WebP、文档 **PDF/Word/Excel/CSV**/Markdown/TXT、代码文件 |

**平台自己在对话上传区的说明文字里划了这条线**，原文：
「如果有其他类型或更大的文件，**请在左侧知识库上传**，这边可直接 @ 引用」。

**为什么这是头等常见错误**：学员把三份制度往对话框一拖，文件出现了、能 `@` 引用、
问一句还真答对了——**他会以为知识库建好了**。实际那是这次对话的附件：
换个会话看不见、Bot 平时用不上、不进 Git、没有版本历史。

**东西在，功能不在，而界面不会告诉你。**跟零之四那张静默失败表是同一个病，
只是这一次的诱因不是平台骗你，是**两个长得几乎一样的入口**。

⬜ **一件待确认**：对话上传区里有个「**指定上传目录**」按钮。如果它能把附件直接送进
知识库的某个目录，那两条路就在这儿接上了，上面这条常见错误的写法要跟着改。点开看看。

需要建目录时（本篇不需要）：工具栏「新建」→「新建目录」→ 输入目录名 → 确认（🟡 `:4849-4853`）；
或右键 →「新建目录」→ 输入 → **回车确认**（🟡 `:5083-5088`）。建议嵌套不超过 3–4 层（🟡 `:5104`）。

### 应看到什么

🟡 `:5059-5065` 上传中：文件名 / 进度条 / 上传速度 / 剩余时间。
🟡 `:5067` 成功：**文件出现在文件树中**。
🟡 `:5067-5079` 失败会显示原因：文件过大 / 类型不支持 / 存储空间不足 / 网络问题。

三份 `.md` 都应出现在文件树，点开能看到渲染后的内容（🟡 `:4878-4907`：`.md` 支持在线编辑
与渲染预览）。

⚠️ 🟢 **根目录实际是四个条目，不是三个**——平台自建了一个 `.gitignore`。截图里会有它，
说明文字必须提一句，否则读者以为自己传错了。

### 索引：有延迟，且 ⬜ 没有界面提示的记载

🟡 `:4964-4968`《知识库管理》「文档索引」全部三句：新建或修改的文档会自动更新索引；
索引更新可能有**几秒延迟**；大文件可能需要更长时间。**没有任何界面标识、徽章或状态列的描述。**

⚠️ **但这条被实测部分推翻了，现在是悬案。**🟢 2026-09 探针：写入一份新文件（内含三份正式
文件里都没有的事实），**上传返回后 3.55 秒**即提问，中间不等待，新事实全部命中。

原因见第四步的检索机制那节：**这个平台在 Bot 一侧没有索引层**，它直接 `find` + `Read`
文件系统。没有索引，自然没有索引延迟。

⬜ **所以「不用等」和「要等十几秒」现在都没有依据。**本次只证明了 API 写入路径没有延迟，
界面上传是否另有异步处理未测。**界面复核之前，这一段先不写死。**

### 另外三条会绊到学员的

🟡 **`.docx` 只能预览，不能在线编辑，且不支持旧版 `.doc`；`.pptx` 完全不支持预览**，只能下载。

🟡 **文件搜索是「文件名搜索」不是全文搜索。**语法是 `filename:` / `ext:` / `path:`，

🟡 **默认跳过 `.gitignore` 忽略的文件。**知识库底层是 Git 仓库，这一条会解释某些

### 一条对第 11 篇有用的：知识库有版本历史，工作指引没有

🟢 知识库是真实的本地 Git 工作树、有完整历史（`storageType: git`、`autoGitCommit: true`），
只是**没有配远程仓库**。所以官方那句「文件误删可通过版本历史恢复」是**成立的**。

⚠️ 注意别被 knodo 项目手册里那句「空间里没有可用的 git 仓库」误导——🔴 判读是那句
把「远程仓库路径为空」说成了「没有 git 仓库」，而同仓库另有两处 🟢 证据与之冲突
（云端 Git 取证做到了逐提交定位、Bot 自述执行过 `git log -S` 全历史搜索）。
**这一条本身就是「错误的平台事实」的又一个实例。**

### ⚠️ 2026-09 新发现两个开关，其中一个动摇了「引用来源」的结论

编辑弹框继续往下滚，「基本信息」页还有三项此前完全不知道的：

| 字段 | 界面说明原文 | 默认 |
|---|---|---|
| **显示知识库** | 允许用户查看助手关联的知识库内容 | **开** |
| **显示引用来源** | **在回复中显示引用的知识库文档** | **开** |
| 可见性 | 仅所在空间的成员可使用此助手 | 「空间成员…」（截断，需展开看全部枚举） |

**「显示引用来源」是一项平台功能，而且有开关。**这跟本文档第四步刚下的结论
「平台渲染的是工具轨迹、不是出处」直接冲突——**那个结论现在悬置，不得引用。**

截图里回答上方那几行（`>_ Bash ✓ List markdown files…`、`📄 Read ✓ 提单与验收流程.md` ……）
到底是什么，有两种读法，目前都说得通：

- **读法 A（我原来的判断）**：那是工具调用轨迹，与「显示引用来源」无关。
  依据：`>_ Bash` 那一行不是知识库文档，工具轨迹才会有它。
- **读法 B**：那就是「显示引用来源」的呈现——平台从工具轨迹里挑出读知识库文件的那几条展示。
  依据：「在回复中显示引用的知识库文档」渲染出来正是这个形状。

🟢 **决定性实验已做（2026-09 站主亲验），读法 B 被证伪。**

做法：把「显示引用来源」**关掉** → 保存 → **新开会话**问同一道题。

**结果：`>_ Bash` 与 `📄 Read` 两行照常出现。**读法 B 预测它们会消失，没消失，
**所以那几行是工具调用轨迹，与这个开关无关。读法 A 成立，原结论保留。**

（这个推断不受实验其余不干净之处影响——两次会话的创建方式与模型行为都有差异，
但读法 B 是一个**会被单次反例杀死**的预测，反例已经拿到了。）

⬜ **换来一个新问题：那「显示引用来源」到底管什么？**关掉之后可观察输出没有任何变化。

🔴 **推测**：这个平台的 Bot 用的是沙箱里的 `Bash`/`Read` 直接扫盘（见第四步检索机制），
**根本没走检索管线**，所以依赖检索结果的「引用来源」功能在这条路径上永远不触发——
**开关是活的，功能是死的。**

如果这条推测成立，它就是零之四那张静默失败表的又一行，而且是最难察觉的一种：
**你打开一个开关，以为出处会显示，实际什么都没变，而界面不会告诉你这个开关在这条路上不生效。**
⬜ 要坐实它，得找到一条真正走检索的路径再试（`@` 手动引用？IM 端？免登链接？），
本篇不做，记给第 11 篇。

**另外别忘了「显示知识库」那个开关**——它管的是「用户能不能查看助手关联的知识库内容」。
这一条第 01 篇不展开，但它是第 08 篇「最小权限」的现成素材：
**同一个 Bot，给不同人看到的东西可以不一样，而这是一个开关的事。**

### 🟢 界面自己写明了零之一那条

「人设/系统提示词」输入框下方有一行灰色说明，原文：

> **人设会作为系统提示词注入每次对话，影响助手的回复风格和行为**

**这句话就是零之一那条分野的正面证据**——助手的人设注入每次对话，
那么空间的工作指引自然就不在这条路上。平台在界面上说了，只是没说另一半。

### ⚠️ 系统提示词是**预填的**，不是空白——这一步的写法要改

### 系统提示词填什么

🟢 **打开弹框时这个框里已经有字了。**平台按空间名自动生成了一段默认模板：

```
你是「<空间名>」，一个基于「<空间名>」工作空间知识构建的 AI 助手。

## 核心职责
- 基于工作空间内的知识库内容，准确回答用户问题
- 如果问题超出知识库范围，诚实告知并建议用户咨询相关负责人

### 回答原则
（下略，需滚动）
```

**所以这一步不是「写」，是「替换」。**正文得交代清楚：先把预填内容删干净，再贴自己的。
不说这一句，学员会直接往下追加，两段规矩叠在一起，改的时候必然漏一处。

⚠️ **还有一处归因要留神。**默认模板第二条「问题超出知识库范围，诚实告知并建议咨询相关负责人」
**跟我们那五条规矩的第 3 条几乎一样**。第 4 题（回滚谁批）它老实承认「流程文件里没写到」，
这个好表现到底是我们那条规矩的功劳，还是平台默认模板的功劳，**目前分不清**——
API 那一遍填的是我们的五条，界面这一遍会带默认模板。
**第 01 篇不能把它当成「你写了规矩所以它听话」的证据**，除非做一次对照。
（这条留给第 16 篇，那里本来就要讲怎么用评测集把归因分开。）

**替换成这五条**（不是工作指引，见零之一）：

```
你是本工作空间的研发流程答疑助手，服务对象是提交变更的业务人员。

回答规则：
1. 只依据知识库里的流程文件回答，不使用常识补充。
2. 每条结论后面注明依据哪一份文件、哪一条。
3. 知识库里没有写到的，直接说「流程文件里没有写到这一条」，
   并建议向研发管理办公室确认。不要推测。
4. 涉及风险等级、变更类型等分档条件时，先确认属于哪一档，再给结论。
5. 不代替审批人做判断，不承诺审批结果与上线时间。
```

🟡 `:7996-8002`：平台会自动生成一份默认系统提示词模板，含核心职责（基于知识库回答问题）、
回答原则（**引用原文**、简洁专业、不编造）、交互风格、安全规范。
🟡 `:8004-8009` 另有一段 HR 助手完整样例。

**注意平台默认模板里就写着「引用原文」**——这条很关键，它暗示「注明来源」这件事
平台是交给提示词去做的，不是平台渲染的组件。见第四步。

### 可见性：建完默认别人看不见

🟡 `:8180`：创建助手时，可见性**默认为 `PRIVATE`（私有）**，此时助手仅创建者可在
「我的助手」列表中看到。可以在私有状态下反复测试、调整系统提示词，
确认满意后再改为 `INTERNAL` 正式发布给组织成员。

**演示空间保持 `PRIVATE` 即可**，本篇不需要发布给别人。但说明里必须写明这一条——
否则读者建完会以为同事也能用了。

🟢 手册 §3.1 补一条易混：`isPublished: false` 时调用报 404「AI 助手不存在或未发布」；
**API 建出的 Bot 默认未发布，界面建的默认已发布**。`isPublished` 与「可见性」是两个东西，
官方文档没讲清二者关系。

### 加入工作空间：本篇多半不需要这一步

🟡 `:8058`：助手有「创建来源空间（homeWorkspace）」概念。🔴 推导：在哪个空间建，
那个空间就是它的 home，不需要再邀请一次。

若需要把它加进别的空间（🟡 `:8036-8044`）：进目标空间设置 → 切到「AI 助手」标签 →

### 应看到什么

空间的 AI 成员列表里出现 `流程助手`，可以对它发起对话。

### 常见错误

- **把规矩写进工作指引。**本步最重要的一条，见零之一。
- **建完不管可见性。**默认 `PRIVATE`，别人看不见；以为建完就发布了。
- **去点「个人技能」Tab。**那是绑 Plugin 的，本篇不碰。🟡 那条路上还埋着本平台最大的
  一个静默失败（零之四第一行）：插件显示「已发布」「已绑定」，Skill 可能根本没注册。
  第 01 篇不碰它，正是因为一碰就要教怎么验。
- **在系统提示词里再抄一遍知识内容。**分工是：**系统提示词说「它是谁、按什么规矩办事」，
  知识库说「事实是什么」。**制度正文抄进提示词，会固定占上下文、丢掉出处、
  改制度还要回来改提示词。
- **以为默认模板里写了「不编造」就不会编造。**🟡 平台自带模板的回答原则确实写着
  「引用原文、简洁专业、不编造」，而 🟢 实测它照样编造（见第四步）。
  **提示词里写了不等于做到了**——这是第 17 篇「提示词管不住『不做什么』」的第一次露面。

### 三条权限相关的，学员会撞到

🟡 **Bot 的编辑权限只给创建人与来源空间的管理员**，其他人连编辑入口都看不到，

这一条对第 21 篇（多 Agent 拆分）是直接的地基——**在这个平台上拆多个 agent，
拆的是提示词与职责，不是知识。**

🟢 解析原始取证 JSON，会话 `messages` 数组元素的完整字段共 **35 个**（2026-09 实操复核，

这不再是「官方文档没写」，是**数据结构里就没有**。

🟢 **另记一个真缺口**：`modelId` 字段存在但**实测全部为 `null`**，平台留了位置没填。
第 10 篇要求可追溯日志记录「模型版本」——**平台目前不满足这一项**，这是那一篇的现成素材。

所以官方那两句「AI 回答会注明信息来源」「回答中标注来源」指的是：
**模型自己在正文里写出来。**平台自带的 Bot 默认系统提示词模板里写着「引用原文」——
平台把这件事交给了 prompt。反证也齐了：AI 回复的操作按钮文档列全了三个，没有出处面板。

**对第 01 篇的含义**：想让答案带出处，唯一办法是**在 Bot 的系统提示词里硬性要求**。
我们那五条规矩的第 2 条就是干这个的。

**对第 02 篇的含义——这条要写进文章，而且它改了论断的口径。**

出处既然是模型行为，它就**会编造**。🟢 实测前科：某次报告写「首轮报告已记录此复制，
本轮对照确认其仍存在」，而首轮的四条发现**无一涉及整段复制**——那句是编的，
是裸断言、没有证据行，**违反了它自己正在执行的规则**。加重情节：工具轨迹显示
**它读过那份原文**，属于「看了却说反」。

所以「结果可自检」不能写成「它会给出处所以可信」，要写成：

> **它给的出处，你能回去对。可自检的主语是你，不是它。**

这个口径差别很大，而且跟全系列的主轴是同一句话——**判据只有一种，自己回去看。**

### 🟢 界面复核结果（2026-09 站主亲验）：平台渲染的是「轨迹」，不是「出处」

**这一条问对了方向但问错了名词。**界面上确实有平台渲染的组件，但它渲染的不是引用来源，
是**工具调用轨迹**——回答正文上方一组带绿点与对勾的行：

```
>_ Bash  ✓  List markdown files in workspa…      >
📄 Read  ✓  提单与验收流程.md                     >
📄 Read  ✓  变更风险分级表.md                     >
📄 Read  ✓  研发变更管理办法.md                   >
```

而正文里那句「依据：《提单与验收流程》第四条『各节点时限』表第一行」是**斜体引用块**，
是模型自己写的 markdown，**不是组件**。两者性质完全不同：

| | 谁产生的 | 可信吗 | 粒度 |
|---|---|---|---|
| **轨迹**（读了哪几个文件） | **平台**，来自工具执行记录 | 🟢 可信，它没法伪造自己调了什么 | 到**文件** |
| **出处**（这句话依据哪一条） | **模型**，写在正文里 | ❌ 会编，有实测前科 | 到**条款**，但可能是编的 |

### ⚠️ 🟢 同一道题跑两次，它读的文件数不一样

这是本轮最该进文章的一条。同一个 Bot、同一道题（「提单之后多久会有人处理」）：

| | 工具轨迹 | 答案形态 |
|---|---|---|
| 第一次 | `Bash` + `Read` × **3**（三份全读） | 分两种理解、带一张时限表、附两点提醒 |
| 第二次 | `Bash` + `Read` × **1**（只读相关那一份） | 一句话给结论，短得多 |

**它会挑，而且两次挑得不一样。**

**这条修正了本文档先前的说法。**原来写「知识库小的时候它会全量读」——不准确，
准确的是：**三份文件它可以全读、也可以只读一份，读几份是它当场决定的，你控制不了。**

**对第 16 篇（评测集）这是靶心**：那一篇的题眼是「几个正向样例不算测试」，
现在它有牙了——**同一道题跑两次，它读的东西都不一样，你凭一次通过就上线？**

**对第 02 篇是个限定**：「结果可自检」里那条「看轨迹知道它读了哪几份」仍然成立，
但要补一句——**轨迹告诉你的是这一次读了什么，不是它下一次会读什么。**

### 🟢 出处的排版两次不同，这是它是模型行为的又一个佐证

第一次是**斜体引用块**（`> 依据：…`），第二次是**加粗**（`**依据：**…`）。
同一个 Bot、同一条规矩、同一道题，排版不一样——**平台渲染的组件不会这样，模型写的才会。**

三条界面细节，全部 🟢 亲验：

1. **展开 `>` 里面只有文件路径，没有文件内容。**所以轨迹告诉你它看了什么范围，
   **不能拿来核对内容**。
2. **轨迹里的文件名可以点，点了直接打开对应文件。**这是这个平台上「可自检」
   唯一一条真实可走的路。
3. **操作按钮在回答块的右上角，不在下方**——先前记「一个都找不到」是因为在下面找。
   🟢 已确认至少有**复制**。⬜ 悬停时那个角落一共出现几个，待补。
   官方文档把它们描述成「回复下方的操作按钮」，位置这一项仍然是错的。

### 这给第 02 篇一条完整的、可执行的「可自检」链

不是抽象原则，是三步操作，而且**三步全都要人做**：

> **看轨迹知道它读了哪几份 → 点文件名打开原文 → 拿模型写的「第四条」回去对。**

所以「结果可自检」的口径最终定为——**平台告诉你它做了什么，模型告诉你它为什么这么说；
前者可信后者会编，而把两者接上的那个动作，只能你自己做。**

### 检索机制：文件级逐份读 + grep 🟢（附边界）

**原本这一条是 ⬜，2026-09 由勘误调研升级为 🟢。**

🟢 实测取证：让 Bot 去找一个不存在的标记串，它的回答自述——
「工作区全部文件（**共 7 份，已逐一确认**）」，检索方式包括大小写不敏感、部分匹配、
正则变体、**`git log -S` 全历史搜索**，并写明「我读的是本工作区，
通过 **Bash / Read / grep 直接扫盘**」。

据此可定三件事：

1. **Bot 在沙箱里持有原生 `Bash` / `Read` / `grep`**，对工作空间的 Git 工作树有文件系统级访问
2. **检索是「逐份读文件 + grep」，不是分块向量召回**——没有召回打分、没有 top-k、
   没有 chunk 概念，它把整个文件读进上下文。七份文件它就逐份确认了七份
3. 同一份证据的另一半：**MCP 层的范围门禁能被原生 `Read`/`Bash` 绕过**——那是第 14 篇
   「门禁必须在 Agent 之外」的实测形态，第 01 篇不讲，记在这里备用

**边界必须说清**：这证明了 Bot 走的是这条路，**不能反过来证明平台没有别的索引通道**。
`@` 引用与「自动检索」背后是否另有实现，未测。

⚠️ **一个极易张冠李戴的陷阱**：官方文档里那句「系统使用**混合搜索**（关键词 + 语义）」
说的是**记忆系统**，不是知识库。记忆系统是另一套东西（Observer Agent 提炼、
每空间上限 1000 条 / 100MB、**仅支持 Claude Code 引擎**、管理页不能新增或编辑记忆内容，
且目前两套实现并存、双开会提示「重复记忆和结果差异」）。**写稿时别混。**

**对第 01 篇的含义**：文件数量与文件名直接决定成本与命中率。七份文件逐份读还行，
七十份呢？这正是第 11 篇「知识库不是文件堆」的由来。

### ⚠️ 2026-09 实操结论：知识库小的时候，它根本不检索

**这一条推翻了本文档原来的一个设计假设，而且它比原假设更有教学价值。**

我们那道「改支付回调谁批」的两跳题，原本预判「大概率答不好」，依据就是上面那条
「只有关键词/文件级检索」。🟢 实测它**答得干净利落**——先判定支付回调命中分级表的
「资金链路」为高风险，再回管理办法取出「架构负责人 + 业务负责人会签 + 回滚方案」，
两跳一次做对，还顺带引用了「命中多条按最高等级」那条说明。

**但工具轨迹说明它根本没做检索：**

```text
[0] Bash   find /workspace -type f \( -name "*.md" -o -name "*.txt" \) | head -50
[1] Read   /workspace/研发变更管理办法.md      ← 整篇
[2] Read   /workspace/变更风险分级表.md        ← 整篇
[3] Read   /workspace/提单与验收流程.md        ← 整篇
```

**它把整个知识库读进了上下文。**三份文件合计 2.6 KB，全量装载比检索便宜得多，
所谓「两跳」在它眼里根本不是两跳——**两条依据都在同一份上下文里。**

所以「检索只有关键词/文件级」那条论断**没有被推翻，只是没被这道题触发**。
检索机制确实弱，只是知识库小到让检索这一环**不必存在**。

**三条直接含义，每一条都要进文章：**

1. **第 01 篇不能拿这道题当「它检索能力强」的证据。**能写的是：知识库小的时候它会全量读，
   所以准——**这个准是规模给的，不是能力给的。**
2. **原设计目标（暴露检索边界）本次没有达成。**要暴露那条边界，得把知识库做到全量装载
   不可行的规模。那是第 11 篇的事，不是第 01 篇的。
3. **计划书给第 01 篇写的那句坑「知识库里放什么决定它答得准不准」，要补一个变量：
   还取决于放了多少。**同样三份文件扩到三百份，这道题的表现可能完全不同，
   **而学员不会预期到这个拐点**——他在十份文件上验收通过，上线时是三百份。

**怎么进一步验**：上传一篇文档，用**与原文完全不同的措辞**问同一件事（语义相同、
无共同关键词）；或者把知识库堆到全量读不动的规模再问同一道两跳题。前者测语义检索有没有，
后者测拐点在哪儿。

### 常见错误

- **在已有会话里换助手。**换不了，助手选择只在新对话开始前生效。
- **没确认输入框工具栏显示的助手名就开始问。**没选中 Bot 时走的是另一条路。
- **只问顺利的那两题就收工。**得到的是一个「看起来能用」的 agent，
  而这个系列全部的价值在知道它哪儿不行。
- **删对话前没把记录抄走。**🟡 删除对话是**硬删除，不可恢复**。
- **以为「更多配置」跟着账号走。**🟡 思考强度、压缩会话这类选项**按工作空间与运行时
  存在浏览器本地**，换台电脑就没了；输入历史（`Ctrl+R`）同样存本地。教学时别让学员依赖它。

## 六之二、只影响写脚本的人（正文不必提，留在这里备查）

第 01 篇全程点击，用不上这三条。但后面几篇一旦教到调接口，它们会立刻变成坑。

🟢 **`GET /files/content` 返回裸文本，不带 `code`/`data` 包封**，与同 API 下其他端点不同构。
按统一包封解析会当场炸。

🟢 **会话消息的数据在 `data.messages`**，不是 `data.list` 或 `data.items`；`limit` 上限 100，
不接受 `page`/`pageSize`/`order`。**解析键写错时接口返回 HTTP 200 加空列表**，
而会话列表同时报 `messageCount=6`——**看起来完完全全像「平台把历史弄丢了」**。
这一遍差点据此往事实层写进一条错误的平台事实，是先看裸响应才拦住的。
**这就是零之四那张表的第三行「解析失败与真的没有长得一模一样」又演了一遍。**

🟢 **同一次回答内 `createdAt` 与 `blockIndex` 的顺序相反**：正文块 `blockIndex=4` 的时间戳
早于 `blockIndex=0` 的工具块。此前只记了「按 `createdAt` 倒序返回，须显式正排」——
**正排也不对**，块内必须按 `blockIndex` 排，否则拼出来的答案顺序是乱的。
