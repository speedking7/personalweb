## 关键设计决定

系列封面**不**写进每篇文章的 frontmatter,而是单独建一个注册表(`series.ts`)。原因:同一系列有多篇文章,如果封面写在每篇的 frontmatter 里,同系列的封面路径要在 N 篇文章里重复,改封面要改 N 处,还容易漏改导致同系列出现两张封面。这和 `blogs.ts` 里"两个数据源必须共用解析器"的思路是一致的——单一数据源。

## 3. `app/src/lib/assets.ts`(新增)

把 `blogs.ts` 里的 `resolveCover` 提取成共享工具,供文章封面和系列封面共用:

```ts
/**
 * 本地相对路径补上部署 base(如 /personalweb/);绝对 URL 和以 / 开头的路径原样返回。
 */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

## 4. `app/src/data/series.ts`(新增)

```ts
/**
 * [INPUT]: 依赖 @/lib/assets 的 resolveAssetPath,@/types/blog 的 BlogPost/SeriesGroup 契约
 * [OUTPUT]: 对外提供 groupPostsBySeries —— 按 frontmatter 的 series 字段分组文章并补上系列封面
 * [POS]: data/ 层的系列聚合器,是 blogs.ts 和列表页之间的桥
 * [PROTOCOL]: 变更时更新此头部,然后检查 CLAUDE.md
 */
import { resolveAssetPath } from '../lib/assets';
import type { BlogPost, SeriesGroup } from '../types/blog';

// 系列封面注册表:key 必须与 frontmatter 里的 series 值完全一致(区分大小写)。
// 新增系列 = 在这里加一行 + 把封面图丢进 src/content/covers/series/。
const seriesCovers: Record<string, string> = {
  'AI 转型指南': 'covers/series/ai-transform.svg',
};

/**
 * 未注册封面的系列,退化用组内第一篇文章的封面兜底,而不是报错或留空。
 */
export function groupPostsBySeries(posts: BlogPost[]): SeriesGroup[] {
  const groups = new Map<string, BlogPost[]>();

  for (const post of posts) {
    if (!post.series) continue;
    const list = groups.get(post.series) ?? [];
    list.push(post);
    groups.set(post.series, list);
  }

  return Array.from(groups.entries()).map(([name, seriesPosts]) => ({
    name,
    cover: resolveAssetPath(seriesCovers[name] ?? '') || seriesPosts[0].coverImage,
    posts: seriesPosts,
  }));
}
```

- 新增 `import { groupPostsBySeries } from './series'` 和 `import type { SeriesGroup } from '@/types/blog'`
- 新增导出函数:

```ts
/**
 * 按系列分组的博客列表(用于列表页系列聚合区块)
 * 复用 getBlogPosts() 的降级逻辑,飞书和本地数据都自动生效
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  return groupPostsBySeries(posts);
}

export type { SeriesGroup };
```

**关于飞书数据源**:`series` 字段是否会出现在飞书文章上,取决于 `feishuBlogClient` 是否内部也调用了 `parseBlogMetadata`(从你贴的头部注释看,架构上应该是共用的)。如果是,飞书文档的 frontmatter 里加 `series:` 字段即可自动生效,`app/src/lib/feishu.ts` 不用改。如果 `feishu.ts` 是手工拼 `BlogPost` 对象、绕开了 `parseBlogMetadata`,需要在那边补一行 `series` 字段透传——我没有那个文件内容,麻烦你确认一下。

## 6. 博客列表页组件

我没有拿到这个文件,下面是接入方式,按你实际的组件结构套用即可:

```tsx
import { useEffect, useState } from 'react';
import { Link } from 'react-router-dom';
import { getSeriesGroups } from '@/data/blogs';
import type { SeriesGroup } from '@/types/blog';

const [seriesGroups, setSeriesGroups] = useState<SeriesGroup[]>([]);

useEffect(() => {
  getSeriesGroups().then(setSeriesGroups);
}, []);

{seriesGroups.length > 0 && (
  <section className="series-section">
    <h2>系列文章</h2>
    <div className="series-grid">
      {seriesGroups.map(group => (
        <div key={group.name} className="series-card">
          <img src={group.cover} alt={group.name} />
          <h3>{group.name}</h3>
          <ul>
            {group.posts.map(post => (
              <li key={post.id}>
                <Link to={`/blog/${post.id}`}>{post.title}</Link>
              </li>
            ))}
          </ul>
        </div>
      ))}
    </div>
  </section>
)}
```

不属于任何系列的文章渲染逻辑不受影响,继续走你现有的普通列表(可用 `posts.filter(p => !p.series)` 拿到剩余部分)。
