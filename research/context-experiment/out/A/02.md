基于给出的三个文件的架构(类型定义 → markdown 解析器 → 数据聚合层),系列功能的落点很清楚。方案如下:

## 1. `app/src/types/blog.ts` — 扩展类型

```typescript
export interface BlogPost {
  id: string;
  title: string;
  excerpt: string;
  content: string;
  coverImage: string;
  category: string;
  tags: string[];
  date: string;
  readTime: number;
  series?: string; // 系列名，可选；不属于任何系列的文章保持 undefined
}

// 系列本身的元数据，与文章解耦——系列封面不该依附在某一篇具体文章上
export interface SeriesMeta {
  name: string;
  cover: string; // 本地相对路径，如 'covers/series/ai-transform.svg'
  description?: string;
}

export interface SeriesGroup extends SeriesMeta {
  posts: BlogPost[];
}
```

## 2. `app/src/lib/markdown.ts` — 解析 `series` 字段

在 `parseBlogMetadata` 的 frontmatter 解析块里，紧挨着 `categoryMatch` 加一行(风格与已有字段完全一致):

```typescript
const seriesMatch = frontmatter.match(/series:\s*["']?([^"'\n]+)["']?/);
if (seriesMatch) metadata.series = seriesMatch[1].trim();
```

不设默认值——没写 `series` 的文章就是独立文章，不应该被兜底成某个假系列。因为飞书和本地 md 共用这个解析器(文件头 POS 注释已经点明),这一行改完两条链路自动都支持 `series` 字段，不用碰 `lib/feishu.ts`。

## 3. 新建 `app/src/content/series.ts` — 系列封面注册表

系列封面不放在某篇文章的 frontmatter 里，而是单独维护一份注册表。原因:一个系列下有多篇文章，如果封面字段散落在每篇文章里，容易出现同一系列里几篇文章填了不同封面的漂移；单独注册表让"系列"成为一等公民，且飞书/本地文章只需在 `series` 字段里写系列名即可对上。

```typescript
import type { SeriesMeta } from '@/types/blog';

// 封面图放在 public/covers/series/ 下，路径写法与文章 cover 字段一致（相对路径，运行时自动补 BASE_URL）
export const seriesRegistry: SeriesMeta[] = [
  {
    name: 'AI 转型指南',
    cover: 'covers/series/ai-transform.svg',
    description: '从零开始梳理企业 AI 转型的关键步骤',
  },
];
```

封面图实体文件放 `app/public/covers/series/ai-transform.svg`（与现有 `content/posts` 里文章 cover 的存放约定保持一致，走 `public/` 而非打包资源，这样 `resolveCover` 的 `BASE_URL` 拼接逻辑可以直接复用）。

## 4. `app/src/data/blogs.ts` — 分组聚合

三处改动:

**a) 导出 `resolveCover`**(目前是文件内私有函数，改成 `export const resolveCover = ...`)，供系列封面复用同一套本地路径解析逻辑。

**b) 引入注册表:**
```typescript
import { seriesRegistry } from '@/content/series';
import type { BlogPost, SeriesGroup } from '@/types/blog';
```

**c) 新增两个导出函数，紧挨着 `getPostsByCategory`/`getPostsByTag`:**

```typescript
/**
 * 按系列分组
 * 只聚合带 series 字段的文章；系列封面来自 series.ts 注册表，找不到注册项时兜底用系列内第一篇文章的封面
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const grouped = new Map<string, BlogPost[]>();

  posts.forEach(post => {
    if (!post.series) return;
    const list = grouped.get(post.series) ?? [];
    list.push(post);
    grouped.set(post.series, list);
  });

  return Array.from(grouped.entries()).map(([name, seriesPosts]) => {
    const meta = seriesRegistry.find(s => s.name === name);
    // 系列内按时间正序排列，方便读者从第一篇开始追更（与全站列表的倒序刻意相反）
    const sorted = [...seriesPosts].sort((a, b) => a.date.localeCompare(b.date));
    return {
      name,
      cover: meta ? resolveCover(meta.cover) : sorted[0].coverImage,
      description: meta?.description,
      posts: sorted,
    };
  });
}

/**
 * 按系列筛选博客
 */
export async function getPostsBySeries(series: string): Promise<BlogPost[]> {
  const posts = await getBlogPosts();
  return posts.filter(post => post.series === series);
}
```

## 5. 博客列表页 — 按系列分组展示

给出的代码里没有列表页组件源码，我按项目现有的 `pages/Blog.tsx` + 文章卡片组件（假设叫 `BlogCard`，请替换为实际组件名）来接入，逻辑本身与具体组件名无关:

**新建 `app/src/components/SeriesSection.tsx`:**
```tsx
import type { SeriesGroup } from '@/types/blog';
import { BlogCard } from './BlogCard';

export function SeriesSection({ series }: { series: SeriesGroup }) {
  return (
    <section className="mb-12">
      <div
        className="relative h-40 rounded-xl bg-cover bg-center flex items-end p-6 mb-4"
        style={{ backgroundImage: `url(${series.cover})` }}
      >
        <div className="absolute inset-0 bg-black/40 rounded-xl" />
        <h2 className="relative text-white text-2xl font-bold">{series.name}</h2>
      </div>
      <div className="grid grid-cols-1 md:grid-cols-3 gap-6">
        {series.posts.map(post => (
          <BlogCard key={post.id} post={post} />
        ))}
      </div>
    </section>
  );
}
```

**`pages/Blog.tsx` 接入点:**
```tsx
const [seriesGroups, setSeriesGroups] = useState<SeriesGroup[]>([]);
const [singlePosts, setSinglePosts] = useState<BlogPost[]>([]);

useEffect(() => {
  (async () => {
    const [groups, all] = await Promise.all([getSeriesGroups(), getBlogPosts()]);
    setSeriesGroups(groups);
    setSinglePosts(all.filter(p => !p.series)); // 无系列的文章保持原有平铺展示
  })();
}, []);

return (
  <>
    {seriesGroups.map(s => (
      <SeriesSection key={s.name} series={s} />
    ))}
    <div className="grid grid-cols-1 md:grid-cols-3 gap-6">
      {singlePosts.map(post => (
        <BlogCard key={post.id} post={post} />
      ))}
    </div>
  </>
);
```

无系列的文章不受影响，继续走原有分类/标签/搜索逻辑；系列区块单独渲染在上方，作为新增而非替换。

## 6. 文章 frontmatter 用法示例

```markdown
---
title: "从数据到决策：AI 转型第一步"
category: AI
tags: [AI, 转型]
series: AI 转型指南
date: 2026-08-01
---
```

只要 `series` 值和 `seriesRegistry` 里的 `name` 一致即可挂上封面，不写就是独立文章，向后兼容现有所有文章。
