基于现有的 `parseBlogMetadata` 共享解析器架构（飞书和本地 md 共用同一入口），系列功能只需在数据层和解析层做三处改动，页面层做一处新增分组渲染。方案如下：

## 1. `app/src/types/blog.ts` — 新增字段和 Series 类型

```typescript
export interface BlogPost {
  id: string;
  title: string;
  excerpt: string;
  content: string;
  coverImage: string;
  category: string;
  tags: string[];
  date: string;
  readTime: number;
  series?: string; // 系列名，如 "AI 转型指南"；不属于任何系列则不写
}

export interface Series {
  name: string;
  cover: string;
  posts: BlogPost[];
}
```

## 2. `app/src/lib/markdown.ts` — 解析 `series` frontmatter 字段

在 `categoryMatch` 后面加一段同构的解析（飞书和本地文章走同一个函数，天然两条链路都支持）：

```typescript
const seriesMatch = frontmatter.match(/series:\s*["']?([^"'\n]+)["']?/);
if (seriesMatch) metadata.series = seriesMatch[1].trim();
```

## 3. 新增 `app/src/lib/assets.ts` — 从 blogs.ts 抽出的路径解析工具

`resolveCover` 目前是 blogs.ts 内部私有函数，只服务文章封面。系列封面要复用同一套"本地相对路径 + BASE_URL 前缀，外链原样返回"的规则，所以把它提成公共工具：

```typescript
/**
 * 本地相对路径补上部署 base；绝对 URL / 以 / 开头的路径原样返回
 */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

## 4. 新增 `app/src/data/series.ts` — 系列封面注册表

系列封面是系列级别的属性，不挂在某一篇文章的 frontmatter 上（否则同系列多篇文章封面互相打架时无法确定真值），单独登记：

```typescript
/**
 * 系列封面注册表：系列名 -> 封面图相对路径（相对 public/，参照文章封面的路径约定）
 * 新增系列：把封面图放到 public/covers/series/ 下，在此登记同名 key
 */
export const seriesCovers: Record<string, string> = {
  'AI 转型指南': 'covers/series/ai-transformation.svg',
};
```

对应放一张图到 `app/public/covers/series/ai-transformation.svg`（图片本身需要你放，我这里只定路径约定）。

## 5. `app/src/data/blogs.ts` — 改动点

- 用新工具替换本地 `resolveCover`：

```typescript
import { resolveAssetPath } from '@/lib/assets';
import { seriesCovers } from './series';
import type { BlogPost, Series } from '@/types/blog';

export type { BlogPost, Series };
```

删除原来私有的 `resolveCover` 定义，`staticBlogPosts` 里的调用改成 `resolveAssetPath(post.coverImage)`。

- 新增按系列分组的聚合函数，放在 `getTags` 之后：

```typescript
/**
 * 按系列分组博客文章
 * 只归并带 series 字段的文章；系列封面优先取注册表，
 * 未登记则退回该系列最新一篇文章自己的封面，避免破图
 */
export async function getSeriesList(): Promise<Series[]> {
  const posts = await getBlogPosts();
  const grouped = new Map<string, BlogPost[]>();

  posts.forEach(post => {
    if (!post.series) return;
    const list = grouped.get(post.series) ?? [];
    list.push(post);
    grouped.set(post.series, list);
  });

  return Array.from(grouped.entries()).map(([name, seriesPosts]) => {
    const sorted = seriesPosts.sort((a, b) => b.date.localeCompare(a.date));
    const cover = seriesCovers[name]
      ? resolveAssetPath(seriesCovers[name])
      : sorted[0].coverImage;
    return { name, cover, posts: sorted };
  });
}
```

飞书数据源无需改动——它和本地文章共用 `parseBlogMetadata`，`series` 字段会自动跟着流过来。

## 6. 列表页分组展示（示例，需按实际 `pages/Blog.tsx` 结构合并）

你没有贴出该文件源码，以下按现有 data 层的调用模式（`getBlogPosts`/`getCategories` 一类的异步 + `useEffect`）给出整合方式：

```tsx
import { useEffect, useState } from 'react';
import { getSeriesList, getBlogPosts } from '@/data/blogs';
import type { Series, BlogPost } from '@/types/blog';

function SeriesSection({ series }: { series: Series }) {
  return (
    <section className="blog-series">
      <div className="blog-series__header">
        <img src={series.cover} alt={series.name} className="blog-series__cover" />
        <h2>{series.name}</h2>
        <span>{series.posts.length} 篇</span>
      </div>
      <div className="blog-series__posts">
        {series.posts.map(post => (
          <BlogCard key={post.id} post={post} />
        ))}
      </div>
    </section>
  );
}

export default function Blog() {
  const [seriesList, setSeriesList] = useState<Series[]>([]);
  const [otherPosts, setOtherPosts] = useState<BlogPost[]>([]);

  useEffect(() => {
    (async () => {
      const [series, posts] = await Promise.all([getSeriesList(), getBlogPosts()]);
      setSeriesList(series);
      setOtherPosts(posts.filter(p => !p.series));
    })();
  }, []);

  return (
    <div>
      {seriesList.map(series => (
        <SeriesSection key={series.name} series={series} />
      ))}
      {otherPosts.length > 0 && (
        <section className="blog-series blog-series--others">
          <h2>其他文章</h2>
          <div className="blog-series__posts">
            {otherPosts.map(post => <BlogCard key={post.id} post={post} />)}
          </div>
        </section>
      )}
    </div>
  );
}
```

`BlogCard` 沿用你现有列表页已有的卡片组件；没有单独抽出的话就换成现有的内联渲染代码。

## 文章示例

同一系列的多篇文章只要 `series` 字段值一致即可自动归组，封面统一走注册表，不受单篇文章 `cover` 字段影响。
