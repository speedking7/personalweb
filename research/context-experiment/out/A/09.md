### 2. `app/src/lib/paths.ts`(新增,从 `blogs.ts` 抽出)

```ts
/**
 * 相对路径转部署路径。飞书文章封面是完整 URL,本地/系列封面是相对路径,
 * 后者需要补 BASE_URL 前缀,否则 dev 环境能看见、GitHub Pages 上 404。
 */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

### 4. `app/src/data/series.ts`(新增)

系列封面独立维护在这里,而不是让同系列的每篇文章各自在 frontmatter 里声明一遍封面——那样容易出现改了一篇忘了另一篇,导致同一系列显示两张不同封面。

```ts
import { resolveAssetPath } from '@/lib/paths';

export interface SeriesInfo {
  name: string;
  cover: string;
  order: number;
}

const SERIES_REGISTRY: Record<string, Omit<SeriesInfo, 'name'>> = {
  'AI 转型指南': {
    cover: 'series-covers/ai-transformation.svg',
    order: 1,
  },
};

/** 未在注册表登记的系列名仍可分组显示,只是没有封面、排在最后 */
export function getSeriesInfo(name: string): SeriesInfo {
  const entry = SERIES_REGISTRY[name];
  return {
    name,
    cover: entry ? resolveAssetPath(entry.cover) : '',
    order: entry?.order ?? Number.MAX_SAFE_INTEGER,
  };
}
```

封面图放 `app/public/series-covers/ai-transformation.svg`(与现有 `covers/` 同级,同样走 public 目录 + `resolveAssetPath` 前缀)。

**新增**分组读取接口(放在 `searchPosts` 之后、`clearCache` 之前):

```ts
export interface SeriesGroup {
  info: SeriesInfo;
  posts: BlogPost[];
}

/**
 * 按 series 分组,系列内部按日期正序(体现阅读顺序,而非发布倒序)。
 * 未标 series 的文章不出现在返回结果里,配合 getUngroupedPosts 使用。
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const grouped = new Map<string, BlogPost[]>();

  for (const post of posts) {
    if (!post.series) continue;
    const list = grouped.get(post.series) ?? [];
    list.push(post);
    grouped.set(post.series, list);
  }

  return Array.from(grouped.entries())
    .map(([series, seriesPosts]) => ({
      info: getSeriesInfo(series),
      posts: seriesPosts.sort((a, b) => a.date.localeCompare(b.date)),
    }))
    .sort((a, b) => a.info.order - b.info.order);
}

/** 不属于任何系列的文章,用于列表页里系列分组之外的常规区块 */
export async function getUngroupedPosts(): Promise<BlogPost[]> {
  const posts = await getBlogPosts();
  return posts.filter(post => !post.series);
}
```

### 6. `app/src/components/blog/SeriesSection.tsx`(新增)

```tsx
import type { SeriesGroup } from '@/data/blogs';
import { Link } from 'react-router-dom';

export function SeriesSection({ group }: { group: SeriesGroup }) {
  const { info, posts } = group;

  return (
    <section className="series-section">
      <div className="series-header">
        {info.cover && <img src={info.cover} alt={info.name} className="series-cover" />}
        <div>
          <h3>{info.name}</h3>
          <span className="series-count">{posts.length} 篇</span>
        </div>
      </div>
      <ol className="series-post-list">
        {posts.map((post, index) => (
          <li key={post.id}>
            <Link to={`/blog/${post.id}`}>
              <span className="series-post-index">{index + 1}</span>
              {post.title}
            </Link>
          </li>
        ))}
      </ol>
    </section>
  );
}
```

### 7. 列表页集成(以假设的 `pages/Blog.tsx` 为例)

把原本对 `getBlogPosts()` 的扁平渲染,拆成"系列分组区块 + 未分组文章"两段:

```tsx
import { getSeriesGroups, getUngroupedPosts } from '@/data/blogs';
import { SeriesSection } from '@/components/blog/SeriesSection';

// 组件内:
const [seriesGroups, setSeriesGroups] = useState<SeriesGroup[]>([]);
const [ungrouped, setUngrouped] = useState<BlogPost[]>([]);

useEffect(() => {
  getSeriesGroups().then(setSeriesGroups);
  getUngroupedPosts().then(setUngrouped);
}, []);

// 渲染:
{seriesGroups.map(group => (
  <SeriesSection key={group.info.name} group={group} />
))}

{ungrouped.map(post => (
  <BlogCard key={post.id} post={post} /> // 复用你现有的单篇卡片组件
))}
```

如果列表页目前是按分类/标签筛选的(`getPostsByCategory` 等),筛选逻辑不受影响 —— 系列分组是叠加在原有扁平列表之上的展示层,不改变已有的筛选/搜索路径。

## 待你确认的点

- 系列封面注册表 `SERIES_REGISTRY` 是手工维护的 —— 新增系列时需要同步在 `series.ts` 里加一条,这是有意的设计(避免封面在多篇文章间漂移),但意味着这一步不能省。
- 列表页文件名/路径按你项目实际的替换,上面第 7 步只是集成模式。
