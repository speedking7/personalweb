## 方案概述

新增「系列」作为文章的正交分类维度（不替代 `category`/`tags`），走三层改造：`markdown.ts` 解析 `series` 字段 → 新增 `data/series.ts` 做分组聚合（系列封面走独立配置，不依赖单篇 frontmatter）→ 列表页按系列渲染分组区块。系列封面路径解析逻辑与文章封面共用，抽成 `lib/assets.ts`。

### 2. `app/src/lib/markdown.ts` — 解析 `series` frontmatter

在其他 `xxxMatch` 旁边加一行即可，不需要默认值（未命中就是 `undefined`，代表不属于任何系列）：

```ts
const seriesMatch = frontmatter.match(/series:\s*["']?([^"'\n]+)["']?/);
if (seriesMatch) metadata.series = seriesMatch[1].trim();
```

插入位置在 `tagsMatch` 处理之后即可。文件头 `[OUTPUT]` 行需补一句「新增支持 series 字段解析」。

### 3. `app/src/lib/assets.ts`（新建）— 抽出封面路径解析

`blogs.ts` 里原有的 `resolveCover` 逻辑要给系列封面复用，提出来做成公共工具：

```ts
/**
 * [INPUT]: 无外部依赖，仅读取 import.meta.env.BASE_URL
 * [OUTPUT]: 对外提供 resolveLocalAsset —— 给本地相对路径的静态资源补上部署 base 前缀
 * [POS]: lib/ 层的路径解析工具，被 data/blogs.ts（文章封面）与 data/series.ts（系列封面）共用
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
export const resolveLocalAsset = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

### 5. `app/src/data/series.ts`（新建）— 分组聚合 + 系列封面

系列封面不放在每篇文章的 frontmatter 里重复写，而是用一张静态映射表统一维护，新增系列只改这一处：

```ts
/**
 * [INPUT]: 依赖 @/data/blogs 的 getBlogPosts，@/lib/assets 的 resolveLocalAsset，@/types/blog 的 BlogSeries
 * [OUTPUT]: 对外提供 getSeriesList（按 series 分组+附封面）、getUnseriesedPosts（无系列文章）
 * [POS]: data/ 层的系列聚合器，供 Blog 列表页分组渲染；与 blogs.ts 共享同一份文章数据，不重复取数逻辑
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { getBlogPosts } from './blogs';
import { resolveLocalAsset } from '@/lib/assets';
import type { BlogPost, BlogSeries } from '@/types/blog';

// 系列名 -> 封面图相对路径。新增系列 = 加一条记录 + 把图放进 public/series-covers/
const seriesCovers: Record<string, string> = {
  'AI 转型指南': 'series-covers/ai-transform.svg',
};

const FALLBACK_COVER = 'series-covers/default.svg';

export async function getSeriesList(): Promise<BlogSeries[]> {
  const posts = await getBlogPosts();
  const grouped = new Map<string, BlogPost[]>();

  posts.forEach(post => {
    if (!post.series) return;
    const list = grouped.get(post.series) ?? [];
    list.push(post);
    grouped.set(post.series, list);
  });

  return Array.from(grouped.entries())
    .map(([name, seriesPosts]) => ({
      name,
      cover: resolveLocalAsset(seriesCovers[name] ?? FALLBACK_COVER),
      posts: seriesPosts.sort((a, b) => a.date.localeCompare(b.date)), // 系列内按时间正序，还原阅读顺序
    }))
    .sort((a, b) => {
      const aLatest = a.posts[a.posts.length - 1].date;
      const bLatest = b.posts[b.posts.length - 1].date;
      return bLatest.localeCompare(aLatest); // 系列之间按最新一篇倒序，最近更新的系列排前面
    });
}

export async function getUnseriesedPosts(): Promise<BlogPost[]> {
  const posts = await getBlogPosts();
  return posts.filter(post => !post.series);
}
```

### 6. 文章 frontmatter 示例（`app/src/content/posts/*.md`）


同一系列的多篇文章只需重复同一个 `series` 值，封面不用每篇都写。

### 7. 封面图片存放位置

放 `app/public/series-covers/ai-transform.svg`（与现有文章封面同级目录约定一致，`resolveLocalAsset` 会在其前缀补上部署 base）。这里假设项目文章封面物理文件已放在 `app/public/covers/` 下（`resolveCover` 注释里 `covers/x.svg` 相对路径能在 dev/生产都生效，只能来自 `public/`），如果实际目录不同，把 `seriesCovers` 里的路径改成对应目录即可。
