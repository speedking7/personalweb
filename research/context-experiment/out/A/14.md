## 设计思路

系列封面图和文章 frontmatter 解耦：文章只声明属于哪个系列（`series: 系列名`），封面统一在一个新的「系列清单」文件里维护，避免同系列每篇文章都重复填一遍封面路径。清单里的相对路径复用现有 `resolveCover` 逻辑（处理 GitHub Pages 的 `BASE_URL` 前缀问题），这样系列封面也能正确应对线上多出的 `/personalweb/` 前缀。

## 2. `app/src/lib/markdown.ts` — 解析 `series` 字段

在 `tagsMatch` 之后加一段（复用同样的 frontmatter 正则风格，飞书和本地 md 共用这一个解析器，所以两条数据源自动都支持）：

```ts
    const seriesMatch = frontmatter.match(/series:\s*["']?([^"'\n]+)["']?/);
    if (seriesMatch) metadata.series = seriesMatch[1].trim();
```

不需要设默认值——没有 `series` 就是独立文章，这是合法状态，不应该伪造一个。

## 3. 新建 `app/src/content/series.ts` — 系列清单（封面来源）

```ts
/**
 * [INPUT]: 无（静态清单）
 * [OUTPUT]: 对外提供 seriesManifest —— 系列名称到封面图/简介的映射
 * [POS]: 系列封面与文章 frontmatter 里的 series 字段解耦：
 *        文章只声明"属于哪个系列"，封面统一在这里维护一次，
 *        避免同系列每篇文章重复配置封面路径
 * [PROTOCOL]: 新增系列时在此追加一项，封面图放到 public/covers/series/ 下，
 *             用相对路径引用（与文章封面同一套解析规则）
 */
export interface SeriesManifestEntry {
  name: string;
  cover: string;
  description?: string;
}

export const seriesManifest: SeriesManifestEntry[] = [
  {
    name: 'AI 转型指南',
    cover: 'covers/series/ai-transformation.svg',
    description: '从工具使用到组织变革的 AI 转型实践路径',
  },

```

## 4. `app/src/data/blogs.ts` — 新增系列聚合函数

顶部新增 import：

```ts
import { seriesManifest } from '@/content/series';
import type { BlogPost, SeriesGroup } from '@/types/blog';
```

在 `getPostsByTag` 附近新增两个函数（沿用它们的写法：都基于已经过飞书/静态降级处理的 `getBlogPosts()`，不直接碰 `feishuBlogClient`，所以系列功能对两个数据源天然生效）：

```ts
/**
 * 按系列分组博客
 * 封面优先取系列清单里配置的图；清单里没有登记的系列，
 * 用该系列第一篇文章自己的封面兜底，避免系列被静默隐藏
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const grouped = new Map<string, BlogPost[]>();

  posts.forEach(post => {
    if (!post.series) return;
    const list = grouped.get(post.series) ?? [];
    list.push(post);
    grouped.set(post.series, list);
  });

  return Array.from(grouped.entries())
    .map(([name, seriesPosts]) => {
      const sorted = seriesPosts.sort((a, b) => b.date.localeCompare(a.date));
      const manifestEntry = seriesManifest.find(s => s.name === name);
      return {
        name,
        cover: manifestEntry ? resolveCover(manifestEntry.cover) : sorted[0].coverImage,
        description: manifestEntry?.description,
        posts: sorted,
      };
    })
    .sort((a, b) => b.posts[0].date.localeCompare(a.posts[0].date));
}

/**
 * 按系列筛选博客
 */
export async function getPostsBySeries(seriesName: string): Promise<BlogPost[]> {
  const posts = await getBlogPosts();
  return posts
    .filter(post => post.series === seriesName)
    .sort((a, b) => b.date.localeCompare(a.date));
}
```

`resolveCover` 已经在文件里定义，直接复用即可，不需要额外导出——它的绝对 URL / `/` 开头路径直通逻辑对系列封面同样适用（万一以后系列封面想直接引用飞书图床 URL 也不会被前缀污染）。

顺带把文件头的 `[OUTPUT]` 行更新一下，加上 `getSeriesGroups/getPostsBySeries`，`[POS]` 补一句"系列封面来自 content/series.ts 清单，与文章数据解耦"，符合这个项目自己定的 PROTOCOL 要求。

## 5. 列表页分组展示（路径按你项目实际结构调整）

新建一个展示组件，比如 `app/src/components/blog/SeriesSection.tsx`：

```tsx
import { Link } from 'react-router-dom';
import type { SeriesGroup } from '@/types/blog';

export function SeriesSection({ groups }: { groups: SeriesGroup[] }) {
  if (groups.length === 0) return null;

  return (
    <section className="space-y-8">
      {groups.map(group => (
        <div key={group.name} className="rounded-lg border overflow-hidden">
          <div
            className="relative h-40 bg-cover bg-center flex items-end p-4"
            style={{ backgroundImage: `url(${group.cover})` }}
          >
            <div className="absolute inset-0 bg-black/40" />
            <h2 className="relative text-white text-xl font-bold">{group.name}</h2>
          </div>
          <ul className="divide-y">
            {group.posts.map(post => (
              <li key={post.id} className="p-4">
                <Link to={`/blog/${post.id}`} className="hover:underline">
                  {post.title}
                </Link>
                <span className="text-sm text-gray-500 ml-2">{post.date}</span>
              </li>
            ))}
          </ul>
        </div>
      ))}
    </section>
  );
}
```

（路由用的是 `react-router-dom` 的 `Link`，这是按常见 React 博客脚手架猜的，你项目里实际用什么路由方案请替换。）

在博客列表页组件里接入（把系列文章从扁平列表里摘出去，避免同一篇文章在系列区块和普通列表里重复出现）：

```tsx
const [seriesGroups, setSeriesGroups] = useState<SeriesGroup[]>([]);
const [posts, setPosts] = useState<BlogPost[]>([]);

useEffect(() => {
  getSeriesGroups().then(setSeriesGroups);
  getBlogPosts().then(all => setPosts(all.filter(p => !p.series)));
}, []);

return (
  <>
    <SeriesSection groups={seriesGroups} />
    {/* 原有的扁平列表渲染逻辑，posts 已过滤掉带 series 的文章 */}
  </>
);
```

## 小结

- 写文章时加 `series: AI 转型指南` 即生效，飞书和本地 md 共用同一个解析器，两条链路自动同步支持。
- 系列封面统一在 `content/series.ts` 登记一次，图片放 `public/covers/series/`，用相对路径，走既有的 `resolveCover` 防止线上 base path 404。
- 没在清单里登记的系列不会被吞掉，会用该系列第一篇文章的封面兜底，保持"降级但不撒谎"的既有设计原则。
