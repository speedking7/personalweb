## 设计要点

系列封面不应该塞进每篇文章的 frontmatter 里重复填——那样同一系列的封面在文章之间容易漂移，新增系列还得记得同步所有文章。所以拆成两部分：

- 文章 frontmatter 只需要 `series: 系列名`（字符串，作为关联 key）
- 系列本身的元数据（封面、排序）单独维护在一个 manifest 文件里，按系列名关联

封面路径复用 `blogs.ts` 里已有的 base-path 拼接逻辑（GitHub Pages 部署有 `/personalweb/` 前缀这个坑），把它提成共享工具，博客封面和系列封面共用一份，不重复写。

## 1. `app/src/lib/assets.ts`（新增）

从 `blogs.ts` 里抽出通用的路径解析逻辑，博客封面和系列封面共用：

```ts
/**
 * [OUTPUT]: 对外提供 resolveAssetPath —— 把本地相对路径（如 covers/x.svg）
 *           补上部署 base(import.meta.env.BASE_URL)；绝对 URL 与 / 开头路径原样返回
 * [POS]: lib/ 层的资源路径解析器，博客封面与系列封面共用同一条 base-path 拼接逻辑，
 *        避免两处各写一份、以后改一处漏一处
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

## 5. `app/src/data/series.ts`（新增）

```ts
/**
 * [INPUT]: 依赖 @/types/blog 的 BlogPost/Series 契约, lib/assets 的 resolveAssetPath
 * [OUTPUT]: 对外提供 seriesManifest（系列名 -> 封面等元数据）、getSeriesMeta、
 *           groupPostsBySeries、getUngroupedPosts
 * [POS]: data/ 层的系列元数据与分组逻辑，与文章的 series frontmatter 字段
 *        通过系列名字符串关联；分组函数是纯函数，接收已经过分类/搜索筛选的
 *        文章数组，不重复发起数据请求，直接和 pages/Blog.tsx 里现有的筛选状态组合
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { resolveAssetPath } from '@/lib/assets';
import type { BlogPost, Series } from '@/types/blog';

// 新增系列：加一条即可，key 必须与文章 frontmatter 的 series 字段完全一致
const rawSeriesManifest: Record<string, { cover: string; order?: number }> = {
  'AI 转型指南': {
    cover: 'covers/series/ai-transform.svg',
    order: 1,
  },
};

export const seriesManifest: Record<string, Series> = Object.fromEntries(
  Object.entries(rawSeriesManifest).map(([name, meta]) => [
    name,
    { name, cover: resolveAssetPath(meta.cover), order: meta.order },
  ])
);

export function getSeriesMeta(name: string): Series {
  const meta = seriesManifest[name];
  if (!meta) {
    console.warn(`[series] 文章使用了未登记的系列名 "${name}"，请在 data/series.ts 补充封面`);
    return { name, cover: resolveAssetPath('covers/series/default.svg'), order: Number.MAX_SAFE_INTEGER };
  }
  return meta;
}

export interface SeriesGroup {
  series: Series;
  posts: BlogPost[];
}

export function groupPostsBySeries(posts: BlogPost[]): SeriesGroup[] {
  const groups = new Map<string, BlogPost[]>();
  posts.forEach(post => {
    if (!post.series) return;
    const list = groups.get(post.series) ?? [];
    list.push(post);
    groups.set(post.series, list);
  });

  return Array.from(groups.entries())
    .map(([name, seriesPosts]) => ({
      series: getSeriesMeta(name),
      posts: seriesPosts.sort((a, b) => b.date.localeCompare(a.date)),
    }))
    .sort((a, b) => (a.series.order ?? Infinity) - (b.series.order ?? Infinity));
}

export function getUngroupedPosts(posts: BlogPost[]): BlogPost[] {
  return posts.filter(post => !post.series);
}
```

设计成纯函数而不是像 `getBlogPosts` 那样自己异步取数据，是为了能直接套在 `pages/Blog.tsx` 里已有的分类/标签/搜索筛选结果上，不用再多打一次飞书请求，也不用关心 `dataSourceMode`。

```tsx
import { groupPostsBySeries, getUngroupedPosts } from '@/data/series';

// posts 是页面现有的筛选结果 state，不需要新的 fetch
const seriesGroups = groupPostsBySeries(posts);
const ungroupedPosts = getUngroupedPosts(posts);

return (
  <div className="blog-list">
    {seriesGroups.map(group => (
      <section key={group.series.name} className="series-section">
        <div className="series-header">
          <img src={group.series.cover} alt={group.series.name} className="series-cover" />
          <h2>{group.series.name}</h2>
          <span className="series-count">{group.posts.length} 篇</span>
        </div>
        <div className="post-grid">
          {group.posts.map(post => <BlogCard key={post.id} post={post} />)}
        </div>
      </section>
    ))}

    {ungroupedPosts.length > 0 && (
      <section className="post-grid">
        {ungroupedPosts.map(post => <BlogCard key={post.id} post={post} />)}
      </section>
    )}
  </div>
);
```

分组基于已筛选的 `posts`，所以分类/标签筛选和系列分组是叠加的：筛选后某个系列如果一篇都不剩，这个分组自然不出现，不需要额外处理。这块只给出了接入方式，具体要套进 `Blog.tsx` 现有的组件结构（`BlogCard` 组件名等）需要按实际文件调整。
