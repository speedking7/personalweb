## 设计要点

系列封面不挂在单篇文章的 frontmatter 里——同一系列多篇文章会被迫重复贴同一张图，一改封面就要改所有文章。改用一个独立的 **系列注册表**（`data/series.ts`），系列名 → 封面/简介，文章只需在 frontmatter 写 `series: 名称` 做关联。这样飞书文档和本地 md 共用同一套分组逻辑，封面始终只有一处真源。

同时把 `blogs.ts` 里原本内联的 `resolveCover`（本地相对路径补 `BASE_URL` 前缀）提出成公共工具，系列封面和文章封面共用，避免同一个 GitHub Pages 前缀坑写两遍。

### 2. `app/src/lib/markdown.ts` — 解析 frontmatter 里的 `series:`

在 `categoryMatch` 附近加一行（不设默认值，未命中就是 `undefined`，语义上等于「不属于系列」）：

```ts
const seriesMatch = frontmatter.match(/series:\s*["']?([^"'\n]+)["']?/);
if (seriesMatch) metadata.series = seriesMatch[1].trim();
```

因为飞书文档和本地 md 共用这个解析器（见文件头 `[POS]` 说明），飞书来源的文章写 `series` 字段同样会被识别。

### 3. 新建 `app/src/lib/paths.ts` — 抽出路径解析公共工具

```ts
/**
 * [INPUT]: import.meta.env.BASE_URL
 * [OUTPUT]: 对外提供 resolveAssetPath —— 把相对路径补上部署 base
 * [POS]: 供 data/blogs.ts（文章封面）与 data/series.ts（系列封面）共用，
 *        避免 GitHub Pages 的 /personalweb/ 前缀问题在两处各修一份
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

### 4. 新建 `app/src/data/series.ts` — 系列注册表

封面图放 `app/public/series-covers/`（沿用文章封面同款「相对路径 + BASE_URL 前缀」的静态资源约定，不是 import，所以必须在 `public/` 下才能被运行时按路径访问到）。

```ts
/**
 * [INPUT]: 依赖 @/lib/paths 的 resolveAssetPath 补全封面部署前缀
 * [OUTPUT]: 对外提供 getSeriesMeta / resolveSeriesCover
 * [POS]: 系列的封面与简介跟具体文章解耦——同系列多篇文章不重复贴同一张封面，
 *        系列只有一篇文章时也照样有封面。新增系列 = 在这里加一条 +
 *        把封面图丢进 public/series-covers/
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { resolveAssetPath } from '../lib/paths';

export interface SeriesMeta {
  name: string;
  cover: string;
  description?: string;
}

const seriesRegistry: SeriesMeta[] = [
  {
    name: 'AI 转型指南',
    cover: 'series-covers/ai-transformation.svg',
    description: '从工具使用到组织流程重塑的系列思考',
  },
];

const registryByName = new Map(seriesRegistry.map(s => [s.name, s]));

export function getSeriesMeta(name: string): SeriesMeta {
  return registryByName.get(name) ?? { name, cover: '' };
}

export function resolveSeriesCover(name: string): string {
  return resolveAssetPath(getSeriesMeta(name).cover);
}
```

### 5. `app/src/data/blogs.ts` — 复用公共工具 + 加分组函数

把内联的 `resolveCover` 换成 `resolveAssetPath`：

```ts
import { resolveAssetPath } from '@/lib/paths';

const staticBlogPosts: BlogPost[] = Object.entries(localPostModules)
  .map(([path, raw]) => {

```

新增分组导出（供列表页用）：

```ts
export interface SeriesGroup {
  name: string;
  cover: string;
  description?: string;
  posts: BlogPost[];
}

/**
 * 按系列分组博客文章
 * 只返回带 series 字段的文章；同系列按日期正序（先发的先读）
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const grouped = new Map<string, BlogPost[]>();

  posts.forEach(post => {
    if (!post.series) return;
    const list = grouped.get(post.series) ?? [];
    list.push(post);
    grouped.set(post.series, list);
  });

  return Array.from(grouped.entries()).map(([name, seriesPosts]) => ({
    name,
    cover: resolveSeriesCover(name),
    description: getSeriesMeta(name).description,
    posts: [...seriesPosts].sort((a, b) => a.date.localeCompare(b.date)),
  }));
}
```

## 需要你确认/补充的动作
- 把系列封面图放到 `app/public/series-covers/`，文件名对应 `series.ts` 里的 `cover` 路径。
- 每新增一个系列，在 `series.ts` 的 `seriesRegistry` 里加一条；文章 frontmatter 加 `series: 系列名`（名称要跟注册表里完全一致，否则封面拿不到，会退到空字符串）。
- 项目自己的 `CLAUDE.md`/文件头协议要求「变更时更新头部注释」，上面新建文件已按现有风格写了头部，`blogs.ts` 头部的 `[INPUT]` 也要补一句新增依赖 `@/lib/paths`、`./series`。
