## 3. `app/src/lib/series.ts`（新增）

系列封面用独立的配置文件而不是塞进代码常量，是为了跟 `markdown.ts`/`content/posts` 的既有模式保持一致：新增系列只丢文件，不用改代码。

```ts
/**
 * [INPUT]: 无外部契约依赖，仅解析 frontmatter 文本
 * [OUTPUT]: 对外提供 parseSeriesMetadata —— 解析系列封面配置文件（content/series/*.md）的 frontmatter
 * [POS]: lib/ 层的格式解析器，与 parseBlogMetadata 同级，供 data/blogs.ts 消费，
 *        服务的是 SeriesMeta 契约而非 BlogPost
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */

export interface SeriesMeta {
  name: string;
  cover: string;
}

export function parseSeriesMetadata(content: string): SeriesMeta | null {
  const frontmatterMatch = content.match(/^---\n([\s\S]*?)\n---/);
  if (!frontmatterMatch) return null;

  const frontmatter = frontmatterMatch[1];
  const nameMatch = frontmatter.match(/name:\s*["']?([^"'\n]+)["']?/);
  if (!nameMatch) return null;

  const coverMatch = frontmatter.match(/cover:\s*["']?([^"'\n]+)["']?/);
  return {
    name: nameMatch[1].trim(),
    cover: coverMatch ? coverMatch[1].trim() : '',
  };
}
```

## 4. `app/src/content/series/ai-zhuanxing.md`（新增，示例）

```md
---
name: AI 转型指南
cover: covers/series/ai-zhuanxing.svg
---
```

对应图片放在 **`app/public/covers/series/ai-zhuanxing.svg`**（不是 `src/assets`）。原因：`resolveCover` 是运行时拼接 `BASE_URL + 相对路径`，不经过 Vite 的 import 打包管线，所以图片必须是 `public/` 下能被直接按路径请求到的静态资源，跟现有文章封面（`covers/x.svg`）的存放约定完全一致。

每加一个系列，就加一个 `content/series/*.md` + 一张 `public/covers/series/*` 图片，不用改 `blogs.ts`。

## 5. `app/src/data/blogs.ts`

三处改动：

**a) 导出 `resolveCover`**（原来是 `const resolveCover`），系列封面要复用同一套本地资源路径解析逻辑：

```ts
export const resolveCover = (cover: string): string =>
  !cover || /^(https?:)?\/\//.test(cover) || cover.startsWith('/')
    ? cover
    : `${import.meta.env.BASE_URL}${cover}`;
```

**b) import 新依赖 + glob 读取系列配置**，放在 `staticBlogPosts` 定义附近：

```ts
import { parseSeriesMetadata } from '@/lib/series';
import type { BlogPost, SeriesGroup } from '@/types/blog';

// 系列封面配置：src/content/series/*.md，走跟文章封面一样的 resolveCover
const seriesConfigModules = import.meta.glob('../content/series/*.md', {
  query: '?raw',
  import: 'default',
  eager: true,
}) as Record<string, string>;

const seriesCoverMap: Record<string, string> = Object.values(seriesConfigModules).reduce(
  (map, raw) => {
    const meta = parseSeriesMetadata(raw);
    if (meta) map[meta.name] = resolveCover(meta.cover);
    return map;
  },
  {} as Record<string, string>
);
```

**c) 新增分组函数**，放在 `searchPosts` 之后：

```ts
/**
 * 按系列分组文章。只有 series 命中的才会出现在结果里，
 * 没有系列的文章不受影响，仍走 getBlogPosts() 原有的扁平列表。
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const groups = new Map<string, BlogPost[]>();

  for (const post of posts) {
    if (!post.series) continue;
    const list = groups.get(post.series) ?? [];
    list.push(post);
    groups.set(post.series, list);
  }

  return Array.from(groups.entries()).map(([name, seriesPosts]) => ({
    name,
    cover: seriesCoverMap[name] ?? '',
    posts: seriesPosts,
  }));
}
```

按文件头协议：改完这个文件，把顶部 `[OUTPUT]` 那行加上 `getSeriesGroups/resolveCover`，然后检查项目根目录 `CLAUDE.md` 有没有对应的架构约束要同步更新。

**需要你确认一件事（不是反问，是必须核实的依赖点）**：`getBlogPosts()` 在飞书模式下走的是 `feishuBlogClient.fetchBlogPosts()`，我没有 `lib/feishu.ts` 源码。如果它对飞书文档字段做了白名单转换，需要在那边同步透传 `series` 字段，否则飞书来源的文章分组会全部落空，只有 `static` 兜底数据能分组。

## 6. 列表页接入

不知道你实际列表页组件长什么样，给一个独立组件，插到现有文章列表上方即可：

```tsx
import { useEffect, useState } from 'react';
import { getSeriesGroups } from '@/data/blogs';
import type { SeriesGroup } from '@/types/blog';

function SeriesSection({ groups }: { groups: SeriesGroup[] }) {
  if (groups.length === 0) return null;
  return (
    <section className="series-section">
      <h2>系列文章</h2>
      <div className="series-grid">
        {groups.map(group => (
          <div key={group.name} className="series-card">
            {group.cover && (
              <img src={group.cover} alt={group.name} className="series-cover" />
            )}
            <h3>{group.name}</h3>
            <p>{group.posts.length} 篇</p>
            <ul>
              {group.posts.map(post => (
                <li key={post.id}>
                  <a href={`/blog/${post.id}`}>{post.title}</a>
                </li>
              ))}
            </ul>
          </div>
        ))}
      </div>
    </section>
  );
}

// 页面组件内：
const [seriesGroups, setSeriesGroups] = useState<SeriesGroup[]>([]);
useEffect(() => {
  getSeriesGroups().then(setSeriesGroups);
}, []);

// JSX：<SeriesSection groups={seriesGroups} /> 放在原有文章列表渲染之前
```

`group.cover` 为空字符串时 `img` 不渲染，不会出现裂图；没有对应 `content/series/*.md` 的系列名会走这个兜底。原有的扁平列表、分类筛选、搜索都不受影响，`series` 字段只是叠加维度。
