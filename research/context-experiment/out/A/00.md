**关键设计决定**：系列封面不放在文章 frontmatter 里，而是单独建一张"系列名 → 封面图"的映射表。原因：一个系列下每篇文章都要重复写同一个 `seriesCover` 路径既冗余又容易写岔（不同文章填了不同封面时该信任谁？），而且飞书文档不适合用来管理"项目本地相对路径"这种构建期资源。系列本身是比文章更高一级的实体，配置应该独立存在。`series` 字段（仅用于分组归属）仍然按你的要求放在文章 frontmatter 里，两条数据源（本地 md + 飞书）通过共用的 `parseBlogMetadata` 自动拿到，无需改 `lib/feishu.ts`。

## 3. `app/src/lib/assetPath.ts`（新建）

把 `blogs.ts` 里的 `resolveCover` 提出来做成通用工具，因为系列封面同样需要"相对路径补 `BASE_URL`"的逻辑，两处不能各写一份，否则以后改部署路径规则时会漏改：

```ts
/**
 * 把项目内本地相对路径资源（图片等）补上部署 base（如 GitHub Pages 的 /personalweb/）。
 * 绝对 URL 与以 / 开头的路径原样返回，避免把已经是完整地址的资源（如飞书返回的封面）污染成错误路径。
 */
export function resolveAssetPath(path: string): string {
  return !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
}
```

## 4. `app/src/data/blogs.ts` 改动

用 `resolveAssetPath` 替换原来内联的 `resolveCover`：

```ts
import { resolveAssetPath } from '@/lib/assetPath';
import { getSeriesCover } from '@/data/seriesCovers';
import type { BlogPost, BlogSeries } from '@/types/blog';

// 删除原来的 resolveCover 定义，改用 resolveAssetPath
const staticBlogPosts: BlogPost[] = Object.entries(localPostModules)
  .map(([path, raw]) => {
    const slug = path.split('/').pop()!.replace(/\.md$/, '');
    const post = { title: slug, excerpt: '', coverImage: '', ...parseBlogMetadata(raw, slug) } as BlogPost;
    return { ...post, coverImage: resolveAssetPath(post.coverImage) };
  })
  .sort((a, b) => b.date.localeCompare(a.date));
```

在文件末尾（`clearCache` 之后）新增两个聚合函数：

```ts
/**
 * 按系列分组博客文章。
 * 系列内文章按日期倒序；系列本身按其最新一篇文章的日期倒序排列。
 * 封面优先取 seriesCovers.ts 里的配置，未配置则回退到该系列最新文章的 coverImage，
 * 保证漏配置封面时页面上不会出现空图。
 */
export async function getSeriesGroups(): Promise<BlogSeries[]> {
  const posts = await getBlogPosts();
  const groups = new Map<string, BlogPost[]>();

  posts.forEach(post => {
    if (!post.series) return;
    const list = groups.get(post.series) ?? [];
    list.push(post);
    groups.set(post.series, list);
  });

  return Array.from(groups.entries())
    .map(([name, seriesPosts]) => {
      const sorted = [...seriesPosts].sort((a, b) => b.date.localeCompare(a.date));
      return { name, cover: getSeriesCover(name) || sorted[0].coverImage, posts: sorted };
    })
    .sort((a, b) => b.posts[0].date.localeCompare(a.posts[0].date));
}

/**
 * 不属于任何系列的文章，用于列表页"其他文章"分区
 */
export async function getStandalonePosts(): Promise<BlogPost[]> {
  const posts = await getBlogPosts();
  return posts.filter(post => !post.series);
}
```

## 5. `app/src/data/seriesCovers.ts`（新建）

```ts
import { resolveAssetPath } from '@/lib/assetPath';

/**
 * 系列封面配置：系列名 -> 图片相对路径（相对 public/ 根目录）。
 * 新增系列 = 加一行映射 + 把图片丢进 public/series-covers/。
 * 与文章封面同规则：本地相对路径会自动补部署 base。
 */
const seriesCoverPaths: Record<string, string> = {
  'AI 转型指南': 'series-covers/ai-transformation.png',
};

export function getSeriesCover(seriesName: string): string {
  return resolveAssetPath(seriesCoverPaths[seriesName] ?? '');
}
```

对应地，图片放在 `app/public/series-covers/ai-transformation.png`（沿用现有文章封面 `public/covers/` 的存放约定，走 Vite 静态资源直出，不经 glob 内联）。

## 7. 列表页接入（未提供源码，按数据层接口给出可直接嵌入的模式）

假设列表页现有逻辑是 `getBlogPosts()` + `BlogCard` 网格渲染。改为：

```tsx
import { getSeriesGroups, getStandalonePosts } from '@/data/blogs';
import type { BlogSeries, BlogPost } from '@/types/blog';

const [seriesGroups, setSeriesGroups] = useState<BlogSeries[]>([]);
const [standalonePosts, setStandalonePosts] = useState<BlogPost[]>([]);

useEffect(() => {
  getSeriesGroups().then(setSeriesGroups);
  getStandalonePosts().then(setStandalonePosts);
}, []);

return (
  <>
    {seriesGroups.map(series => (
      <section key={series.name} className="mb-12">
        <div className="flex items-center gap-3 mb-4">
          <img src={series.cover} alt={series.name} className="w-16 h-16 rounded object-cover" />
          <h2 className="text-xl font-bold">{series.name}</h2>
          <span className="text-sm text-gray-500">{series.posts.length} 篇</span>
        </div>
        <div className="grid grid-cols-3 gap-6">
          {series.posts.map(post => <BlogCard key={post.id} post={post} />)}
        </div>
      </section>
    ))}

    {standalonePosts.length > 0 && (
      <section>
        <h2 className="text-xl font-bold mb-4">其他文章</h2>
        <div className="grid grid-cols-3 gap-6">
          {standalonePosts.map(post => <BlogCard key={post.id} post={post} />)}
        </div>
      </section>
    )}
  </>
);
```

**分类/标签筛选的处理**：现有页面应该已经有 `getPostsByCategory`/`getPostsByTag`/`searchPosts` 驱动的筛选态。建议：无筛选（"全部"）时走上面按系列分组的视图；一旦用户选中具体分类/标签或发起搜索，回退成现有的扁平列表（复用原有的 `getPostsByCategory` 等函数，不套系列分组）——因为筛选结果通常是跨系列的，分组展示反而割裂结果。这个切换只需在原有筛选态变量上加一个 `isFiltering ? 扁平列表 : 分组视图` 的判断，不需要新建状态。
