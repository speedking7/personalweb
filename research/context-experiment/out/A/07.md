基于你贴出的三个文件,给出完整实现方案。核心思路:`series` 只是 frontmatter 里的一个字符串标识,封面图不塞进每篇文章的 frontmatter(避免同系列文章里封面互相打架),而是单独建一个系列注册表来维护"系列名 → 封面路径"的映射,两条数据源(飞书 / 本地 md)产出的文章只要 `series` 字段能对上这个表,就能拿到封面。

## 1. `app/src/types/blog.ts` — 加一个可选字段

```ts

  id: string;
  title: string;
  excerpt: string;
  content: string;
  coverImage: string;
  category: string;
  tags: string[];
  date: string;
  readTime: number;
  series?: string;
}
```

## 2. `app/src/lib/markdown.ts` — 解析 `series` 字段

在 `categoryMatch` 后面加一行(其余解析逻辑不动):

```ts
    const seriesMatch = frontmatter.match(/series:\s*["']?([^"'\n]+)["']?/);
    if (seriesMatch) metadata.series = seriesMatch[1].trim();
```

不需要设默认值——`series` 是可选字段,没写就是 `undefined`,不属于任何系列。

## 3. 新建 `app/src/data/series.ts` — 系列封面注册表

```ts
/**
 * [POS]: 系列元数据的唯一登记处。封面是本地图片,与文章内容解耦——
 * 无论文章来自飞书还是本地 md,只要 frontmatter 的 series 字段能匹配这里的 key,
 * 就能拿到封面。不把封面塞进每篇文章的 frontmatter,是为了避免同系列内
 * 不同文章各自声明不同封面导致互相打架。
 */
export interface SeriesMeta {
  cover: string; // 本地相对路径,与文章 cover 字段同规则(如 covers/series/ai-transform.svg)
  description?: string;
}

export const seriesRegistry: Record<string, SeriesMeta> = {
  'AI 转型指南': {
    cover: 'covers/series/ai-transform.svg',
    description: '从传统开发到 AI 辅助工作流的转型笔记',
  },
};
```

封面图片实体放在 `app/src/content/covers/series/` 下(与现有 post 封面同级目录约定),`.svg`/`.png` 都行。

## 4. `app/src/data/blogs.ts` — 分组函数

导入注册表,新增 `groupPostsBySeries`,复用已有的 `resolveCover`(它已经处理了 GitHub Pages 的 BASE_URL 前缀和绝对 URL 直通逻辑,系列封面完全可以吃同一套规则):

```ts
import { seriesRegistry } from './series';

export interface SeriesGroup {
  series: string;
  cover: string;
  description?: string;
  posts: BlogPost[];
}

/**
 * 按系列分组。无 series 字段的文章进 ungrouped,由调用方决定展示位置。
 */
export function groupPostsBySeries(posts: BlogPost[]): { groups: SeriesGroup[]; ungrouped: BlogPost[] } {
  const bySeries = new Map<string, BlogPost[]>();
  const ungrouped: BlogPost[] = [];

  posts.forEach(post => {
    if (!post.series) {
      ungrouped.push(post);
      return;
    }
    const list = bySeries.get(post.series) ?? [];
    list.push(post);
    bySeries.set(post.series, list);
  });

  const groups: SeriesGroup[] = Array.from(bySeries.entries()).map(([series, seriesPosts]) => {
    const meta = seriesRegistry[series];
    if (!meta) {
      console.warn(`系列 "${series}" 未在 seriesRegistry 中登记封面,已退化为该系列第一篇文章的封面`);
    }
    return {
      series,
      cover: resolveCover(meta?.cover ?? seriesPosts[0].coverImage),
      description: meta?.description,
      posts: [...seriesPosts].sort((a, b) => b.date.localeCompare(a.date)),
    };
  });

  return { groups, ungrouped };
}
```

顶部文件头的 `[OUTPUT]` 注释按你项目的 PROTOCOL 约定加一句:`groupPostsBySeries 按系列分组`。

**需要你确认一点**:文件头注释提到飞书和本地 md 共用 `parseBlogMetadata`。如果 `feishuBlogClient.fetchBlogPosts()` 内部确实是直接调这个函数产出 `BlogPost`,那 `series` 字段自动打通,飞书文档里写了 `series:` 元数据就能生效。如果飞书那边是自己单独摘字段拼 `BlogPost`(没走 `parseBlogMetadata`),需要在 `lib/feishu.ts` 里同样加一行 `series` 的摘取,否则会出现"本地文章能分组、飞书文章不能分组"的两条链路漂移——这正是这个文件注释里点名警惕的问题。

## 5. 新建 `app/src/components/SeriesSection.tsx` — 单个系列的展示单元

```tsx
import type { BlogPost } from '@/types/blog';
import type { SeriesGroup } from '@/data/blogs';
import { BlogCard } from './BlogCard'; // 复用现有的文章卡片组件

export function SeriesSection({ group }: { group: SeriesGroup }) {
  return (
    <section className="series-section">
      <div
        className="series-section__banner"
        style={{ backgroundImage: `url(${group.cover})` }}
      >
        <h2>{group.series}</h2>
        {group.description && <p>{group.description}</p>}
        <span>{group.posts.length} 篇</span>
      </div>
      <div className="series-section__posts">
        {group.posts.map((post: BlogPost) => (
          <BlogCard key={post.id} post={post} />
        ))}
      </div>
    </section>
  );
}
```

如果你现有的 `BlogCard` props 不是 `{ post }` 这种形状,按实际签名调整即可,核心是遍历 `group.posts` 渲染卡片。
