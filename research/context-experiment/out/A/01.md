## 1. `app/src/types/blog.ts` — 新增字段与分组类型

```ts
export interface BlogPost {
  id: string;
  title: string;
  excerpt: string;
  content: string;
  coverImage: string;
  category: string;
  tags: string[];
  date: string;
  readTime: number;
  series?: string;       // 系列名称，不填则不属于任何系列
  seriesCover?: string;  // 系列封面图，相对路径或完整 URL
}

export interface BlogSeries {
  name: string;
  cover: string;
  posts: BlogPost[];
}
```

`series`/`seriesCover` 设为可选，未命中 frontmatter 的文章保持原有单篇展示逻辑不受影响。

## 2. `app/src/lib/markdown.ts` — frontmatter 解析新增两个字段

跟现有 `category`/`cover` 同款正则,加在 `coverMatch` 之后:

```ts
    const seriesMatch = frontmatter.match(/series:\s*["']?([^"'\n]+)["']?/);
    if (seriesMatch) metadata.series = seriesMatch[1].trim();

    const seriesCoverMatch = frontmatter.match(/seriesCover:\s*["']?([^"'\n]+)["']?/);
    if (seriesCoverMatch) metadata.seriesCover = seriesCoverMatch[1].trim();
```

注意不要在"设置默认值"那段给 `series` 补默认值——它必须保持 `undefined` 语义,代表"不属于任何系列",不能像 `category` 那样兜底成字符串。

飞书链路复用同一个 `parseBlogMetadata`(见 blogs.ts 头部注释),因此只要 `lib/feishu.ts` 内部走的是这个解析器,飞书文章无需额外改动即可自动获得 `series` 字段。如果 `lib/feishu.ts` 是自己单独解析 metadata 而没有调用 `parseBlogMetadata`,则需要同步在那边补一份——这一点建议实际改的时候顺手确认一下那个文件。

## 3. `app/src/data/blogs.ts` — 封面路径解析 + 分组导出

**3.1** `staticBlogPosts` 构建时,`seriesCover` 要走跟 `coverImage` 一样的 `resolveCover`(否则本地能看见、GitHub Pages 部署后 404,踩上头部注释里提过的同一个坑):

```ts
const staticBlogPosts: BlogPost[] = Object.entries(localPostModules)
  .map(([path, raw]) => {
    const slug = path.split('/').pop()!.replace(/\.md$/, '');
    const post = { title: slug, excerpt: '', coverImage: '', ...parseBlogMetadata(raw, slug) } as BlogPost;
    return {
      ...post,
      coverImage: resolveCover(post.coverImage),
      seriesCover: post.seriesCover ? resolveCover(post.seriesCover) : post.seriesCover,
    };
  })
  .sort((a, b) => b.date.localeCompare(a.date));
```

**3.2** 新增分组函数与对外接口,放在 `searchPosts` 后面:

```ts
import type { BlogPost, BlogSeries } from '@/types/blog';
export type { BlogPost, BlogSeries };

function groupPostsBySeries(posts: BlogPost[]): BlogSeries[] {
  const map = new Map<string, BlogSeries>();
  for (const post of posts) {
    if (!post.series) continue;
    const existing = map.get(post.series);
    if (existing) {
      existing.posts.push(post);
      if (!existing.cover && post.seriesCover) existing.cover = post.seriesCover;
    } else {
      map.set(post.series, { name: post.series, cover: post.seriesCover ?? '', posts: [post] });
    }
  }
  return Array.from(map.values());
}

/**
 * 按系列分组博客文章
 * 同一系列下多篇文章若封面不一致，取第一篇非空的 seriesCover
 */
export async function getSeriesList(): Promise<BlogSeries[]> {
  const posts = await getBlogPosts();
  return groupPostsBySeries(posts);
}
```

`getBlogPosts()` 已经处理好 feishu/static/auto 三态降级,`getSeriesList` 直接复用它,不需要重新走一遍降级分支。

## 5. 列表页分组展示(未提供该文件源码,以下是接入点)

你贴的三个文件里没有实际的列表页组件(大概率是 `pages/Blog.tsx`),我没看到它现在怎么渲染 `getBlogPosts()`/`getCategories()` 的结果,所以下面是基于现有数据层 API 风格给的接入示例,具体要按那个文件里已有的状态管理/组件结构接进去:

```tsx
const [series, setSeries] = useState<BlogSeries[]>([]);
const [posts, setPosts] = useState<BlogPost[]>([]);

useEffect(() => {
  getSeriesList().then(setSeries);
  getBlogPosts().then(setPosts);
}, []);

const seriesPostIds = new Set(series.flatMap(s => s.posts.map(p => p.id)));
const standalonePosts = posts.filter(p => !seriesPostIds.has(p.id));
```

渲染顺序:先按 `series` 循环渲染分组卡片(封面 `s.cover` + 名称 `s.name` + `s.posts.length` 篇),再渲染 `standalonePosts` 作为不属于任何系列的普通列表,复用现有的单篇 BlogCard 组件即可。
