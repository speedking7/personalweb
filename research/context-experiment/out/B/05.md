这是一个纯前端数据链路的扩展：新增字段 → 两个解析入口（本地 md / 飞书）都要认得它 → 列表页按它分组。核心难点在「系列封面」——系列不是一篇文章，没有自己的 frontmatter，所以封面配置只能单独放。方案如下：

## 改动文件清单

| 文件 | 改动 |
|---|---|
| `types/blog.ts` | `BlogPost` 加 `series?: string` |
| `lib/markdown.ts` | frontmatter 新增解析 `series` |
| `lib/feishu.ts` | 飞书路径透传 `metadata.series` |
| `lib/utils.ts` | 抽出 `resolveAssetPath`（原 blogs.ts 里的 `resolveCover`，系列封面也要用） |
| `data/blogs.ts` | 改用共享的 `resolveAssetPath` |
| `data/series.ts`（新增） | 系列名 → 封面图的映射配置 |
| `pages/Blog.tsx` | 列表页渲染系列分组卡片 + 接入筛选 |
| `public/series-covers/default.svg`（新增） | 未登记系列的占位封面 |

### 1. `app/src/types/blog.ts`

```ts
export interface BlogPost {
  id: string;
  title: string;
  excerpt: string;
  content: string;
  coverImage: string;
  category: string;
  tags: string[];
  date: string;
  readTime: number;
  /** 所属系列，对应 frontmatter 的 series 字段；不属于任何系列时为 undefined */
  series?: string;
}
```

### 2. `app/src/lib/markdown.ts`

在 `categoryMatch` 后面加一行解析，**不设默认值**——没有 series 就是 undefined，不像 category 那样兜底成"未分类"，否则所有散文章会被误聚合进一个假系列：

```ts
const categoryMatch = frontmatter.match(/category:\s*["']?([^"'\n]+)["']?/);
if (categoryMatch) metadata.category = categoryMatch[1].trim();

const seriesMatch = frontmatter.match(/series:\s*["']?([^"'\n]+)["']?/);
if (seriesMatch) metadata.series = seriesMatch[1].trim();
```

头部注释同步补一句：`[POS]` 段末尾加"新增 series 字段用于系列文章分组，两条数据源解析规则必须保持一致"。

### 3. `app/src/lib/feishu.ts`

`fetchBlogPosts()` 里组装 `posts.push({...})` 时补上一行，否则飞书来源的文章永远没有 series：

```ts
posts.push({
  id: metadata.id!,
  title: metadata.title || node.title,
  excerpt: metadata.excerpt || '',
  content: metadata.content || content,
  coverImage: metadata.coverImage || this.getDefaultCover(metadata.category),
  category: metadata.category || '未分类',
  tags: metadata.tags || [],
  date: metadata.date || new Date().toISOString().split('T')[0],
  readTime: metadata.readTime || 5,
  series: metadata.series,          // 新增
});
```

### 4. `app/src/lib/utils.ts`

`data/blogs.ts` 里原本有个私有的 `resolveCover`，系列封面要做同样的事（补 GitHub Pages 部署前缀），与其复制一份，不如提出来共用：

```ts
import { clsx, type ClassValue } from "clsx"
import { twMerge } from "tailwind-merge"

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs))
}

/**
 * 把内容里写的本地相对路径（如 covers/x.svg）补上部署 base（GitHub Pages 下是 /personalweb/）。
 * 绝对 URL 和以 / 开头的路径原样返回，避免被前缀污染。
 */
export function resolveAssetPath(path: string): string {
  if (!path || /^(https?:)?\/\//.test(path) || path.startsWith('/')) {
    return path;
  }
  return `${import.meta.env.BASE_URL}${path}`;
}
```

### 5. `app/src/data/blogs.ts`

删掉本地 `resolveCover`，改成引用共享函数：

```ts
import { feishuBlogClient } from '@/lib/feishu';
import { parseBlogMetadata } from '@/lib/markdown';
import { resolveAssetPath } from '@/lib/utils';   // 新增
import type { BlogPost } from '@/types/blog';

// ...

// 删除原来的：
// const resolveCover = (cover: string): string => ...

const staticBlogPosts: BlogPost[] = Object.entries(localPostModules)
  .map(([path, raw]) => {
    const slug = path.split('/').pop()!.replace(/\.md$/, '');
    const post = { title: slug, excerpt: '', coverImage: '', ...parseBlogMetadata(raw, slug) } as BlogPost;

```

头部 `[INPUT]` 那行同步改成"依赖 @/lib/utils 的 resolveAssetPath 补全部署路径前缀"。

### 6. `app/src/data/series.ts`（新增）

系列封面独立配置，键是系列名本身（中文自由文本，不做 slug 化，可读即所见）：

```ts
/**
 * [INPUT]: 依赖 @/lib/utils 的 resolveAssetPath 补全部署路径前缀
 * [OUTPUT]: 对外提供 getSeriesCover —— 按系列名取封面图路径
 * [POS]: data/ 层的系列封面配置，被 pages/Blog 的系列分组卡片消费。
 *        系列由文章 frontmatter 的 series 字段自由命名，此处不做 slug 化——
 *        中文系列名直接作为对象键，读起来即所见即所得，省掉一张额外的 id 映射表。
 *        新增系列 = 把封面图放进 public/series-covers/，在下方补一行映射；
 *        未登记的系列显式回退到占位封面，而不是让 <img> 破图
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { resolveAssetPath } from '@/lib/utils';

// 系列名 -> 封面图相对路径（相对于 public/，Vite 构建时原样拷贝到产物根目录）
const seriesCovers: Record<string, string> = {
  'AI 转型指南': 'series-covers/ai-transformation.svg',
};

const DEFAULT_SERIES_COVER = 'series-covers/default.svg';

export function getSeriesCover(series: string): string {
  return resolveAssetPath(seriesCovers[series] ?? DEFAULT_SERIES_COVER);
}
```

图片实际放在 `app/public/series-covers/` 下（Vite 的 `public/` 是原样拷贝到产物根目录的静态资源目录，`data/blogs.ts` 里文章封面走的是同一套机制）。占位图：

### 7. `app/src/pages/Blog.tsx`

加 import、加状态、按 `posts` 聚合系列（写法和已有的 `archives` 归档聚合完全同构，不新增数据层查询，避免重复请求）、接入筛选、渲染分组卡片。

```tsx
import { getSeriesCover } from '@/data/series';   // 新增 import

// ...组件内，state 部分
const [activeSeries, setActiveSeries] = useState<string | null>(null);

// ...紧跟在 archives 计算之后，同样从已加载的 posts 聚合
// 系列同样由真实文章聚合而来，不写死；无 series 字段的文章不参与分组
const seriesGroups = Array.from(
  posts.reduce((map, post) => {
    if (!post.series) return map;
    const list = map.get(post.series) ?? [];
    list.push(post);
    map.set(post.series, list);
    return map;
  }, new Map<string, BlogPost[]>())
);

// filteredPosts 加一个 matchesSeries 条件
const filteredPosts = posts.filter((post) => {
  const matchesCategory =
    activeCategory === '全部' || post.category === activeCategory;
  const matchesTag = !activeTag || post.tags.includes(activeTag);
  const matchesSeries = !activeSeries || post.series === activeSeries;   // 新增
  const matchesSearch =
    !searchQuery ||
    post.title.toLowerCase().includes(searchQuery.toLowerCase()) ||
    post.excerpt.toLowerCase().includes(searchQuery.toLowerCase());
  return matchesCategory && matchesTag && matchesSeries && matchesSearch; // 加 matchesSeries
});
```

在「搜索 & 分类筛选卡片」和「Loading/文章列表」之间插入系列分组区块：

```tsx
{!loading && !error && seriesGroups.length > 0 && (
  <div className="bg-white rounded-xl p-4 mb-6 shadow-sm">

              : 'bg-[#f8f8f8] hover:bg-[#f0f0f0]'

            alt={name}

          />
          <div className="min-w-0">
            <p className="font-medium truncate">{name}</p>

              {seriesPosts.length} 篇
            </p>
          </div>
        </button>
      ))}
    </div>
  </div>
)}
```

顺带在文章卡片上补一个系列徽标（放在 category 徽标旁边，点开列表就能看出某篇文章属于哪个系列）：

## 使用方式

新增一篇系列文章，只需在 `content/posts/*.md` 的 frontmatter 里加一行：

```markdown
---
title: "AI 转型指南：从工具到心智模型"
category: "技术"
series: "AI 转型指南"
tags: [AI, 转型]
date: "2026-08-01"
cover: "covers/ai-1.svg"
excerpt: "系列第一篇：为什么先谈心智模型，而不是工具清单。"
---
```

同一系列的其他文章重复同样的 `series: "AI 转型指南"` 即可自动聚合；封面图只需要在 `data/series.ts` 里登记一次。
