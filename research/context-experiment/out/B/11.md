## 3. `src/lib/paths.ts`(新建)

把 `data/blogs.ts` 里原本私有的 `resolveCover` 提升为公共工具,系列封面要复用同一套"本地相对路径补 base"逻辑,不能各写一份、日后跑偏。

```ts
/**
 * [INPUT]: 无外部依赖，读取 import.meta.env.BASE_URL
 * [OUTPUT]: 对外提供 resolveAssetPath —— 给项目内相对路径的静态资源补上部署 base
 * [POS]: lib/ 层的路径工具，被 data/blogs 与 data/series 共用。
 *        绝对 URL（http/https）与以 / 开头的路径原样返回；只有仓库内相对路径
 *        （如 covers/x.svg）才需要补 base，否则本地 dev 能看见、GitHub Pages 上是 404
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

import { resolveAssetPath } from '@/lib/paths';

## 6. `src/data/series.ts`(新建)

系列封面是"系列"这个概念本身的属性,不是某一篇文章的字段——所以单独建一张 `name -> 封面路径` 的映射表,而不是让系列里每篇文章各自在 frontmatter 里填一遍封面(那样容易同系列文章封面互相打架)。

```ts
/**
 * [INPUT]: 依赖 @/lib/paths 的 resolveAssetPath 补全封面路径，@/types/blog 的 BlogPost 契约
 * [OUTPUT]: 对外提供 getSeriesCover 封面查询、groupPostsBySeries 按系列分组聚合
 * [POS]: data/ 层的系列数据，被 pages/Blog 消费。封面配置与文章数据分离——
 *        系列封面是系列本身的属性，用一张表维护，而不是塞进每篇文章的 frontmatter 里重复填写。
 *        分组只对内存里已加载的 posts 做归纳，不发起新的数据源请求
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { resolveAssetPath } from '@/lib/paths';
import type { BlogPost } from '@/types/blog';

// 系列封面配置：系列名 -> 项目内本地相对路径（相对 public/ 根目录）
// 新增系列：把封面图放进 public/series-covers/，在此加一行映射
const seriesCovers: Record<string, string> = {
  'AI 转型指南': 'series-covers/ai-transform.svg',
};

export function getSeriesCover(name: string): string | undefined {
  const raw = seriesCovers[name];
  return raw ? resolveAssetPath(raw) : undefined;
}

export interface SeriesGroup {
  name: string;
  cover?: string;
  posts: BlogPost[];
}

/** 按 series 字段分组；没有 series 的文章不出现在结果里 */
export function groupPostsBySeries(posts: BlogPost[]): SeriesGroup[] {
  const map = new Map<string, BlogPost[]>();
  for (const post of posts) {
    if (!post.series) continue;
    const list = map.get(post.series) ?? [];
    list.push(post);
    map.set(post.series, list);
  }

  return Array.from(map.entries())
    .map(([name, seriesPosts]) => ({
      name,
      cover: getSeriesCover(name),
      // 系列内按时间正序：读者该从第一篇开始看
      posts: [...seriesPosts].sort((a, b) => a.date.localeCompare(b.date)),
    }))
    // 系列间按最新一篇的时间倒序：近期更新的系列排前面
    .sort((a, b) =>
      b.posts[b.posts.length - 1].date.localeCompare(a.posts[a.posts.length - 1].date)
    );
}
```

封面图实际文件放在 `app/public/series-covers/ai-transform.svg`(与现有文章封面走同一套 `public/` 静态资源约定,`resolveAssetPath` 会自动补 GitHub Pages 的 base 前缀)。

## 7. `src/pages/Blog.tsx`(修改)

导入分组函数,基于当前筛选结果(`filteredPosts`)计算系列分组和"未入系列"的散篇列表,在原来的文章列表之上先渲染系列区块。

**顶部 import 加一行:**
```tsx
import { groupPostsBySeries } from '@/data/series';
```

**在 `filteredPosts` 定义之后加分组计算:**
```tsx
  const filteredPosts = posts.filter((post) => {
    const matchesCategory =
      activeCategory === '全部' || post.category === activeCategory;
    const matchesTag = !activeTag || post.tags.includes(activeTag);
    const matchesSearch =
      !searchQuery ||
      post.title.toLowerCase().includes(searchQuery.toLowerCase()) ||
      post.excerpt.toLowerCase().includes(searchQuery.toLowerCase());
    return matchesCategory && matchesTag && matchesSearch;
  });

  const seriesGroups = groupPostsBySeries(filteredPosts);
  const standalonePosts = filteredPosts.filter((post) => !post.series);
```

**替换原来的 "Posts List" 渲染块**(原来直接 `.map(filteredPosts...)`,现在先渲染系列,再渲染散篇;并把空状态判断改成两者都为空才提示):
