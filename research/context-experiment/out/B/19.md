## 实现方案

系列元数据（封面等）不写进每篇文章的 frontmatter，而是单独建一个 `data/series.ts` 做「系列名 → 封面」的映射表——这样封面只需维护一处，不用每篇文章重复填，也符合本项目 `giscus.ts`/`music.ts` 那种集中配置的写法。文章 frontmatter 只需要 `series: 系列名` 一个字段，靠这个名字去查表。

### 涉及文件

| 文件 | 改动 |
|---|---|
| `types/blog.ts` | `BlogPost` 加 `series?: string` |
| `lib/markdown.ts` | frontmatter 解析加 `series` 字段 |
| `lib/feishu.ts` | 把 `metadata.series` 透传进飞书文章对象 |
| `lib/utils.ts` | 抽出 `resolveAssetPath`（本地相对路径补 BASE_URL），供 `blogs.ts` 和新的 `series.ts` 共用 |
| `data/series.ts`（新增） | 系列名 → 封面图的映射表 + 兜底封面 |
| `data/blogs.ts` | 改用共享的 `resolveAssetPath`；新增 `groupPostsBySeries` |
| `pages/Blog.tsx` | 列表页先渲染系列分组卡片，再渲染无系列的散篇 |
| `public/covers/series/*.svg` | 实际封面图片文件（本地相对路径引用的落地位置） |

### 2. `app/src/lib/markdown.ts`

在 `coverMatch` 那段旁边加一行解析（frontmatter 分支内）：

```ts
const coverMatch = frontmatter.match(/cover:\s*["']?([^"'\n]+)["']?/);
if (coverMatch) metadata.coverImage = coverMatch[1].trim();

const seriesMatch = frontmatter.match(/series:\s*["']?([^"'\n]+)["']?/);
if (seriesMatch) metadata.series = seriesMatch[1].trim();
```

没有默认值——不属于任何系列的文章 `series` 就是 `undefined`，不强行给个「未分组」字符串污染分组逻辑。

### 4. `app/src/lib/utils.ts`

把 `blogs.ts` 里那段本地路径补 base 的逻辑提出来共用：

```ts
import { clsx, type ClassValue } from "clsx"
import { twMerge } from "tailwind-merge"

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs))
}

/** 相对路径补上部署 base；绝对 URL 或以 / 开头的路径原样返回 */
export function resolveAssetPath(path: string): string {
  return !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
}
```

### 5. `app/src/data/series.ts`（新增）

```ts
/**
 * [INPUT]: 依赖 @/lib/utils 的 resolveAssetPath 补部署 base
 * [OUTPUT]: 对外提供 getSeriesCover —— 按系列名取封面图路径
 * [POS]: data/ 层的系列封面配置。文章 frontmatter 里的 series 只是个名字字符串，
 *        封面图与该名字的映射集中在这一处维护，避免同一系列的封面在多篇文章里各写各的、
 *        改封面要改一堆文件。找不到对应系列时落到 defaultCover，不让页面出现裂图
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { resolveAssetPath } from '@/lib/utils';

// key 必须与文章 frontmatter 里 series 字段的原文完全一致（含空格、标点）
const seriesCovers: Record<string, string> = {
  'AI 转型指南': 'covers/series/ai-transformation.svg',
};

const defaultCover = 'covers/series/default.svg';

export function getSeriesCover(seriesName: string): string {
  return resolveAssetPath(seriesCovers[seriesName] ?? defaultCover);
}
```

图片实际放在 `app/public/covers/series/` 下（与现有文章封面 `covers/x.svg` 同一套目录约定，`public/` 内的文件按原样从 BASE_URL 下发布），新增系列时把图丢进这个目录、在上面表里加一行即可。记得放一张 `default.svg` 兜底。

### 6. `app/src/data/blogs.ts`

删掉文件内自己写的 `resolveCover`，改用共享版本；并新增分组函数：

```ts
import { feishuBlogClient } from '@/lib/feishu';
import { parseBlogMetadata } from '@/lib/markdown';
import { resolveAssetPath } from '@/lib/utils';
import { getSeriesCover } from '@/data/series';
import type { BlogPost } from '@/types/blog';

// ... staticBlogPosts 里 resolveCover(...) 全部换成 resolveAssetPath(...)

export interface SeriesGroup {
  name: string;
  cover: string;
  posts: BlogPost[];
}

/**
 * 按系列名对文章分组。未设置 series 的文章归入 standalone，原样保留原有渲染方式。
 * 系列内部按日期升序——读者理应从第一篇开始追更，而不是先看到最新一篇。
 */
export function groupPostsBySeries(posts: BlogPost[]): {
  series: SeriesGroup[];
  standalone: BlogPost[];
} {
  const seriesMap = new Map<string, BlogPost[]>();
  const standalone: BlogPost[] = [];

  for (const post of posts) {
    if (!post.series) {
      standalone.push(post);
      continue;
    }
    const list = seriesMap.get(post.series) ?? [];
    list.push(post);
    seriesMap.set(post.series, list);
  }

  const series = Array.from(seriesMap.entries()).map(([name, seriesPosts]) => ({
    name,
    cover: getSeriesCover(name),
    posts: seriesPosts.slice().sort((a, b) => a.date.localeCompare(b.date)),
  }));

  return { series, standalone };
}
```

`resolveCover` 原本是模块内私有函数，删除时注意 `staticBlogPosts` 那段 `.map(...)` 里的调用点也要同步改名。

### 使用方式

新文章 frontmatter 里加一行：

```yaml
---
title: "从提示词到 Agent"
category: 技术
series: AI 转型指南
date: 2026-08-20
---
```

新系列首次出现时，去 `data/series.ts` 补一行映射，并把封面图放进 `app/public/covers/series/`。
