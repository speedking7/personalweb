## 改动方案

核心思路：`series` 只是 frontmatter 里的一个字符串标识，真正的系列元数据（封面图、简介）不应该塞进每篇文章里重复填，所以单独建一个 `data/series.ts` 注册表，用系列名字符串做 key 关联两边。

### 涉及文件

1. `app/src/types/blog.ts` — 加 `series` 字段
2. `app/src/lib/utils.ts` — 抽出封面路径解析的公共函数
3. `app/src/lib/markdown.ts` — frontmatter 解析 `series`
4. `app/src/lib/feishu.ts` — 飞书数据源透传 `series`
5. `app/src/data/series.ts`（新增）— 系列注册表：名称 → 封面/简介
6. `app/src/data/blogs.ts` — 新增 `getSeriesGroups()` 按系列分组
7. `app/src/pages/Blog.tsx` — 列表页渲染分组区块
8. 图片放在 `app/public/covers/series/` 下

### 2. `app/src/lib/utils.ts`

把 `blogs.ts` 里那段本地路径补 `BASE_URL` 前缀的逻辑提出来，系列封面要复用同一套规则（否则 GitHub Pages 上系列封面会 404，跟现有文章封面踩过的坑一样）：

```ts
import { clsx, type ClassValue } from "clsx"
import { twMerge } from "tailwind-merge"

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs))
}

/** 相对路径补上部署 base 前缀；绝对 URL 或以 / 开头的路径原样返回 */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

### 3. `app/src/lib/markdown.ts`

在 `categoryMatch` 附近加一行，不给默认值（没写 `series` 就是 `undefined`，不像 `category` 那样兜底成"未分类"——没系列就是没系列）：

```ts
const categoryMatch = frontmatter.match(/category:\s*["']?([^"'\n]+)["']?/);
if (categoryMatch) metadata.category = categoryMatch[1].trim();

const seriesMatch = frontmatter.match(/series:\s*["']?([^"'\n]+)["']?/);
if (seriesMatch) metadata.series = seriesMatch[1].trim();
```

对应文章里这样写：

```md

date: 2026-01-10
---
```

### 5. `app/src/data/series.ts`（新建）

```ts
/**
 * [INPUT]: 依赖 @/lib/utils 的 resolveAssetPath 补全部署 base 前缀
 * [OUTPUT]: 对外提供 SeriesInfo 类型与 getSeriesInfo 查询函数
 * [POS]: data/ 层的系列元数据源。frontmatter 里的 series 只是个名字字符串，
 *        封面图、简介这类与"某一篇文章"无关的信息集中放在这里，
 *        避免同一系列的每篇文章都重复填一遍封面。
 *        系列名字符串是关联两边的唯一 key，必须与文章 frontmatter 里的
 *        series 值逐字一致，大小写、空格都算数。
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { resolveAssetPath } from '@/lib/utils';

export interface SeriesInfo {
  /** 需与文章 frontmatter 中的 series 字段完全一致 */
  name: string;
  /** 封面图本地相对路径，实际文件放在 public/covers/series/ 下 */
  cover: string;
  description?: string;
}

// 新增系列：追加一条注册信息，并把封面图放进 public/covers/series/
const seriesRegistry: SeriesInfo[] = [
  // { name: 'AI 转型指南', cover: 'covers/series/ai-transform.svg', description: '从零开始的 AI 转型笔记' },
];

export function getSeriesInfo(name: string): SeriesInfo | undefined {
  const info = seriesRegistry.find((s) => s.name === name);
  return info ? { ...info, cover: resolveAssetPath(info.cover) } : undefined;
}
```

- 用 `resolveAssetPath` 替换原来私有的 `resolveCover`，去重逻辑：

- 新增分组导出（放在文件末尾、`clearCache` 之前即可）：

```ts
import { getSeriesInfo } from '@/data/series';

export interface SeriesGroup {
  name: string;
  cover?: string;
  description?: string;
  posts: BlogPost[];
}

/**
 * 按系列分组。分组顺序取决于各系列最新一篇文章在全量列表（按日期倒序）中
 * 出现的先后，无需额外排序字段，也不会把没写 series 的文章塞进结果里。
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const order: string[] = [];
  const grouped = new Map<string, BlogPost[]>();

  for (const post of posts) {
    if (!post.series) continue;
    if (!grouped.has(post.series)) {
      grouped.set(post.series, []);
      order.push(post.series);
    }
    grouped.get(post.series)!.push(post);
  }

  return order.map((name) => {
    const info = getSeriesInfo(name);
    return {
      name,
      cover: info?.cover,
      description: info?.description,
      posts: grouped.get(name)!,
    };
  });
}
```

### 7. `app/src/pages/Blog.tsx`

导入与状态：

```ts
import { getBlogPosts, getCategories, getTags, getSeriesGroups, type BlogPost, type SeriesGroup } from '@/data/blogs';

```

`loadBlogData` 里一起拉取：

```ts
const [loadedPosts, loadedCategories, loadedTags, loadedSeriesGroups] = await Promise.all([
  getBlogPosts(),
  getCategories(),
  getTags(),
  getSeriesGroups(),

setPosts(loadedPosts);

setTags(loadedTags);
```

在 `<div className="lg:col-span-2">` 内、"Search & Filter" 卡片**之前**插入分组区块：

```tsx
{/* 系列合集 */}
{seriesGroups.length > 0 && (
  <div className="mb-6 space-y-4">
    <h2 className="text-xl font-medium text-[#1a1a1a]">系列合集</h2>
    {seriesGroups.map((group) => (
      <div key={group.name} className="bg-white rounded-xl overflow-hidden shadow-sm">
        <div className="md:flex">
          {group.cover && (
            <div className="md:w-1/4 aspect-video md:aspect-square overflow-hidden">
              <img
                src={group.cover}
                alt={group.name}
                className="w-full h-full object-cover"
              />
            </div>
          )}
          <div className="p-5 flex-1">
            <div className="flex items-center justify-between mb-2">
              <h3 className="font-medium text-[#1a1a1a]">{group.name}</h3>
              <span className="text-[#9ca3af] text-sm">{group.posts.length} 篇</span>
            </div>
            {group.description && (
              <p className="text-[#6b6b6b] text-sm mb-3">{group.description}</p>
            )}
            <ul className="space-y-1">
              {group.posts.map((post) => (
                <li key={post.id}>
                  <Link
                    to={`/blog/${post.id}`}
                    className="text-[#6b6b6b] hover:text-[#1a1a1a] text-sm transition-colors"
                  >
                    · {post.title}
                  </Link>
                </li>
              ))}
            </ul>
          </div>
        </div>
      </div>
    ))}
  </div>

```

原来的搜索框、分类筛选、文章列表保持不变——系列区块只是加在最上面，不影响现有的按分类/标签/关键词筛选逻辑。

### 图片放置

系列封面实际文件放 `app/public/covers/series/xxx.svg`（跟现有本地文章封面 `covers/*.svg` 同级），`series.ts` 里 `cover` 字段填 `covers/series/xxx.svg` 这种相对路径，`resolveAssetPath` 会在生产环境自动补上 `/personalweb/` 之类的 base 前缀。
