## 2. `app/src/lib/markdown.ts` — 解析 frontmatter 的 series 字段

在 `categoryMatch` 那一段旁边加一行：

```ts
    const categoryMatch = frontmatter.match(/category:\s*["']?([^"'\n]+)["']?/);
    if (categoryMatch) metadata.category = categoryMatch[1].trim();

    // 新增
    const seriesMatch = frontmatter.match(/series:\s*["']?([^"'\n]+)["']?/);
```

不设默认值——没写 `series` 就是不属于任何系列，这点很重要，后面分组逻辑依赖 `undefined` 判断。

对应地，本地文章现在可以这样写 frontmatter：

```md

series: AI 转型指南
date: 2026-08-01
---
```

## 3. `app/src/lib/assetPath.ts`（新建）— 抽出公共的本地路径解析逻辑

`data/blogs.ts` 里原本给文章封面用的 `resolveCover` 只服务于文章封面一处，现在系列封面也要用同一套“相对路径补 BASE_URL”的规则，所以提出来共享：

```ts
/**
 * [INPUT]: 依赖 import.meta.env.BASE_URL
 * [OUTPUT]: 对外提供 resolveAssetPath —— 把本地相对路径补上部署 base
 * [POS]: lib/ 层的通用路径解析器，被 data/blogs 与 data/seriesCovers 共用。
 *        绝对 URL 与以 / 开头的路径原样返回，避免飞书封面被前缀污染
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

## 4. `app/src/data/seriesCovers.ts`（新建）— 系列封面配置

封面是“系列”维度的属性，不是“文章”维度的——如果放进每篇文章的 frontmatter，同一系列的多篇文章填出不一致的封面会很难排查。所以单独建一个映射文件，新增系列时改这一处即可：

```ts
/**
 * [INPUT]: 依赖 @/lib/assetPath 的 resolveAssetPath 补全部署 base
 * [OUTPUT]: 对外提供 getSeriesCover —— 按系列名查封面图
 * [POS]: data/ 层的系列封面配置，被 pages/Blog 消费。
 *        新增系列 = 把封面图放进 public/covers/series/，在下面加一行映射；
 *        查不到映射时返回空字符串，调用方据此不渲染封面图，不用占位图冒充
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { resolveAssetPath } from '@/lib/assetPath';

const seriesCovers: Record<string, string> = {
  'AI 转型指南': 'covers/series/ai-transform.svg',
};

export function getSeriesCover(seriesName: string): string {
  const cover = seriesCovers[seriesName];
  return cover ? resolveAssetPath(cover) : '';
}
```

图片实际放在 `app/public/covers/series/ai-transform.svg`（`public/` 下的文件会被 Vite 原样拷贝到产物根目录，`resolveAssetPath` 负责在部署时补上 `/personalweb/` 这类 base 前缀）。

```ts
const staticBlogPosts: BlogPost[] = Object.entries(localPostModules)
```

在 `filteredPosts` 之后新增分组逻辑：

```tsx
// 按系列分组：有 series 的文章归入对应系列（保留首次出现顺序），其余进入 ungrouped
const seriesGroups = filteredPosts.reduce<{ name: string; posts: BlogPost[] }[]>(
  (groups, post) => {
    if (!post.series) return groups;
    const group = groups.find((g) => g.name === post.series);
    if (group) group.posts.push(post);
    else groups.push({ name: post.series, posts: [post] });
    return groups;
  },
  []
);
const ungroupedPosts = filteredPosts.filter((post) => !post.series);
```

## 设计要点

- 分组是对**筛选后**的 `filteredPosts` 做的，所以分类/标签/搜索照常生效，系列分组只影响展示结构，不是额外的筛选维度。
- 没有系列的文章不受影响：`seriesGroups` 为空时直接走 `ungroupedPosts`（=全部 `filteredPosts`），渲染效果和分组功能上线前完全一样。
- 封面缺失时 `getSeriesCover` 返回空串，`{getSeriesCover(...) && <img />}` 直接不渲染图片，不会用占位图冒充。
- `BlogDetail.tsx`、`Home.tsx` 未改动——如果需要在文章详情页显示"本系列其他文章"，可以复用 `getSeriesCover` + 按 `post.series` 过滤 `getBlogPosts()` 结果，思路和现有 `RelatedPosts` 组件一致，需要的话我可以继续补上。
