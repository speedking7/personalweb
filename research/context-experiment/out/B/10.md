## 设计概要

- `series` 作为 frontmatter 可选字段，走现有的 `parseBlogMetadata` 统一解析（飞书文档和本地 `.md` 共用一套逻辑，不新增第二套解析规则)。
- 系列封面**不**塞进每篇文章的 frontmatter，而是单独建一个 `data/series.ts` 配置表（复用本项目 `giscus.ts` 那种"集中配置"模式）——同系列多篇文章共享一张封面，写进 frontmatter 会导致多篇各自维护、容易失配。
- 封面路径解析逻辑（`covers/x.svg` → 补 `BASE_URL`）目前私有在 `blogs.ts` 里，抽成 `lib/assets.ts` 给 `blogs.ts` 和 `series.ts` 共用，避免复制粘贴。
- 列表页新增"系列专栏"横向卡片区，点击进入该系列的过滤视图，不新增路由，改动集中在 `Blog.tsx`。

### 4. 新建 `app/src/lib/assets.ts` —— 从 `blogs.ts` 抽出的路径解析器

```ts
/**
 * [INPUT]: 无外部依赖，仅读取 import.meta.env.BASE_URL
 * [OUTPUT]: 对外提供 resolveAssetPath —— 把本地相对路径补上部署 base
 * [POS]: lib/ 层的资源路径解析器，被 data/blogs 与 data/series 共用。
 *        绝对 URL 与以 / 开头的路径原样返回，只有裸相对路径才补前缀——
 *        本地 dev 能看见、发到 GitHub Pages 就 404 的坑就出在这条规则上
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

### 5. 新建 `app/src/data/series.ts` —— 系列封面配置

图片实际存放位置：**`app/public/covers/series/`**（Vite 的 `public/` 会原样发布到 `BASE_URL` 根下，与现有文章封面 `covers/x.svg` 同一套约定）。

```ts
/**
 * [INPUT]: 依赖 @/lib/assets 的 resolveAssetPath 补全部署 base
 * [OUTPUT]: 对外提供 SeriesMeta 类型、seriesConfig 配置表、getSeriesCover/getSeriesDescription 查询
 * [POS]: data/ 层的系列元数据配置，被 data/blogs 的分组逻辑消费。
 *        封面集中配置在此而非塞进 frontmatter——同系列文章共享一张封面，
 *        写进每篇文章会导致多处维护、容易前后失配
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { resolveAssetPath } from '@/lib/assets';

export interface SeriesMeta {
  cover: string;
  description?: string;
}

// key 必须与文章 frontmatter 里的 series 字段完全一致（含大小写、空格）。
// 图片放在 app/public/covers/series/ 下，此处填相对路径。
export const seriesConfig: Record<string, SeriesMeta> = {
  'AI 转型指南': {
    cover: 'covers/series/ai-transformation.svg',
    description: '从传统岗位转向 AI 从业者的一路实录',
  },
};

/** 未在 seriesConfig 登记的系列，回退为 undefined，由调用方决定兜底（通常用系列内第一篇文章的封面） */
export function getSeriesCover(seriesName: string): string | undefined {
  const meta = seriesConfig[seriesName];
  return meta ? resolveAssetPath(meta.cover) : undefined;
}

export function getSeriesDescription(seriesName: string): string | undefined {
  return seriesConfig[seriesName]?.description;
}
```

**b) 新增分组类型与函数（放在文件末尾、`clearCache` 之前）：**

```ts
export interface SeriesGroup {
  name: string;
  cover?: string;
  description?: string;
  posts: BlogPost[];
}

/**
 * 按系列分组博客文章。
 * 只收纳写了 series 字段的文章；未归入系列的文章不出现在结果里。
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const groups = new Map<string, BlogPost[]>();

  for (const post of posts) {
    if (!post.series) continue;
    const list = groups.get(post.series) ?? [];
    list.push(post);
    groups.set(post.series, list);
  }

  return Array.from(groups.entries())
    .map(([name, seriesPosts]) => {
      const sorted = [...seriesPosts].sort((a, b) => a.date.localeCompare(b.date));
      return {
        name,
        // 配置里没登记封面时，退而用系列内第一篇文章的封面，不留空白
        cover: getSeriesCover(name) ?? sorted[0]?.coverImage,
        description: getSeriesDescription(name),
        posts: sorted, // 系列内按日期升序，读者从头篇开始追更
      };
    })
    // 系列本身按最新一篇日期倒序，活跃系列排前面
    .sort((a, b) => {
      const aLatest = a.posts[a.posts.length - 1]?.date ?? '';
      const bLatest = b.posts[b.posts.length - 1]?.date ?? '';
      return bLatest.localeCompare(aLatest);
    });
}
```

**c) 更新文件头部注释**（该文件自带 `PROTOCOL: 变更时更新此头部` 的约定），`[OUTPUT]` 一行补上：

```
 * [OUTPUT]: 对外提供 getBlogPosts/getBlogPost 读取、getCategories/getTags/getSeriesGroups 聚合、
 *           getPostsByCategory/getPostsByTag/searchPosts 筛选、setDataSourceMode 与 clearCache 控制
```
