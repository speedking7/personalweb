## 总体设计

- **数据层**：`series` 字段随 frontmatter 解析进 `BlogPost`，飞书和本地文章共用同一个解析器，不会出现两套规则漂移。
- **配置层**：新增 `data/series.ts` 维护「系列名 → 封面/描述/排序」，因为系列本身没有独立 markdown 文件，封面只能人工登记；未登记的系列自动退化为用该系列最早一篇文章的封面兜底，不写死占位图。
- **聚合层**：`data/blogs.ts` 新增 `getSeriesGroups()`，按 `series` 字段对现有文章分组，不影响原有 `getBlogPosts` 等接口。
- **UI 层**：`pages/Blog.tsx` 在原有搜索/分类之上新增「系列文章」卡片网格，点击进入系列内的有序阅读视图；不点系列时页面行为与现在完全一致。

## 4. `app/src/lib/assets.ts`（新建）

把 `blogs.ts` 里原本内联的 `resolveCover` 提出来，因为系列封面要复用同一套「相对路径补 `BASE_URL`」逻辑，两处各写一份会在部署路径变化时各自漂移。

```ts
/**
 * [INPUT]: 依赖 import.meta.env.BASE_URL
 * [OUTPUT]: 对外提供 resolveAssetPath —— 把项目内相对路径解析为可用的 <img src>
 * [POS]: lib/ 层的静态资源路径解析器，被 data/blogs（文章封面）与 data/series（系列封面）共用。
 *        本地 dev 与 GitHub Pages 部署的 base path 不同，相对路径必须在此统一补前缀，
 *        否则本地能看见、线上 404
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */

/** 绝对 URL 或以 / 开头的路径原样返回，仅对纯相对路径补 BASE_URL */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

## 5. `app/src/data/series.ts`（新建）

```ts
/**
 * [INPUT]: 依赖 @/lib/assets 的 resolveAssetPath 解析封面相对路径
 * [OUTPUT]: 对外提供 SeriesMeta 类型与 seriesConfig 配置表
 * [POS]: data/ 层的系列元数据配置，被 data/blogs 的 getSeriesGroups 消费。
 *        系列没有独立的 markdown 文件，封面/排序只能人工维护在这里；
 *        没在此登记的系列名，getSeriesGroups 会退化为用该系列最早一篇文章的封面兜底
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { resolveAssetPath } from '@/lib/assets';

export interface SeriesMeta {
  cover: string;
  description?: string;
  /** 数字越小排越前，不填的排在后面并按名称排序 */
  order?: number;
}

// key 必须与文章 frontmatter 里的 series 字段逐字一致（含空格）
const rawSeriesConfig: Record<string, SeriesMeta> = {
  'AI 转型指南': {
    cover: 'covers/series/ai-transform.svg',
    description: '从传统开发到 AI 辅助开发的转型笔记',
    order: 1,
  },
};

export const seriesConfig: Record<string, SeriesMeta> = Object.fromEntries(
  Object.entries(rawSeriesConfig).map(([name, meta]) => [
    name,
    { ...meta, cover: resolveAssetPath(meta.cover) },
  ])
);
```

- 文件末尾新增分组聚合函数：

```ts
export interface SeriesGroup {
  name: string;
  cover: string;
  description?: string;
  /** 按日期升序排列——系列是有阅读顺序的，跟博客列表的倒序展示是两回事 */
  posts: BlogPost[];
}

/**
 * 按 frontmatter 的 series 字段对文章分组。
 * 没写 series 的文章不参与分组，仍在博客列表里正常展示，不会“消失”。
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const grouped = new Map<string, BlogPost[]>();

  for (const post of posts) {
    if (!post.series) continue;
    const list = grouped.get(post.series);
    list ? list.push(post) : grouped.set(post.series, [post]);
  }

  return Array.from(grouped.entries())
    .map(([name, seriesPosts]) => {
      const meta = seriesConfig[name];
      const sorted = [...seriesPosts].sort((a, b) => a.date.localeCompare(b.date));
      return {
        name,
        cover: meta?.cover || sorted[0].coverImage,
        description: meta?.description,
        posts: sorted,
      };
    })
    .sort((a, b) => {
      const orderA = seriesConfig[a.name]?.order ?? Number.MAX_SAFE_INTEGER;
      const orderB = seriesConfig[b.name]?.order ?? Number.MAX_SAFE_INTEGER;
      return orderA - orderB || a.name.localeCompare(b.name, 'zh-CN');
    });
}
```

const filteredPosts = activeSeriesGroup
  ? activeSeriesGroup.posts.filter(
      (post) =>

## 图片放置

系列封面走的是跟文章封面同一套机制（`resolveAssetPath` 补 `BASE_URL`），也就是需要放在被静态托管的目录下，与现有 `covers/x.svg` 保持同一约定，即 `app/public/covers/series/ai-transform.svg`。这是基于现有 `resolveCover` 用法推断出的目录结构——如果你实际的静态资源目录不是 `public/`，把 `series.ts` 里的相对路径对应改一下即可，`resolveAssetPath` 的逻辑不用动。

新增系列时只需两步：往 `data/series.ts` 加一条配置 + 把封面图放进对应目录；文章那边只需在 frontmatter 加一行 `series: 系列名`，无需改代码。
