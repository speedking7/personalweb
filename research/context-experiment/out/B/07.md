### 2. `app/src/lib/markdown.ts` — 解析 `series:` frontmatter

在 `category` 解析那行下面加一段,写法完全照抄现有 pattern:

```ts
const seriesMatch = frontmatter.match(/series:\s*["']?([^"'\n]+)["']?/);
if (seriesMatch) metadata.series = seriesMatch[1].trim();
```

不给默认值——没写就是 `undefined`,代表"不属于任何系列",不像 `category`/`tags` 那样需要兜底成 `'未分类'`/`[]`。

frontmatter 用法示例(给内容作者看):

```yaml
---
title: "从 Prompt 到 Agent"
category: "技术"
series: "AI 转型指南"
date: "2026-08-01"
---
```

### 4. `app/src/lib/assets.ts` — 新建,把 `blogs.ts` 里的 `resolveCover` 提出来复用

系列封面和文章封面要走同一套「本地相对路径 → 补 `BASE_URL`」逻辑,不提出来的话 `data/series.ts` 会抄一份一模一样的正则,以后改一处漏改一处。

```ts
/**
 * [INPUT]: 无外部依赖,读取 import.meta.env.BASE_URL
 * [OUTPUT]: 对外提供 resolveLocalAsset —— 把本地相对路径补全为带部署 base 的可用 URL
 * [POS]: lib/ 层的资源路径解析器,被 data/blogs 与 data/series 共用。
 *        本地素材(文章封面、系列封面)在源码里只写相对路径,部署目标是 GitHub Pages
 *        这类带子路径的环境,缺这一步本地能看见、上线就是 404
 * [PROTOCOL]: 变更时更新此头部,然后检查 CLAUDE.md
 */
export const resolveLocalAsset = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

### 6. `app/src/data/series.ts` — 新建,系列封面配置 + 分组函数

系列没有独立的 content 文件,只是文章 frontmatter 里的一个字符串字段,封面因此需要一处集中登记,不然每篇文章各写一份互相打架。

```ts
/**
 * [INPUT]: 依赖 @/lib/assets 的 resolveLocalAsset 补全部署 base 前缀,
 *           依赖 @/types/blog 的 BlogPost 契约
 * [OUTPUT]: 对外提供 seriesCovers 封面配置、getSeriesCover 查询、
 *           groupPostsBySeries 分组函数
 * [POS]: data/ 层的系列元信息。系列本身没有独立 content 文件,只是文章
 *        frontmatter 里的 series 字段;封面因此在此集中登记一次,而不是让
 *        每篇文章各写一份、互相打架。未登记封面的系列不报错,回退到该系列内
 *        最新一篇文章的封面——同样是"真兜底",不是占位图
 * [PROTOCOL]: 变更时更新此头部,然后检查 CLAUDE.md
 */
import { resolveLocalAsset } from '@/lib/assets';
import type { BlogPost } from '@/types/blog';

// 系列名 -> 封面图相对路径。图片放进 public/series-covers/,
// 与文章封面(public/covers/)同一约定,同一套 BASE_URL 解析。
// 新增系列 = 把图放进 public/series-covers/,在这里加一行。
const seriesCoverPaths: Record<string, string> = {
  // 'AI 转型指南': 'series-covers/ai-transformation.svg',
};

export const seriesCovers: Record<string, string> = Object.fromEntries(
  Object.entries(seriesCoverPaths).map(([name, path]) => [name, resolveLocalAsset(path)])
);

export interface SeriesGroup {
  name: string;
  cover: string;
  posts: BlogPost[];
}

/** 未登记封面时,用组内最新一篇文章的封面兜底,而不是显示占位图 */
export function getSeriesCover(seriesName: string, fallback = ''): string {
  return seriesCovers[seriesName] || fallback;
}

/** 按 series 字段分组;没有该字段的文章不参与分组,留在普通列表里 */
export function groupPostsBySeries(posts: BlogPost[]): SeriesGroup[] {
  const groups = new Map<string, BlogPost[]>();
  posts.forEach((post) => {
    if (!post.series) return;
    const list = groups.get(post.series) ?? [];
    list.push(post);
    groups.set(post.series, list);
  });

  return Array.from(groups.entries())
    .map(([name, seriesPosts]) => {
      const sorted = [...seriesPosts].sort((a, b) => b.date.localeCompare(a.date));
      return { name, cover: getSeriesCover(name, sorted[0]?.coverImage), posts: sorted };
    })
    .sort((a, b) => b.posts[0].date.localeCompare(a.posts[0].date));
}
```

封面图片实际放在 **`app/public/series-covers/`** 目录下(新建),`series-covers/xxx.svg` 这种相对路径就是给 `seriesCoverPaths` 用的。

```ts

  const matchesCategory =
    activeCategory === '全部' || post.category === activeCategory;
```

**在「Header」和「grid lg:grid-cols-3」之间插入系列卡片区**(仅在有系列数据时渲染):

```tsx
        >

            <img
              src={group.cover}
              alt={group.name}
```
