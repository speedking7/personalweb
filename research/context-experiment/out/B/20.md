# 系列文章功能实现方案

核心思路：`series` 只是文章 frontmatter 里的一个分组标签，分组关系从文章自己推导出来；封面这类"分组本身"的元数据，单独放一个轻量配置文件按系列名匹配，不与文章耦合。一共改 5 个已有文件 + 新增 2 个文件。

## 1. `app/src/types/blog.ts` —— 加字段

```ts

  id: string;
  title: string;
  excerpt: string;
  content: string;
  coverImage: string;
  category: string;
  tags: string[];
  date: string;
  readTime: number;
  series?: string;   // 新增，可选——非系列文章不填
}
```

## 2. `app/src/lib/markdown.ts` —— frontmatter 解析加一行

在 `categoryMatch` 那段旁边加：

```ts
const seriesMatch = frontmatter.match(/series:\s*["']?([^"'\n]+)["']?/);
if (seriesMatch) metadata.series = seriesMatch[1].trim();
```

飞书文档和本地 `.md` 共用这一个解析器，两条数据源自动同时支持。

## 3. `app/src/lib/utils.ts` —— 抽出封面路径解析

`blogs.ts` 里已有一个内联的 `resolveCover`（本地相对路径补 `BASE_URL` 前缀），系列封面要复用同一规则，所以提成共享函数：

```ts
export function resolveAssetPath(path: string): string {
  if (!path || /^(https?:)?\/\//.test(path) || path.startsWith('/')) {
    return path;
  }
  return `${import.meta.env.BASE_URL}${path}`;
}
```

## 4. `app/src/data/series.ts` —— 新增文件，系列的专属元数据

```ts
/**
 * [INPUT]: 无外部依赖
 * [OUTPUT]: 对外提供 SeriesMeta 类型与 seriesMeta 配置数组
 * [POS]: data/ 层的系列元数据。系列的分组关系来自文章 frontmatter 的 series 字段，
 *        这里只补充分组之外的展示信息——封面与简介，用 name 与 frontmatter 的 series 值精确匹配。
 *        未在此登记的系列依旧会正常分组显示，只是没有专属封面，退化用系列内最新文章的封面代替
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
export interface SeriesMeta {
  /** 需与文章 frontmatter 里 series 字段的值完全一致 */
  name: string;
  /** 相对 public/ 目录的路径，如 series-covers/xxx.svg */
  cover: string;
  description?: string;
}

export const seriesMeta: SeriesMeta[] = [
  // { name: 'AI 转型指南', cover: 'series-covers/ai-transformation.svg', description: '从传统开发者到 AI 时代从业者的转型笔记' },
];
```

图片放法：把封面图丢进 `app/public/series-covers/xxx.svg`（新建目录），跟现有文章封面 `covers/xxx.svg` 是同一套约定——都在 `public/` 下，都是相对路径，构建时自动补 GitHub Pages 的 `/personalweb/` 前缀。

## 5. `app/src/data/blogs.ts`

替换局部 `resolveCover` 定义为导入，并新增 `getSeriesGroups`：

删掉原来那段内联的 `const resolveCover = (cover: string) => ...`，其余用到 `resolveCover(...)` 的地方不用改。

在文件末尾（`searchPosts` 之后、`clearCache` 之前）新增：

```ts
export interface SeriesGroup {
  name: string;
  cover: string;
  description?: string;
  posts: BlogPost[];
}

/**
 * 按 frontmatter 的 series 字段分组。
 * 系列内按日期升序（阅读顺序）；系列之间按各自最新一篇的日期降序。
 * 封面优先取 seriesMeta 里登记的专属封面，未登记则退化为系列内最新文章的封面——不留空白占位。
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const groups = new Map<string, BlogPost[]>();

  for (const post of posts) {
    if (!post.series) continue;
    const list = groups.get(post.series) ?? [];
    list.push(post);
    groups.set(post.series, list);
  }

  return Array.from(groups.entries())
    .map(([name, seriesPosts]) => {
      const sorted = [...seriesPosts].sort((a, b) => a.date.localeCompare(b.date));
      const meta = seriesMeta.find((s) => s.name === name);
      return {
        name,
        cover: meta?.cover ? resolveCover(meta.cover) : sorted[sorted.length - 1].coverImage,
        description: meta?.description,
        posts: sorted,
      };
    })
    .sort((a, b) => {
      const aLatest = a.posts[a.posts.length - 1].date;
      const bLatest = b.posts[b.posts.length - 1].date;
      return bLatest.localeCompare(aLatest);
    });
}
```

## 8. `app/src/pages/BlogDetail.tsx` —— 详情页给出系列上下文（低成本必要项）

只分组不在文章页体现归属，系列会变成"列表页孤立的入口"，读者点进文章后找不到上一篇/下一篇。加一个复用 `getSeriesGroups` 的小组件：

**引入**：

```ts
import { getBlogPost, getBlogPosts, getSeriesGroups, type BlogPost, type SeriesGroup } from '@/data/blogs';
```

**组件**（放在文件底部，与 `RelatedPosts` 平级）：

```tsx
function SeriesNav({ postId, seriesName }: { postId: string; seriesName?: string }) {
  const [group, setGroup] = useState<SeriesGroup | null>(null);

  useEffect(() => {
    if (!seriesName) {
      setGroup(null);
      return;
    }
    getSeriesGroups().then((groups) => {
      setGroup(groups.find((g) => g.name === seriesName) ?? null);
    });
  }, [seriesName]);

  if (!group) return null;

  const index = group.posts.findIndex((p) => p.id === postId);
  const prev = index > 0 ? group.posts[index - 1] : null;
  const next = index < group.posts.length - 1 ? group.posts[index + 1] : null;

  return (
    <div className="bg-white rounded-xl p-6 shadow-sm mb-8">
      <p className="text-sm text-[#9ca3af] mb-3">
        系列 · {group.name}（第 {index + 1} / {group.posts.length} 篇）
      </p>
      <div className="flex items-center justify-between gap-4">
        {prev ? (
          <Link to={`/blog/${prev.id}`} className="text-sm text-[#1a1a1a] hover:underline truncate">
            ← {prev.title}
          </Link>
        ) : <span />}
        {next ? (
          <Link to={`/blog/${next.id}`} className="text-sm text-[#1a1a1a] hover:underline truncate text-right">
            {next.title} →
          </Link>
        ) : <span />}
      </div>
    </div>
  );
}
```

在主渲染里，头部卡片（封面/标题）之后、`<article>` 正文之前插入：

```tsx
<SeriesNav postId={post.id} seriesName={post.series} />
```

## 使用方式

文章 frontmatter 里加一行：

```md
---
title: 从传统开发到 AI 结对编程
category: 技术
series: AI 转型指南
tags: [AI, 效率]
date: 2026-08-01
cover: covers/ai-1.svg
readTime: 6
---
```

系列封面在 `app/src/data/series.ts` 登记一次，图片放到 `app/public/series-covers/`：

```ts
export const seriesMeta: SeriesMeta[] = [
  { name: 'AI 转型指南', cover: 'series-covers/ai-transformation.svg', description: '从传统开发者到 AI 时代从业者的转型笔记' },
];
```

未登记的系列不会报错也不会消失，只是封面退化为系列内最新一篇文章的封面——和现有代码里"宁可用真实兜底、不用假占位"的一贯做法保持一致。
