## 实现方案

系列信息通过 frontmatter 的 `series` 字段隐式定义（同名即同系列），不单独维护系列列表；系列封面用一个独立的映射表管理，与文章数据解耦。改动范围：

| 文件 | 改动 |
|---|---|
| `app/src/types/blog.ts` | `BlogPost` 加 `series?: string` |
| `app/src/lib/markdown.ts` | frontmatter 解析加 `series:` 字段 |
| `app/src/lib/feishu.ts` | 飞书文档拼装 `BlogPost` 时补上 `series` |
| `app/src/data/series.ts`（新建） | 系列名 → 封面图路径的映射 + `getSeriesCover` |
| `app/src/pages/Blog.tsx` | 按 `series` 分组渲染 |
| `app/src/pages/BlogDetail.tsx`（可选） | 详情页显示所属系列 |

---

### 1. `app/src/types/blog.ts`

```ts
export interface BlogPost {
  id: string;
  title: string;
  excerpt: string;
  content: string;
  coverImage: string;
  category: string;
  tags: string[];
  date: string;
  readTime: number;
  /** 系列名称，可选。frontmatter 写 series: 字段，同名文章自动归入同一系列 */
  series?: string;
}
```

---

### 2. `app/src/lib/markdown.ts`

在 `categoryMatch` 之后加一段，和其他字段解析方式保持一致；**不要**给 series 设默认值（不同于 category 的 `未分类` 兜底），否则所有未标记系列的文章会被误归为同一组：

```ts
const categoryMatch = frontmatter.match(/category:\s*["']?([^"'\n]+)["']?/);
if (categoryMatch) metadata.category = categoryMatch[1].trim();

// 新增：可选字段，不写则文章不属于任何系列
const seriesMatch = frontmatter.match(/series:\s*["']?([^"'\n]+)["']?/);
if (seriesMatch) metadata.series = seriesMatch[1].trim();
```

`content/posts/*.md` 的用法示例：

```md
---
title: "从提示词到 Agent：AI 转型第一步"
category: "技术"
series: "AI 转型指南"
date: "2026-01-10"
---
```

本地文章走 `data/blogs.ts` 的 `{ ...parseBlogMetadata(raw, slug) }` 展开，`series` 字段自动带过去，**`blogs.ts` 不需要改**。

---

### 3. `app/src/lib/feishu.ts`

飞书路径是手工拼对象，不是展开 metadata，必须显式补一行，否则飞书来源的文章会丢失 series：

```ts
posts.push({
  id: metadata.id!,
  title: metadata.title || node.title,
  excerpt: metadata.excerpt || '',
  content: metadata.content || content,
  coverImage: metadata.coverImage || this.getDefaultCover(metadata.category),
  category: metadata.category || '未分类',
  tags: metadata.tags || [],
  date: metadata.date || new Date().toISOString().split('T')[0],
  readTime: metadata.readTime || 5,
  series: metadata.series,   // 新增
});
```

### 4. 新建 `app/src/data/series.ts`

沿用 `data/blogs.ts` 里 `resolveCover` 的同一套「相对路径补 BASE_URL」逻辑（GitHub Pages 部署有 `/personalweb/` 前缀，直接写死路径线上会 404）：

```ts
/**
 * [INPUT]: 无外部依赖，仅定义系列封面的静态映射
 * [OUTPUT]: 对外提供 getSeriesCover —— 按系列名取封面图 URL（已补 BASE_URL 前缀）
 * [POS]: data/ 层的系列封面配置，被 pages/Blog 的分组展示消费。
 *        系列本身由文章 frontmatter 里的 series 字段隐式定义，此文件只管
 *        「系列名 -> 封面图」这一件事。新增系列：图片丢进 public/covers/series/，
 *        再在下方 map 里加一行同名映射即可，无需改动其他文件
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */

// key 必须和文章 frontmatter 里的 series 值完全一致（区分大小写、空格）
const seriesCovers: Record<string, string> = {
  'AI 转型指南': 'covers/series/ai-transform.svg',
};

const resolveCover = (cover: string): string =>
  !cover || /^(https?:)?\/\//.test(cover) || cover.startsWith('/')
    ? cover
    : `${import.meta.env.BASE_URL}${cover}`;

/** 未配置封面的系列返回空字符串，调用方据此显示占位样式，而非报错或裂图 */
export function getSeriesCover(seriesName: string): string {
  return resolveCover(seriesCovers[seriesName] ?? '');
}
```

图片实体放 `app/public/covers/series/ai-transform.svg`（和现有本地文章封面 `public/covers/*.svg` 同一目录规则），换系列名直接照抄这一行即可。

### 5. `app/src/pages/Blog.tsx` — 分组渲染

**a) 顶部加 import：**

```tsx
import { getSeriesCover } from '@/data/series';
```

**b) 在 `filteredPosts` 计算之后加分组逻辑：**

```tsx
const filteredPosts = posts.filter((post) => {
  const matchesCategory =
    activeCategory === '全部' || post.category === activeCategory;
  const matchesTag = !activeTag || post.tags.includes(activeTag);
  const matchesSearch =
    !searchQuery ||
    post.title.toLowerCase().includes(searchQuery.toLowerCase()) ||
    post.excerpt.toLowerCase().includes(searchQuery.toLowerCase());
  return matchesCategory && matchesTag && matchesSearch;
});

// 新增：按 series 分组，未标记系列的文章单独归为 ungroupedPosts
const seriesGroups = Array.from(
  filteredPosts.reduce((map, post) => {
    if (!post.series) return map;
    const list = map.get(post.series) ?? [];
    list.push(post);
    map.set(post.series, list);
    return map;
  }, new Map<string, BlogPost[]>())
).map(
  ([name, list]) =>
    [name, [...list].sort((a, b) => a.date.localeCompare(b.date))] as [string, BlogPost[]]
  // 系列内按日期升序：读起来是「第一篇 -> 最新一篇」的顺序，而非全站默认的倒序
);

const ungroupedPosts = filteredPosts.filter((post) => !post.series);
```

**c) 把原来「Posts List」整块替换为分组渲染，同时把原来 `<Link>` 卡片抽成组件复用：**

原代码：
```tsx
{!loading && !error && (
  <div className="space-y-4">
    {filteredPosts.map((post) => (
      <Link key={post.id} to={`/blog/${post.id}`} ...> ... </Link>
    ))}
  </div>
)}
```

替换为：
```tsx
{!loading && !error && (
  <div className="space-y-10">
    {seriesGroups.map(([seriesName, seriesPosts]) => {
      const cover = getSeriesCover(seriesName) || seriesPosts[0]?.coverImage || '';
      return (
        <div key={seriesName}>
          <div className="flex items-center gap-4 mb-4 bg-white rounded-xl p-4 shadow-sm">
            {cover && (
              <img
                src={cover}
                alt={seriesName}
                className="w-16 h-16 rounded-lg object-cover shrink-0"
              />
            )}
            <div>
              <h2 className="text-lg font-medium text-[#1a1a1a]">{seriesName}</h2>
              <p className="text-[#9ca3af] text-sm">系列 · 共 {seriesPosts.length} 篇</p>
            </div>
          </div>
          <div className="space-y-4">
            {seriesPosts.map((post) => (
              <BlogPostCard key={post.id} post={post} />
            ))}
          </div>
        </div>
      );
    })}

    {ungroupedPosts.length > 0 && (
      <div>
        {seriesGroups.length > 0 && (
          <h2 className="text-lg font-medium text-[#1a1a1a] mb-4">全部文章</h2>
        )}
        <div className="space-y-4">
          {ungroupedPosts.map((post) => (
            <BlogPostCard key={post.id} post={post} />
          ))}
        </div>
      </div>
    )}
  </div>
)}
```

**d) 在文件底部（`Blog` 函数外）新增 `BlogPostCard`，内容就是原来那段 `<Link>` 卡片 JSX 原样搬过去：**

```tsx
function BlogPostCard({ post }: { post: BlogPost }) {
  return (
    <Link
      to={`/blog/${post.id}`}
      className="group block bg-white rounded-xl overflow-hidden shadow-sm hover:shadow-lg transition-all duration-300"
    >
      <div className="md:flex">
        {post.coverImage && (
          <div className="md:w-1/3 aspect-video md:aspect-auto overflow-hidden">
            <img
              src={post.coverImage}
              alt={post.title}
              className="w-full h-full object-cover group-hover:scale-105 transition-transform duration-300"
            />
          </div>
        )}
        <div className="md:w-2/3 p-6">
          <div className="flex items-center gap-3 mb-3">
            <span className="px-2 py-1 bg-[#f0f0f0] text-[#4a4a4a] text-xs font-medium rounded-full">
              {post.category}
            </span>
            <span className="flex items-center gap-1 text-[#9ca3af] text-xs">
              <Calendar className="w-3 h-3" />
              {post.date}
            </span>
            <span className="flex items-center gap-1 text-[#9ca3af] text-xs">
              <Clock className="w-3 h-3" />
              {post.readTime} 分钟
            </span>
          </div>
          <h2 className="text-xl font-medium text-[#1a1a1a] mb-2 group-hover:text-[#6b6b6b] transition-colors">
            {post.title}
          </h2>
          <p className="text-[#6b6b6b] text-sm mb-4 line-clamp-2">
            {post.excerpt}
          </p>
          <div className="flex flex-wrap gap-2">
            {post.tags.map((tag: string) => (
              <span
                key={tag}
                className="flex items-center gap-1 px-2 py-1 bg-[#f0f0f0] text-[#6b6b6b] text-xs rounded-full"
              >
                <Tag className="w-3 h-3" />
                {tag}
              </span>
            ))}
          </div>
        </div>
      </div>
    </Link>
  );
}
```

`filteredPosts.length === 0` 的空状态判断不用动，逻辑基础没变。分组是基于已过滤结果算的，所以搜索 / 分类 / 标签筛选和系列分组是叠加生效的——筛出来的结果里有系列就分组显示，没有就还是原来的平铺列表。

### 落地步骤

1. 建 `app/public/covers/series/` 目录，放系列封面图。
2. 挑几篇文章的 frontmatter 加 `series: 系列名`。
3. `app/src/data/series.ts` 里补上「系列名 → 图片路径」映射。
4. 跑 `npm run dev` 看 `/blog` 页面是否按系列分组、封面图是否正常加载（尤其注意 GitHub Pages 部署后 BASE_URL 前缀有没有生效）。
