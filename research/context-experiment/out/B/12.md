## 实现方案

系列功能贯穿三层：**类型定义 → 解析/数据聚合 → 列表页展示**。核心思路是「系列归属」用文章 frontmatter 的自由文本字段表达，「系列元信息（封面/简介）」单独用一个配置文件维护，两者靠系列名字符串对齐——这样不用改动 `BlogPost` 之外的数据结构，也不用给每篇文章都填封面路径。

### 1. `app/src/types/blog.ts` — 加字段

```ts
export interface BlogPost {
  id: string;
  title: string;
  excerpt: string;
  content: string;
  coverImage: string;
  category: string;
  tags: string[];
  date: string;
  readTime: number;
  series?: string; // 系列名，需与 data/series.ts 中的配置项完全一致
}
```

### 2. `app/src/lib/markdown.ts` — 解析 frontmatter 的 `series`

在 `categoryMatch` 附近加一行：

```ts
const seriesMatch = frontmatter.match(/series:\s*["']?([^"'\n]+)["']?/);
if (seriesMatch) metadata.series = seriesMatch[1].trim();
```

文件头注释补一句说明（该文件遵循项目里 `[INPUT]/[OUTPUT]/[POS]` 的头部协议，改动后要同步更新）：

```ts
/**
 * [INPUT]: 依赖 @/types/blog 的 BlogPost 契约
 * [OUTPUT]: 对外提供 parseBlogMetadata —— 把带 YAML frontmatter 的 markdown 解析为 BlogPost 字段
 * [POS]: lib/ 层的格式解析器，是飞书文档与本地 md 文件的共同入口。
 *        两个数据源必须共用它，否则元数据规则会各自漂移，同一篇文章在两条链路上解析出不同结果。
 *        series 是自由文本，未做校验——拼错系列名的后果是文章「静默掉出」该系列，而不是报错
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
```

### 3. `app/src/lib/feishu.ts` — 飞书数据源透传 `series`

`fetchBlogPosts()` 里手工构造 `BlogPost` 的地方（本地文章走 spread 会自动带上，飞书这里是显式字段，必须补一行）：

```ts
posts.push({
  id: metadata.id!,
  title: metadata.title || node.title,
  excerpt: metadata.excerpt || '',
  content: metadata.content || content,
  coverImage: metadata.coverImage || this.getDefaultCover(metadata.category),
  category: metadata.category || '未分类',
  tags: metadata.tags || [],
  date: metadata.date || new Date().toISOString().split('T')[0],
  readTime: metadata.readTime || 5,
  series: metadata.series, // 新增
});
```

### 4. 新建 `app/src/lib/paths.ts` — 抽出资源路径解析

原本 `data/blogs.ts` 里给封面图补部署前缀的逻辑是私有的，系列封面也要复用同一套规则（GitHub Pages 部署会多一层 `/personalweb/` 前缀），所以抽成公共工具：

```ts
/**
 * [INPUT]: 无外部依赖，读取 import.meta.env.BASE_URL
 * [OUTPUT]: 对外提供 resolveAssetPath —— 把本地相对路径的静态资源补上部署 base
 * [POS]: lib/ 层的路径工具，从 data/blogs 抽出以便 data/series 复用；
 *        绝对 URL（http/https）与以 / 开头的路径原样返回，避免被部署前缀污染
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

### 5. 新建 `app/src/data/series.ts` — 系列元信息配置

```ts
/**
 * [INPUT]: 依赖 @/lib/paths 的 resolveAssetPath 补全部署 base
 * [OUTPUT]: 对外提供 SeriesMeta 类型与 seriesMetaMap —— 系列名到封面图/简介的映射
 * [POS]: data/ 层的系列元数据配置，被 data/blogs 消费用于聚合系列分组。
 *        系列的归属关系由文章 frontmatter 的 series 字段决定（自由文本），
 *        此文件只补充封面图与简介这类「系列本身」的信息，不重复维护文章列表
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { resolveAssetPath } from '@/lib/paths';

export interface SeriesMeta {
  /** 系列名称，需与文章 frontmatter 中的 series 字段完全一致 */
  name: string;
  /** 封面图，本地相对路径（相对 public/），如 covers/series/ai.svg */
  cover: string;
  description?: string;
}

// 新增系列 = 在此追加一项，图片放到 public/covers/series/ 下
const seriesConfig: SeriesMeta[] = [
  // {
  //   name: 'AI 转型指南',
  //   cover: 'covers/series/ai-transform.svg',
  //   description: '从写提示词到搭建工作流的实践笔记',
  // },
];

export const seriesMetaMap: Map<string, SeriesMeta> = new Map(
  seriesConfig.map((s) => [s.name, { ...s, cover: resolveAssetPath(s.cover) }])
);
```

封面图片实际放在 `app/public/covers/series/*.svg|jpg|png`，走 Vite `public/` 目录的静态资源约定，和本地文章封面同一套规则。

### 6. `app/src/data/blogs.ts` — 复用 `resolveAssetPath` + 新增 `getSeriesGroups`

替换原来私有的 `resolveCover`：

```ts
import { feishuBlogClient } from '@/lib/feishu';
import { parseBlogMetadata } from '@/lib/markdown';
import { resolveAssetPath } from '@/lib/paths';
import { seriesMetaMap } from './series';
import type { BlogPost } from '@/types/blog';

// ...

const staticBlogPosts: BlogPost[] = Object.entries(localPostModules)
  .map(([path, raw]) => {
    const slug = path.split('/').pop()!.replace(/\.md$/, '');
    const post = { title: slug, excerpt: '', coverImage: '', ...parseBlogMetadata(raw, slug) } as BlogPost;
    return { ...post, coverImage: resolveAssetPath(post.coverImage) }; // 改这一行
  })
  .sort((a, b) => b.date.localeCompare(a.date));
```

文件末尾（`clearCache` 之前或之后均可）新增分组聚合：

```ts
export interface SeriesGroup {
  name: string;
  cover?: string;
  description?: string;
  posts: BlogPost[];
}

/**
 * 按系列分组博客文章
 * 系列封面/简介来自 data/series.ts 的配置，文章归属由 frontmatter 的 series 字段决定
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const grouped = new Map<string, BlogPost[]>();

  posts.forEach((post) => {
    if (!post.series) return;
    const group = grouped.get(post.series) ?? [];
    group.push(post);
    grouped.set(post.series, group);
  });

  return Array.from(grouped.entries()).map(([name, seriesPosts]) => {
    const meta = seriesMetaMap.get(name);
    return {
      name,
      cover: meta?.cover,
      description: meta?.description,
      posts: seriesPosts.sort((a, b) => a.date.localeCompare(b.date)), // 系列内按时间正序，体现「第几篇」
    };
  });
}
```

头部注释同步补充（`[INPUT]`/`[OUTPUT]`/`[POS]` 都有变化）：

```ts
/**
 * [INPUT]: 依赖 @/lib/feishu 的 feishuBlogClient 取远端数据，@/lib/markdown 的 parseBlogMetadata
 *           解析 frontmatter，@/lib/paths 的 resolveAssetPath 补全部署 base，@/data/series 的
 *           seriesMetaMap 提供系列封面/简介，@/types/blog 的 BlogPost 契约；构建期 glob 内联 content/posts/*.md
 * [OUTPUT]: 对外提供 getBlogPosts/getBlogPost 读取、getCategories/getTags/getSeriesGroups 聚合、
 *           getPostsByCategory/getPostsByTag/searchPosts 筛选、setDataSourceMode 与 clearCache 控制
 * [POS]: data/ 层的博客数据唯一入口，横在 pages/Blog·BlogDetail·Home 与两个数据源之间。
 *        持有 feishu/static/auto 三态降级决策；系列（series）是文章间的弱关联，
 *        归属靠 frontmatter 自由文本对齐 data/series 的配置名，拼写不一致会导致文章「掉出」系列而非报错
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
```

### 7. `app/src/pages/Blog.tsx` — 列表页按系列分组展示

在原有 state 基础上加系列状态和数据获取：

```tsx
import { getBlogPosts, getCategories, getTags, getSeriesGroups, type BlogPost, type SeriesGroup } from '@/data/blogs';

export function Blog() {
  const [posts, setPosts] = useState<BlogPost[]>([]);
  const [categories, setCategories] = useState<string[]>(['全部']);
  const [tags, setTags] = useState<string[]>([]);
  const [seriesGroups, setSeriesGroups] = useState<SeriesGroup[]>([]); // 新增
  const [activeCategory, setActiveCategory] = useState('全部');
  const [activeTag, setActiveTag] = useState<string | null>(null);
  const [activeSeries, setActiveSeries] = useState<string | null>(null); // 新增
  const [searchQuery, setSearchQuery] = useState('');
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    window.scrollTo(0, 0);

    async function loadBlogData() {
      try {
        setLoading(true);
        const [loadedPosts, loadedCategories, loadedTags, loadedSeries] = await Promise.all([
          getBlogPosts(),
          getCategories(),
          getTags(),
          getSeriesGroups(), // 新增
        ]);
        setPosts(loadedPosts);
        setCategories(loadedCategories);
        setTags(loadedTags);
        setSeriesGroups(loadedSeries); // 新增
        setError(null);
      } catch (err) {
        console.error('Failed to load blog data:', err);
        setError('加载博客失败，请稍后重试');
      } finally {
        setLoading(false);
      }
    }

    loadBlogData();
  }, []);
```

过滤逻辑加一个 AND 条件（和现有 category/tag 过滤同一套写法）：

```tsx
  const filteredPosts = posts.filter((post) => {
    const matchesCategory =
      activeCategory === '全部' || post.category === activeCategory;
    const matchesTag = !activeTag || post.tags.includes(activeTag);
    const matchesSeries = !activeSeries || post.series === activeSeries; // 新增
    const matchesSearch =
      !searchQuery ||
      post.title.toLowerCase().includes(searchQuery.toLowerCase()) ||
      post.excerpt.toLowerCase().includes(searchQuery.toLowerCase());
    return matchesCategory && matchesTag && matchesSeries && matchesSearch;
  });
```

在「搜索 & 分类过滤」卡片之后、Loading 状态之前插入「系列专栏」区块（有封面卡片，点击即筛选，再点一次取消）：

```tsx
{seriesGroups.length > 0 && (

    <h3 className="font-medium text-[#1a1a1a] mb-3">系列专栏</h3>
    <div className="grid sm:grid-cols-2 gap-3">
      {seriesGroups.map((series) => (
        <button
          key={series.name}

            setActiveSeries(activeSeries === series.name ? null : series.name)

            activeSeries === series.name

              : 'border-[#e5e5e5] hover:border-[#c5c5c5]'
          }`}
        >
          {series.cover && (
            <div className="aspect-[16/9] overflow-hidden bg-[#f0f0f0]">
              <img
                src={series.cover}
                alt={series.name}
                className="w-full h-full object-cover group-hover:scale-105 transition-transform"
              />

          )}
          <div className="p-3">
            <p className="font-medium text-[#1a1a1a] text-sm">{series.name}</p>
            <p className="text-[#9ca3af] text-xs mt-1">{series.posts.length} 篇</p>
          </div>
        </button>
      ))}
    </div>
  </div>
)}
```
