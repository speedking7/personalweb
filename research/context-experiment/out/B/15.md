## 实现方案

核心思路：`series` 只是 frontmatter 里的自由文本字段，无法从中派生出"系列封面图"这种额外元数据，所以新增一张独立配置表（系列名 → 封面/简介），文章通过 `series` 字段与之关联，这与项目里 `giscus.ts`、`blogs.ts` 的"数据 vs 配置分离"风格是一致的。封面图沿用现有的 `resolveCover` 本地相对路径约定（相对 `public/`，构建时补 `BASE_URL` 前缀），所以顺手把这个函数提到共享的 `lib/assets.ts`，供文章封面和系列封面共用一份逻辑。

### 3. `app/src/lib/assets.ts`（新建）

从 `blogs.ts` 里把 `resolveCover` 抽出来，改名 `resolveAssetPath`，因为系列封面和文章封面要共用同一份"本地相对路径 → 部署 URL"的规则：

```ts
/**
 * [INPUT]: 依赖 import.meta.env.BASE_URL
 * [OUTPUT]: 对外提供 resolveAssetPath —— 给本地相对路径补上部署 base
 * [POS]: lib/ 层的路径解析工具，被 data/blogs 与 data/series 共用。
 *        两处都要把 frontmatter/配置里写的本地相对路径转成可用 URL，
 *        逻辑必须只有一份，否则 GitHub Pages 的 /personalweb/ 前缀迟早会漏加
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */

/** 绝对 URL 与以 / 开头的路径原样返回；其余视为相对 public/ 的本地路径，补上部署 base */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

### 4. `app/src/data/series.ts`（新建）

```ts
/**
 * [INPUT]: 依赖 @/lib/assets 的 resolveAssetPath 解析本地封面路径
 * [OUTPUT]: 对外提供 SeriesInfo 类型与 seriesList 系列元数据数组
 * [POS]: data/ 层的系列配置，被 data/blogs 的 groupPostsBySeries 消费。
 *        系列名是文章 frontmatter 里的自由文本，封面图只能靠人工维护对应关系，
 *        所以单独开一张表，而不是让每篇同系列文章重复填写同一张封面
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { resolveAssetPath } from '@/lib/assets';

export interface SeriesInfo {
  /** 系列名称，须与文章 frontmatter 中的 series 字段完全一致 */
  name: string;
  /** 封面图，本地相对路径（相对于 public/），如 'covers/series/ai-transform.svg' */
  cover: string;
  description?: string;
}

const rawSeriesList: SeriesInfo[] = [
  // 新增系列时在此追加一条，封面图放到 public/covers/series/ 下，例如：
  // { name: 'AI 转型指南', cover: 'covers/series/ai-transform.svg', description: '从认知到落地的转型笔记' },
];

export const seriesList: SeriesInfo[] = rawSeriesList.map((s) => ({
  ...s,
  cover: resolveAssetPath(s.cover),
}));
```

在 `searchPosts` 之后（`clearCache` 之前）新增分组函数：

```ts
export interface SeriesGroup {
  name: string;
  cover: string;
  description?: string;
  posts: BlogPost[];
}

/**
 * 按 series 字段分组。未填 series 的文章不进入任何分组，
 * 由调用方（Blog 列表页）决定如何和未分组文章并列展示。
 */
export function groupPostsBySeries(posts: BlogPost[]): SeriesGroup[] {
  const bySeries = new Map<string, BlogPost[]>();
  posts.forEach((post) => {
    if (!post.series) return;
    const list = bySeries.get(post.series) ?? [];
    list.push(post);
    bySeries.set(post.series, list);
  });

  return Array.from(bySeries.entries()).map(([name, seriesPosts]) => {
    const registered = seriesList.find((s) => s.name === name);
    return {
      name,
      // 系列未在 data/series.ts 登记封面时，退化用该系列第一篇文章的封面，避免空白
      cover: registered?.cover || seriesPosts[0].coverImage,
      description: registered?.description,
      posts: seriesPosts,
    };
  });
}
```

### 使用方式

1. 文章 frontmatter 加一行：`series: AI 转型指南`
2. 把该系列封面图放到 `app/public/covers/series/ai-transform.svg`
3. 在 `src/data/series.ts` 的 `rawSeriesList` 里登记一条 `{ name: 'AI 转型指南', cover: 'covers/series/ai-transform.svg' }`

如果某系列一时没登记封面，`groupPostsBySeries` 会退化用该系列第一篇文章的封面兜底，不会出现空白卡片。
