**`app/src/lib/assets.ts`**（新建，从 blogs.ts 里搬出来的逻辑，一字不改）

```ts
/**
 * [INPUT]: 依赖 import.meta.env.BASE_URL（Vite 注入的部署前缀）
 * [OUTPUT]: 对外提供 resolveLocalAsset —— 把配置/frontmatter 里的本地相对路径转成部署期可用 URL
 * [POS]: lib/ 层的路径解析器，被 data/blogs.ts（文章封面）与 data/series.ts（系列封面）共用。
 *        此前这段逻辑私藏在 blogs.ts 内部，系列封面一上线就得抄一份——这里掐掉这个重复
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */

// 绝对 URL 与以 / 开头的路径原样返回：飞书图片是完整 URL，绝不能被前缀污染
export function resolveLocalAsset(path: string): string {
  if (!path || /^(https?:)?\/\//.test(path) || path.startsWith('/')) {
    return path;
  }
  return `${import.meta.env.BASE_URL}${path}`;
}
```

**`app/src/data/series.ts`**（新建）

系列封面为什么不塞进某篇文章的 frontmatter，而单开注册表？因为封面是"系列"的属性，不是"文章"的属性——一对多关系。塞进文章里，谁先发布谁定义封面，后面改了图还得回头改历史文章的 frontmatter，这是要出漂移的设计。

```ts
/**
 * [INPUT]: 依赖 @/lib/assets 的 resolveLocalAsset，@/types/blog 的 BlogPost 契约
 * [OUTPUT]: 对外提供 getSeriesMeta、groupPostsBySeries、SeriesMeta/SeriesGroup 类型
 * [POS]: data/ 层的系列元数据入口，与 blogs.ts 并列而非从属。
 *        系列封面是系列本身的属性，不是某篇文章的属性——挂在某篇文章的 frontmatter 上，
 *        会让"一对多"关系退化成"谁先发布谁定义封面"的偶然结果
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { resolveLocalAsset } from '@/lib/assets';
import type { BlogPost } from '@/types/blog';

export interface SeriesMeta {
  name: string;
  cover: string;
  description?: string;
}

// 系列封面手工登记表：新增系列 = 加一行 + 把封面图丢进 public/series-covers/
// 未登记的系列不给默认图掩盖——那和"数据源已死"一样，会在页面上和"一切正常"长得一模一样
const SERIES_REGISTRY: Record<string, Omit<SeriesMeta, 'name'>> = {
  'AI 转型指南': {
    cover: 'series-covers/ai-transformation.svg',
    description: '从工具使用者到系统设计者的转型笔记',
  },
};

export function getSeriesMeta(name: string): SeriesMeta | undefined {
  const entry = SERIES_REGISTRY[name];
  if (!entry) return undefined;
  return { name, cover: resolveLocalAsset(entry.cover), description: entry.description };
}

export interface SeriesGroup {
  meta: SeriesMeta | undefined; // undefined = 系列未登记封面，调用方必须显式处理
  posts: BlogPost[];
}

/**
 * 按 series 字段分组，无 series 的文章归入 standalone。
 * 分组顺序 = 各系列最新一篇文章在 posts 中的出现顺序（posts 传入前已按日期倒序）
 */
export function groupPostsBySeries(posts: BlogPost[]): {
  series: SeriesGroup[];
  standalone: BlogPost[];
} {
  const order: string[] = [];
  const buckets = new Map<string, BlogPost[]>();
  const standalone: BlogPost[] = [];

  for (const post of posts) {
    if (!post.series) {
      standalone.push(post);
      continue;
    }
    if (!buckets.has(post.series)) {
      buckets.set(post.series, []);
      order.push(post.series);
    }
    buckets.get(post.series)!.push(post);
  }

  const series = order.map(name => ({ meta: getSeriesMeta(name), posts: buckets.get(name)! }));
  return { series, standalone };
}
```

## 2. 品味自检

- **`resolveLocalAsset` 提取**：不提取的话，`series.ts` 要处理封面路径就得抄一遍 blogs.ts 里的正则和判断逻辑，两处维护，迟早漂移。DRY 不是口号，这是提前掐掉一个必然出现的重复。
- **系列注册表独立于 frontmatter**：一对多关系放对了位置。封面改一次全系列生效，不用回改历史文章。
- **未登记系列显式占位**：延续你项目里"auto 降级必须是真兜底，不能是假数据"的原则——这里对应到"没配置就显式说没配置"，不给默认图蒙混过去。
- **筛选态退化为平铺**：没有强行把系列分组套到所有场景，避免为了"功能完整"而在用户实际不需要的地方增加认知负担。
