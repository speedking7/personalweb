老杨来了。系列文章这个需求不复杂，但你的项目里有个我必须先点破的架构决定：**系列封面不该塞进文章 frontmatter**——一个系列十篇文章，封面写十遍，改一次封面要动十个文件，这是最典型的"数据泥团"。封面该是系列级的元数据，独立登记，文章只需声明"我属于哪个系列"。方案照这个思路来。

## 1. 核心实现

### 1.1 `app/src/types/blog.ts` — 加一个可选字段

```typescript
export interface BlogPost {
  id: string;
  title: string;
  excerpt: string;
  content: string;
  coverImage: string;
  category: string;
  tags: string[];
  date: string;
  readTime: number;
  series?: string;   // 新增：系列名。不填即视为零散文章，不给默认值
}
```

不给 `series` 设默认值——`category` 缺省会归到"未分类"是因为分类需要穷举展示，但系列不是，没系列的文章就该是零散文章，不该被伪造进某个"未分类系列"。

### 1.2 `app/src/lib/markdown.ts` — frontmatter 新增一个字段解析

在 `categoryMatch` 那段旁边加一行，其余不动：

```typescript
const seriesMatch = frontmatter.match(/series:\s*["']?([^"'\n]+)["']?/);
if (seriesMatch) metadata.series = seriesMatch[1].trim();
```

这一处改完，飞书和本地两条链路自动都获得系列解析能力——因为两源共用这一个函数，这正是你在 CLAUDE.md 里写下的架构约束的意义所在。

### 1.3 新建 `app/src/lib/assetPath.ts` — 抽出 resolveCover 的公共逻辑

`blogs.ts` 里已经有一份"相对路径补 BASE_URL"的逻辑，系列封面要复用同一条规则，不能抄一份。抽出来：

```typescript
/**
 * [INPUT]: 无外部依赖
 * [OUTPUT]: 对外提供 resolveAssetPath —— 为 public/ 下的相对路径资源补上部署 base
 * [POS]: lib/ 层的唯一路径解析器，被 data/blogs.ts 与 config/series.ts 共用。
 *        绝对 URL 与以 / 开头的路径原样返回，避免飞书返回的完整 URL 被前缀污染
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
export function resolveAssetPath(path: string): string {
  return !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
}
```

文件末尾（`clearCache` 之后）新增分组能力：

```typescript
export interface SeriesGroup {
  name: string;
  cover: string;
  posts: BlogPost[];
}

/**
 * 按系列分组博客文章。无 series 字段的文章不进入任何分组
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const groups = new Map<string, BlogPost[]>();

  posts.forEach(post => {
    if (!post.series) return;
    const list = groups.get(post.series) ?? [];
    list.push(post);
    groups.set(post.series, list);
  });

  return Array.from(groups.entries())
    .map(([name, seriesPosts]) => ({
      name,
      cover: getSeriesCover(name, seriesPosts[0].coverImage),
      posts: seriesPosts.sort((a, b) => b.date.localeCompare(a.date)),
    }))
    .sort((a, b) => getSeriesOrder(a.name) - getSeriesOrder(b.name));
}

/**
 * 未归入任何系列的文章，供列表页常规区域渲染，避免与系列区重复展示
 */
export async function getStandalonePosts(): Promise<BlogPost[]> {
  const posts = await getBlogPosts();
  return posts.filter(post => !post.series);
}
```

### 1.5 新建 `app/src/config/series.ts` — 系列封面唯一登记表

和 `giscus.ts` 同一种模式：一个手工填写点。

```typescript
/**
 * [INPUT]: 依赖 @/lib/assetPath 的 resolveAssetPath
 * [OUTPUT]: 对外提供 SERIES_CONFIG 登记表、getSeriesCover/getSeriesOrder 存取函数
 * [POS]: config/ 层的系列元数据唯一填写位。文章 frontmatter 只声明系列名（外键），
 *        封面与排序集中在此，避免同一系列的每篇文章重复填一遍封面路径
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { resolveAssetPath } from '@/lib/assetPath';

export interface SeriesMeta {
  cover: string;   // 相对 public/series-covers/ 的路径，如 'series-covers/ai-transform.svg'
  order?: number;  // 越小越靠前，缺省排到最后
}

export const SERIES_CONFIG: Record<string, SeriesMeta> = {
  'AI 转型指南': {
    cover: 'series-covers/ai-transform.svg',
    order: 1,
  },
};

export function getSeriesCover(seriesName: string, fallback: string): string {
  const cover = SERIES_CONFIG[seriesName]?.cover;
  return cover ? resolveAssetPath(cover) : fallback;
}

export function getSeriesOrder(seriesName: string): number {
  return SERIES_CONFIG[seriesName]?.order ?? Number.MAX_SAFE_INTEGER;
}
```

未登记的系列名不会报错，会退化为用该系列第一篇文章自己的封面——这是有意的兜底，和你项目里"降级但绝不假装"的原则一致。

### 1.6 新建 `app/src/components/SeriesSection.tsx` — 一个系列的展示区块

import { Link } from 'react-router-dom';

## 2. 品味自检

- **DRY**：`resolveCover` 原来只在 `blogs.ts` 里，系列封面也要用同一条路径规则，所以抽成 `lib/assetPath.ts` 共享，没有抄第二份。
- **单一填写位**：系列封面登记表只有 `config/series.ts` 一处，和 `giscus.ts` 的模式一致，不是我发明的新范式。
- **不伪造兜底**：系列名未登记时退化为该系列首篇文章自己的封面，而不是占位图——延续你项目里"降级但绝不装死"的既有原则。
- **没有过度设计**：我一开始想给系列封面加"点击进入系列详情页"的路由筛选，中途否掉了——需求只要"分组展示"，不要专属路由，加了就是给假想需求增加复杂度。

## 3. 改进建议（不做，但你需要知道）

- **系列名是裸字符串外键**，`"AI 转型指南"` 和 `"AI转型指南"`（少个空格）会被判定成两个不同系列，静默分裂，没有任何报错。文章一多，这是最容易踩的坑。现在不做归一化处理，是因为你项目体量还小，加一层归一化本身就是过度设计；但系列名变多之后，值得在 `getSeriesGroups` 里加一次 trim + 归一化校验。
- **分类筛选与系列区块是两套独立视图**：如果某篇文章既属于"AI 转型指南"系列又想被"效率"分类筛选选中，现在的实现下用户在分类筛选结果里看不到它。这是设计取舍，不是 bug，但如果你后续想要"系列文章也能被分类筛中"，需要把 `getStandalonePosts` 换回全量 `getBlogPosts` 并在 UI 层做去重，那是另一次改动，现在不做。
