### `app/src/lib/assets.ts`（新增，从 `blogs.ts` 挖出来的）

```ts
/**
 * [INPUT]: 依赖 vite 注入的 import.meta.env.BASE_URL
 * [OUTPUT]: 对外提供 resolveAssetPath —— 把内容里写的相对路径资源，
 *           解析成带部署 base 前缀的可用 URL
 * [POS]: lib/ 层的资源路径解析器，被 data/blogs.ts（文章封面）与
 *        data/series.ts（系列封面）共用，避免同一段 base 拼接逻辑长出两份
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
export function resolveAssetPath(path: string): string {
  // 绝对 URL 与以 / 开头的路径原样返回：飞书文章封面是完整 URL，不能被前缀污染
  if (!path || /^(https?:)?\/\//.test(path) || path.startsWith('/')) {
    return path;
  }
  return `${import.meta.env.BASE_URL}${path}`;
}
```

### `app/src/data/series.ts`（新增）

```ts
/**
 * [INPUT]: 依赖 @/lib/assets 的 resolveAssetPath 解析封面相对路径
 * [OUTPUT]: 对外提供 getSeriesCover —— 按系列名查封面
 * [POS]: data/ 层系列元数据的唯一登记表。系列封面故意不放进 frontmatter：
 *        一个系列挂 N 篇文章，封面写进每篇就是 N 份重复，改一次要动 N 个文件，
 *        迟早互相漂移。这里是唯一权威来源，新增系列只需登记一行
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { resolveAssetPath } from '@/lib/assets';

// 系列名（须与文章 frontmatter 里的 series 值完全一致） -> 封面相对路径（相对 public/）
const SERIES_COVERS: Record<string, string> = {
  'AI 转型指南': 'covers/series/ai-transformation.svg',
};

export function getSeriesCover(name: string): string | undefined {
  const cover = SERIES_COVERS[name];
  return cover ? resolveAssetPath(cover) : undefined;
}
```

新增分组能力：

```ts
// ---------------------------------------------
// 系列分组
// ---------------------------------------------
export interface SeriesGroup {
  name: string;
  cover: string;
  posts: BlogPost[];
}

/**
 * 按系列分组博客文章
 * 组内按日期正序（第 1 篇到最后一篇的阅读顺序），组间按最新文章日期倒序
 * 组内顺序刻意反着全站列表——全站是"最新优先"的信息流，
 * 系列是"从头读到尾"的教程，两种排序语义不同，不能共用一套 sort
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const grouped = new Map<string, BlogPost[]>();

  for (const post of posts) {
    if (!post.series) continue;
    const list = grouped.get(post.series) ?? [];
    list.push(post);
    grouped.set(post.series, list);
  }

  const groups: SeriesGroup[] = Array.from(grouped.entries()).map(([name, groupPosts]) => {
    const sorted = [...groupPosts].sort((a, b) => a.date.localeCompare(b.date));
    return {
      name,
      // 未登记封面时兜底用系列第一篇文章自己的封面——真实内容，不是占位图
      cover: getSeriesCover(name) ?? sorted[0].coverImage,
      posts: sorted,
    };
  });

  return groups.sort(
    (a, b) => b.posts[b.posts.length - 1].date.localeCompare(a.posts[a.posts.length - 1].date)
  );
}
```

 * [INPUT]: 依赖 @/data/blogs 的 SeriesGroup 契约，react-router-dom 的 Link
 * [OUTPUT]: 对外提供 SeriesSection 组件
 * [POS]: components/blog 的系列分组展示器，被 pages/Blog 消费；

import { Link } from 'react-router-dom';
import type { SeriesGroup } from '@/data/blogs';

export function SeriesSection({ groups }: { groups: SeriesGroup[] }) {
  if (groups.length === 0) return null;

  return (

                  <li key={post.id}>
                    <Link to={`/blog/${post.id}`} className="text-sm hover:underline">

                    </Link>
                  </li>

              </ul>
            </div>

  );
}

## 2. 品味自检

- **封面为什么不进 frontmatter**：一个系列挂多篇文章，封面若跟着每篇文章走，就是同一份数据在 N 个文件里重复一份——改封面要改 N 次，且必然有一天漂移成"这篇系列文章用的是三个月前的旧封面"。单独登记表把"系列"这个实体的属性还给系列自己，而不是寄生在某一篇文章身上。这跟项目里 `config/giscus.ts` 是同一种模式：需要人工填写、且是全局唯一值的东西，只留一个填写位。
- **为什么抽出 `lib/assets.ts` 而不是让 `series.ts` 自己拼 `BASE_URL`**：`blogs.ts` 里原本就有一份一模一样的相对路径解析逻辑（`resolveCover`），系列封面要用同一条规则（否则本地能看见、发布到 GitHub Pages 又是一次 404 幽灵），复制一份就是这个项目最讨厌的"熵增"——同一件事第二次要用不同代码做。抽出来是唯一体面的做法。
- **系列内排序为什么反着全站列表**：全站列表是"最新优先"的信息流语义；系列是"从第一篇读到最后一篇"的教程语义。两者共用一套 `sort` 会把系列文章读乱——这是你提需求时没提到、但架构上必须显式做出的决定，不是我自作主张加功能。
- **未登记封面的兜底用系列首篇的 `coverImage`，不是灰色占位图**：延续这个项目一直坚持的原则——降级可以，但降级到的必须是真内容，不能是"看起来正常实则空转"的假数据。

## 3. 改进建议

- 系列数量若长到二十个以上，`SERIES_COVERS` 这个 `Record` 手写会开始难维护，到时候再考虑挪到 JSON 或允许单篇 frontmatter 覆写——现在做纯属过度设计，不做。
- `BlogDetail.tsx` 消费 `getSeriesGroups()` 做"上一篇/下一篇"系列内导航，是这个功能的自然延伸，但你没提，我也没动它——需要的话说一声，改动量很小（就是在详情页按 `series` 查一次分组，找当前文章的相邻两篇）。
- 系列封面图现在只是路径占位，`ai-transformation.svg` 这张图需要你自己设计放进去，不是我能代劳的部分。
