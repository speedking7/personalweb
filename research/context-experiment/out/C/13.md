### 新增 `app/src/data/series.ts`
系列是新的聚合维度,不是文章字段的衍生品。封面单独登记,而不是从某篇文章的 frontmatter 里猜——猜的方案一旦有人改了那篇"被指定"的文章封面,系列封面就跟着悄悄变了,查都没法查。

```ts
/**
 * [INPUT]: 依赖 @/data/blogs 的 getBlogPosts 取当前生效文章列表,@/lib/markdown 的
 *           resolveAssetPath 解析本地封面路径,@/types/blog 的 BlogPost 契约
 * [OUTPUT]: 对外提供 getSeriesGroups —— 按 frontmatter.series 分组聚合的系列列表
 * [POS]: data/ 层的系列聚合器,架在 blogs.ts 之上做纯聚合,不持有文章数据本身。
 *        封面单独登记在 seriesCovers,因为封面是"系列"粒度的事实,不是"文章"粒度的事实
 * [PROTOCOL]: 变更时更新此头部,然后检查 CLAUDE.md
 */
import { getBlogPosts } from './blogs';
import { resolveAssetPath } from '@/lib/markdown';
import type { BlogPost } from '@/types/blog';

// 系列封面登记表:系列名 -> 项目内本地相对路径,与文章封面同一套解析规则
// 图片实体放 app/public/covers/series/ 下
const seriesCovers: Record<string, string> = {
  'AI 转型指南': 'covers/series/ai-transformation.svg',
};

export interface SeriesGroup {
  name: string;
  cover: string;
  posts: BlogPost[];
}

/**
 * 按 series 字段分组,未标注的文章不参与。
 * 未登记封面的系列回退到组内最早一篇的封面——回退到真实数据,不留占位图。
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const grouped = new Map<string, BlogPost[]>();

  for (const post of posts) {
    if (!post.series) continue;
    const list = grouped.get(post.series) ?? [];
    list.push(post);
    grouped.set(post.series, list);
  }

  return Array.from(grouped.entries())
    .map(([name, seriesPosts]) => {
      const sorted = seriesPosts.slice().sort((a, b) => a.date.localeCompare(b.date));
      const registeredCover = seriesCovers[name];
      return {
        name,
        cover: registeredCover ? resolveAssetPath(registeredCover) : sorted[0].coverImage,
        posts: sorted,
      };
    })
    .sort((a, b) =>
      b.posts[b.posts.length - 1].date.localeCompare(a.posts[a.posts.length - 1].date)
    );
}
```

### 新增 `app/src/components/blog/SeriesSection.tsx`
这是一个新模块(components/ 下原来没有 blog/ 子目录),独立展示区,不侵入你现有分类/标签筛选的状态逻辑——两套筛选维度互不耦合,点击展开系列内文章列表,不改列表页原有 grid。

```tsx
/**
 * [INPUT]: 依赖 @/data/series 的 getSeriesGroups,react-router-dom 的 Link,
 *           @/components/ui/card 的 Card 系列 shadcn 基元
 * [OUTPUT]: 对外提供 SeriesSection 组件 —— 博客列表页顶部的系列分组展示区
 * [POS]: 博客列表页(pages/Blog.tsx)的独立分区,只读系列聚合结果、自持展开状态,
 *        不反向影响列表页原有的分类/标签筛选状态
 * [PROTOCOL]: 变更时更新此头部,然后检查 CLAUDE.md
 */
import { useEffect, useState } from 'react';
import { Link } from 'react-router-dom';
import { Card, CardContent } from '@/components/ui/card';
import { getSeriesGroups, type SeriesGroup } from '@/data/series';

export function SeriesSection() {
  const [groups, setGroups] = useState<SeriesGroup[]>([]);
  const [expanded, setExpanded] = useState<string | null>(null);

  useEffect(() => {
    getSeriesGroups().then(setGroups);
  }, []);

  if (groups.length === 0) return null;

  return (
    <section className="mb-12">
      <h2 className="text-2xl font-bold mb-4">系列文章</h2>
      <div className="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-4">
        {groups.map(group => (
          <Card
            key={group.name}
            className="cursor-pointer overflow-hidden"
            onClick={() => setExpanded(expanded === group.name ? null : group.name)}
          >
            {group.cover && (
              <img src={group.cover} alt={group.name} className="w-full h-32 object-cover" />
            )}
            <CardContent className="p-4">
              <h3 className="font-semibold">{group.name}</h3>
              <p className="text-sm text-muted-foreground">{group.posts.length} 篇</p>
            </CardContent>
          </Card>
        ))}
      </div>

      {expanded && (
        <ul className="mt-4 space-y-2 border-l-2 pl-4">
          {groups.find(g => g.name === expanded)!.posts.map(post => (
            <li key={post.id}>
              <Link to={`/blog/${post.id}`} className="hover:underline">{post.title}</Link>
              <span className="text-sm text-muted-foreground ml-2">{post.date}</span>
            </li>
          ))}
        </ul>
      )}
    </section>
  );
}
```

集成到 `pages/Blog.tsx`(我没看到这个文件,你自己找地方接):在分类筛选器上方加一行 `import { SeriesSection } from '@/components/blog/SeriesSection';`,JSX 里筛选栏之前插入 `<SeriesSection />`。

## 2. 品味自检

- SRP:`series.ts` 只做聚合,不碰文章存储;`SeriesSection` 只做展示,不碰筛选状态。三个关注点没有互相纠缠。
- DRY:`resolveAssetPath` 从 `blogs.ts` 提到 `lib/markdown.ts`,系列封面和文章封面共用一条规则,没有第二份实现。
- 数据源一致性:series 字段走 `parseBlogMetadata`,飞书/本地两条链路自动同步,没有另开一条解析逻辑。
- 有个假设我替你做了主张,说清楚:需求 2"按系列分组展示"我理解成"列表页顶部加一个系列展示区",而不是把整个列表推翻重排成系列视图——后者会打乱你现有的分类/标签筛选交互,前者是纯增量。如果你要的是后者,这版方案不够,得改。
- 封面登记表 `seriesCovers` 现在是硬编码在 `series.ts` 里的对象,系列一多会变成要维护的第二份清单——这是目前唯一没有完全消灭的"漂移点",但比"从某篇文章里猜封面"更诚实,drift 可见、可查、不会静默出错。

## 3. 改进建议

- 详情页(BlogDetail)加"系列内上一篇/下一篇"导航——这次没做,你没提,不该现在加(YAGNI)。真要做,数据已经现成:`getSeriesGroups()` 里排好序的 `posts` 数组直接能算出邻居。
- 系列封面登记表如果后续系列超过五六个,建议挪进 frontmatter 场景之外的一个独立 `series.yaml`/`series.json`,或者干脆强制"系列的第一篇必须带 `seriesCover` 字段",二选一,现在这个 `Record` 常量够用,先别过度设计。
- `SeriesSection` 目前点击是本地 `useState` 展开/收起,没有 URL 状态,刷新会丢失展开态——如果这个系列区要做成可分享链接,需要接入路由 query,现在没做。
