老杨：需求收到。系列文章本质上是"给文章打标签、给标签配封面"，数据源在两条链路（飞书/本地）之外还得留一个第三方登记点——封面这种一改全系列生效的东西，不能塞进每篇文章的 frontmatter 里重复写，否则你未来改一次封面就要去改 N 篇文章，这是明摆着的重复。方案如下，直接落地。

## 一、核心实现

### 1. `app/src/types/blog.ts` — 加一个可选字段

```ts
export interface BlogPost {
  id: string;
  title: string;
  excerpt: string;
  content: string;
  coverImage: string;
  category: string;
  tags: string[];
  date: string;
  readTime: number;
  series?: string; // 未命中 frontmatter 时不存在此键，不是空字符串——用于和"无系列"区分
}
```

### 2. `app/src/lib/markdown.ts` — frontmatter 里认出 `series`

在 `categoryMatch` 那段旁边加一行，两个数据源共用同一份规则，不会漂移：

```ts
const seriesMatch = frontmatter.match(/series:\s*["']?([^"'\n]+)["']?/);
if (seriesMatch) metadata.series = seriesMatch[1].trim();
```

不设默认值——没写 `series` 就是没有系列，不能给它捏造一个"未分类系列"，那是给数据造假。

### 3. 新增 `app/src/lib/assets.ts` — 把 `resolveCover` 的逻辑提出来做成公用件

`data/blogs.ts` 里原来那个 `resolveCover` 只服务文章封面，现在系列封面也要用同一套"相对路径补 BASE_URL、绝对路径原样放行"的规则，两处各写一份就是同一个 bug 未来会出现两次。提出来：

```ts
/**
 * [INPUT]: 依赖 import.meta.env.BASE_URL
 * [OUTPUT]: 对外提供 resolveAssetPath —— 本地相对路径补部署 base，绝对 URL/根路径原样放行
 * [POS]: lib/ 层的资源路径解析器，供 data/blogs.ts 的文章封面与 config/series.ts 的系列封面共用，
 *        规则只有一份；上线多一层路径前缀时只改这一处
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

### 4. 新增 `app/src/config/series.ts` — 系列封面的唯一填写位

和 `config/giscus.ts` 是同一类文件：需要人工维护、不该散落在文章里的值，只写这一处。

```ts
/**
 * [INPUT]: 依赖 @/lib/assets 的 resolveAssetPath 补全封面路径
 * [OUTPUT]: 对外提供 getSeriesMeta / resolveSeriesCover —— 系列名到封面/简介的映射
 * [POS]: config/ 层系列元数据的唯一填写位。frontmatter 里的 series 只是个名字，
 *        封面不重复写进每篇文章——改一次封面对整个系列生效，不用改 N 篇文章
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { resolveAssetPath } from '@/lib/assets';

interface SeriesMeta {
  cover: string;
  description?: string;
}

// key 必须与文章 frontmatter 里的 series 字段逐字符一致（含空格）
const seriesRegistry: Record<string, SeriesMeta> = {
  'AI 转型指南': {
    cover: 'series-covers/ai-transform.svg',
    description: '从工具使用到组织变革的 AI 落地路径',
  },
};

// 名字没登记时不丢文章，只是给个默认封面——数据源死掉和一切正常不能长得一样
const FALLBACK_COVER = 'series-covers/default.svg';

export function getSeriesMeta(name: string): SeriesMeta {
  return seriesRegistry[name] ?? { cover: FALLBACK_COVER };
}

export function resolveSeriesCover(name: string): string {
  return resolveAssetPath(getSeriesMeta(name).cover);
}
```

封面图片实体放 `app/public/series-covers/*.svg`（和文章封面同一套约定：`public/` 下的文件按 BASE_URL 原样静态服务，不走 Vite 模块打包）。

const staticBlogPosts: BlogPost[] = Object.entries(localPostModules)

在文件末尾（`clearCache` 之后）加分组能力：

```ts
export interface SeriesGroup {
  name: string;
  cover: string;
  description?: string;
  posts: BlogPost[];
}

/**
 * 按系列分组
 * posts 已按日期降序传入；组的先后顺序取自"该系列最新一篇文章在列表里第一次出现的位置"，
 * 也就是最近更新的系列排在前面——这是隐含语义，不是随机顺序
 * 未写 series 的文章不进入任何分组，交给调用方（列表页）决定怎么展示散篇
 */
export function groupPostsBySeries(posts: BlogPost[]): SeriesGroup[] {
  const order: string[] = [];
  const buckets = new Map<string, BlogPost[]>();

  for (const post of posts) {
    if (!post.series) continue;
    if (!buckets.has(post.series)) {
      buckets.set(post.series, []);
      order.push(post.series);
    }
    buckets.get(post.series)!.push(post);
  }

  return order.map(name => ({
    name,
    cover: resolveSeriesCover(name),
    description: getSeriesMeta(name).description,
    posts: buckets.get(name)!,
  }));
}

/** 不属于任何系列的文章，保持原有扁平展示 */
export function getStandalonePosts(posts: BlogPost[]): BlogPost[] {
  return posts.filter(post => !post.series);
}
```

### 6. 列表页（`app/src/pages/Blog.tsx`）— 接入分组渲染

我没有这个文件的现状，下面给的是接入点模板：找到现在渲染文章卡片的那段 `posts.map(post => <PostCard ... />)`，在它外面套一层分组。如果页面本身还有分类筛选，筛选要发生在分组**之前**（先过滤出当前分类的 posts，再分组），顺序反了会导致某个系列筛选后突然消失一半文章却看不出原因。

```tsx
import { groupPostsBySeries, getStandalonePosts } from '@/data/blogs';

// posts 是筛选后的当前文章列表（保持原有筛选逻辑不变）
const seriesGroups = useMemo(() => groupPostsBySeries(posts), [posts]);
const standalonePosts = useMemo(() => getStandalonePosts(posts), [posts]);

return (
  <div className="space-y-12">
    {seriesGroups.map(group => (
      <section key={group.name}>
        <div
          className="relative h-40 rounded-lg bg-cover bg-center flex items-end p-4 mb-4 overflow-hidden"
          style={{ backgroundImage: `url(${group.cover})` }}
        >
          <div className="absolute inset-0 bg-black/40" />
          <h2 className="relative z-10 text-2xl font-bold text-white">{group.name}</h2>
        </div>
        {group.description && (
          <p className="text-muted-foreground mb-4">{group.description}</p>
        )}
        <div className="grid grid-cols-1 md:grid-cols-3 gap-6">
          {group.posts.map(post => (
            <PostCard key={post.id} post={post} />
          ))}
        </div>
      </section>
    ))}

    {standalonePosts.length > 0 && (
      <section>
        {seriesGroups.length > 0 && (
          <h2 className="text-2xl font-bold mb-4">更多文章</h2>
        )}
        <div className="grid grid-cols-1 md:grid-cols-3 gap-6">
          {standalonePosts.map(post => (
            <PostCard key={post.id} post={post} />
          ))}
        </div>
      </section>
    )}
  </div>
);
```

`PostCard` 换成页面里实际用的卡片组件名即可，其它布局/className 按现有页面风格对齐。

## 二、品味自检

- **DRY**：路径解析规则只有一份（`resolveAssetPath`），文章封面和系列封面共用，不会各自漂移。
- **SRP**：`config/series.ts` 只管"系列元数据"，`data/blogs.ts` 只管"怎么分组"，`lib/assets.ts` 只管"路径怎么补全"——三个变更理由，三个文件。
- **YAGNI 边界**：没有做系列的分类筛选整合、没有做 BlogDetail 系列导航、没有做系列专属路由——需求只要三件事，就只交付三件事。
- **兜底原则一致**：`getSeriesMeta` 对未登记的系列名给默认封面而不是丢文章，延续了这个项目"降级但不假装正常"的既有原则。
- **风险点**：`seriesRegistry` 的 key 是字符串精确匹配，frontmatter 里系列名多打一个空格就会被当成两个系列。这是人工维护表带来的脆弱性，暂时可接受（系列数量少），但值得留意。

## 三、改进建议

1. 系列一旦超过 5-6 个，`seriesRegistry` 手写映射会变得难维护，届时可以考虑把系列元数据也下沉成 `content/series/*.md`（自带 frontmatter：name/cover/description），用和文章一样的 glob 扫描方式，彻底摆脱手工登记表。
2. `BlogDetail.tsx` 目前看不到系列上下文，后续可以在文中加一条"本文属于《XX 系列》，查看系列其他文章"的面包屑，复用 `groupPostsBySeries` 按 `series` 反查即可，工作量很小，但这次不在需求范围内，先不动。
