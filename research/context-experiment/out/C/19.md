老杨来了。系列文章这需求不复杂，但有一个坑得先挑明：**系列封面不能塞进每篇文章的 frontmatter**——一个系列十篇文章重复写十遍同一张封面路径，就是"数据泥团"，以后改张封面图要改十个文件。封面归系列，不归文章，这是这次设计的唯一关键决策。

## 1. 核心实现

**`lib/assets.ts`**（新建，从 `blogs.ts` 里那段 `resolveCover` 原样搬过来改名导出）
```ts
/**
 * [INPUT]: 依赖 import.meta.env.BASE_URL
 * [OUTPUT]: 对外提供 resolveAssetPath —— 把 frontmatter 里的相对路径补上部署 base
 * [POS]: lib/ 层的路径解析器，被 data/blogs.ts（文章封面）与 data/series.ts（系列封面）共用，
 *        两处都要遵守同一条"绝对 URL/根路径原样返回，相对路径补 base"规则，抽出来避免规则分叉
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

**`data/series.ts`**（新建）
```ts
/**
 * [INPUT]: 依赖 @/lib/assets 的 resolveAssetPath 解析封面路径
 * [OUTPUT]: 对外提供 getSeriesCover —— 按系列名查封面
 * [POS]: data/ 层的系列元数据清单。文章 frontmatter 只认领系列名字，
 *        封面图与系列的绑定关系集中在这一份表里，避免每篇文章重复写同一张封面路径
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { resolveAssetPath } from '@/lib/assets';

// 系列名 -> 封面相对路径，图片实体放 app/public/series/ 下
// 新增系列 = 加一行 + 把封面图丢进 public/series/，无需改动其他文件
const SERIES_COVERS: Record<string, string> = {
  'AI 转型指南': 'series/ai-transformation.svg',
};

export function getSeriesCover(series: string): string | undefined {
  const cover = SERIES_COVERS[series];
  return cover ? resolveAssetPath(cover) : undefined;
}
```

在 `getPostsByTag` 之后加两个聚合函数，与 `getPostsByCategory` 同一档次：
```ts
export interface SeriesGroup {
  series: string;
  cover?: string;
  posts: BlogPost[];
}

/**
 * 按系列分组博客，保留文章在系列内的原始顺序（按日期倒序）
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const order: string[] = [];
  const groups = new Map<string, BlogPost[]>();
  for (const post of posts) {
    if (!post.series) continue;
    if (!groups.has(post.series)) {
      groups.set(post.series, []);
      order.push(post.series);
    }
    groups.get(post.series)!.push(post);
  }
  return order.map(series => ({
    series,
    cover: getSeriesCover(series),
    posts: groups.get(series)!,
  }));
}

/**
 * 未归入任何系列的文章，供列表页在系列分组之外单独渲染
 */
export async function getStandalonePosts(): Promise<BlogPost[]> {
  const posts = await getBlogPosts();
  return posts.filter(post => !post.series);
}
```

**`pages/Blog.tsx`**（该文件不在你贴的上下文里，我按现有数据流的调用惯例给接入点，卡片组件复用现有的即可，不用新建）
```tsx
const [seriesGroups, standalonePosts] = await Promise.all([
  getSeriesGroups(),
  getStandalonePosts(),
]);
```
```tsx
{seriesGroups.map(group => (
  <section key={group.series} className="mb-12">
    <div
      className="rounded-lg bg-cover bg-center p-6 mb-4"
      style={group.cover ? { backgroundImage: `url(${group.cover})` } : undefined}
    >
      <h2 className="text-xl font-semibold text-white">{group.series}</h2>
    </div>
    <div className="grid grid-cols-1 md:grid-cols-3 gap-6">
      {group.posts.map(post => <BlogCard key={post.id} post={post} />)}
    </div>
  </section>
))}
{standalonePosts.length > 0 && (
  <div className="grid grid-cols-1 md:grid-cols-3 gap-6">
    {standalonePosts.map(post => <BlogCard key={post.id} post={post} />)}
  </div>
)}
```
**范围收窄**：系列分组只在"全部"视图下出现；用户切到具体分类筛选时退回现有的平铺列表，不做"分类 × 系列"二次交叉分组——一篇文章可能属于某系列又挂某分类，交叉展示是没人要求的复杂度（YAGNI），先不做。

## 2. 品味自检

- 封面与文章解耦，改封面不碰文章文件——过了"僵化"红线检查
- `resolveAssetPath` 抽出来后只有一份路径规则，飞书文章的绝对 URL 封面和本地系列封面走同一逻辑——没有规则分叉
- `getSeriesGroups` 是纯函数聚合，不侵入 `getBlogPosts` 的飞书/静态降级分支，`blogs.ts` 的职责边界没被打破
- 风险点：`SERIES_COVERS` 是手工维护的 Record，系列名全靠人工输入字符串对齐，frontmatter 里 `series: AI 转型指南` 和清单里的 key 拼错一个字就悄悄丢分组——这是唯一的脆弱点，值得注意但暂不需要为此加校验机制（文章量级不大，构建时肉眼能查）

## 3. 改进建议

若系列数量后续涨到两位数，或者要求系列内文章有手动排序（而非按日期倒序），`SERIES_COVERS: Record<string,string>` 该升级成 `Record<string, {cover: string; order: number}>`，现在先不做——先按 YAGNI 用最小实现，等真的痛了再改。
