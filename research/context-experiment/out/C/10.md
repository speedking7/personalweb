### 新建 `app/src/lib/assets.ts` —— 从 `blogs.ts` 抽出来的公共逻辑

`blogs.ts` 里原本有个 `resolveCover`，专门给本地文章封面补 `BASE_URL`。系列封面要用同一套规则——不抽出来，这逻辑马上就会在两个文件里长出两份，早晚一处漏改。

```ts
/**
 * [INPUT]: 依赖 import.meta.env.BASE_URL
 * [OUTPUT]: 对外提供 resolveAssetPath —— 给本地相对路径资源补上部署 base
 * [POS]: lib/ 层的路径解析工具，被 data/blogs.ts（文章封面）与 data/series.ts（系列封面）共用。
 *        绝对 URL 与以 / 开头的路径原样返回，避免飞书返回的完整 URL 被前缀污染
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

### 新建 `app/src/config/series.ts` —— 系列封面的人工登记表

### 新建 `app/src/data/series.ts` —— 分组聚合逻辑

```ts
/**
 * [INPUT]: 依赖 @/data/blogs 的 getBlogPosts，@/config/series 的 seriesRegistry，
 *           @/lib/assets 的 resolveAssetPath，@/types/blog 的 BlogPost/SeriesGroup 契约
 * [OUTPUT]: 对外提供 getSeriesGroups —— 把文章列表按 series 字段分组，附带系列封面
 * [POS]: data/ 层的系列聚合器，是 blogs.ts 之上的一层视图变换，不直接接触数据源。
 *        没有 series 字段的文章不进入任何分组——避免用"未分类系列"这种假分组
 *        冒充成真实的系列内容，重蹈本项目已经明确拒绝过的"占位假数据"覆辙
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { getBlogPosts } from '@/data/blogs';
import { seriesRegistry } from '@/config/series';
import { resolveAssetPath } from '@/lib/assets';
import type { SeriesGroup } from '@/types/blog';

export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const groups = new Map<string, SeriesGroup>();

  for (const post of posts) {
    if (!post.series) continue;
    const existing = groups.get(post.series);
    if (existing) {
      existing.posts.push(post);
      continue;
    }
    const rawCover = seriesRegistry[post.series] ?? '';
    groups.set(post.series, {
      name: post.series,
      cover: rawCover ? resolveAssetPath(rawCover) : '',
      posts: [post],
    });
  }

  return Array.from(groups.values())
    .map(group => ({
      ...group,
      posts: group.posts.sort((a, b) => b.date.localeCompare(a.date)),
    }))
    .sort((a, b) => b.posts[0].date.localeCompare(a.posts[0].date));
}
```

### 新建 `app/src/components/BlogSeriesSection.tsx` —— 列表页的系列区块

单独成组件，不直接改 `pages/Blog.tsx` 内部的筛选/搜索状态——那部分我没拿到源码，硬猜着改风险大，加一个独立区块比往一个不认识的状态机里插逻辑安全。

```tsx
/**
 * [INPUT]: 依赖 @/data/series 的 getSeriesGroups，@/types/blog 的 SeriesGroup，
 *           @/components/ui/card 的 Card/CardContent，react-router-dom 的 Link
 * [OUTPUT]: 对外提供 BlogSeriesSection 组件 —— 系列封面卡片陈列
 * [POS]: components/ 层的博客列表页子区块，被 pages/Blog.tsx 挂载在文章列表上方
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { useEffect, useState } from 'react';
import { Link } from 'react-router-dom';
import { Card, CardContent } from '@/components/ui/card';
import { getSeriesGroups } from '@/data/series';
import type { SeriesGroup } from '@/types/blog';

export function BlogSeriesSection() {
  const [groups, setGroups] = useState<SeriesGroup[]>([]);

  useEffect(() => {
    getSeriesGroups().then(setGroups);
  }, []);

  if (groups.length === 0) return null;

  return (
    <section className="mb-12">
      <h2 className="text-2xl font-bold mb-4">系列文章</h2>
      <div className="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-4">
        {groups.map(group => (
          <Card key={group.name} className="overflow-hidden">
            {group.cover ? (
              <img src={group.cover} alt={group.name} className="h-32 w-full object-cover" />
            ) : (
              <div className="h-32 w-full flex items-center justify-center bg-muted text-muted-foreground text-sm">
                未配置封面
              </div>
            )}
            <CardContent className="p-4">
              <h3 className="font-semibold">{group.name}</h3>
              <p className="text-sm text-muted-foreground">{group.posts.length} 篇</p>
              <ul className="mt-2 space-y-1">
                {group.posts.map(post => (
                  <li key={post.id}>
                    <Link to={`/blog/${post.id}`} className="text-sm hover:underline">
                      {post.title}
                    </Link>
                  </li>
                ))}
              </ul>
            </CardContent>
          </Card>
        ))}
      </div>
    </section>
  );
}
```

## 2. 品味自检

- **不是重复而是复用**：`resolveAssetPath` 从 `blogs.ts` 抽出来，`series.ts` 和 `blogs.ts` 共用一份 base 前缀逻辑——如果你不抽，两周后有人改了其中一处的正则，另一处线上就悄悄 404，这种 bug 最难查，因为本地永远复现不了（本地 dev 本来就是从根提供服务）。
- **没有假数据**：系列没配置封面时，卡片显式写"未配置封面"，不拿占位图糊弄——跟你项目里 `getCategories()` 兜底不写死分类是同一个态度，我没有破例。
- **没有强行合并数据源**：飞书和本地共用 `parseBlogMetadata`，所以 `series` 字段两条链路自动生效，我没有在 `feishu.ts` 里另开一条路径——但这依赖一个我没验证的前提：飞书客户端内部确实调用了 `parseBlogMetadata` 而不是自己另起一套解析。CLAUDE.md 里写了这是既定事实，我信了，但你落地前最好扫一眼 `lib/feishu.ts` 确认。
- **唯一的硬伤**：`seriesRegistry` 的 key 和文章 frontmatter 里的 `series` 字符串必须逐字相同，纯靠人眼对齐，没有任何编译期或运行期校验，手滑打错一个字系列就静默分裂成两个。这个我留到"改进建议"里，不在这次范围内顺手做，YAGNI——现在系列数量小，先跑起来再说。

## 3. 改进建议

- 系列一旦多起来（比如超过 5 个），给 `getSeriesGroups()` 加一个开发环境下的一致性检查：文章里出现的 `series` 值如果不在 `seriesRegistry` 里，`console.warn` 提示"该系列未登记封面"，比现在完全静默、只在页面上看出"没图"要主动。
- 如果以后要支持系列内"上一篇/下一篇"跳转，`series.ts` 这层已经天然是加这个的位置——`getSeriesGroups()` 里的分组结果直接能派生出来，不需要另开数据流。

**GEB 文档回环**：`lib/CLAUDE.md`、`data/CLAUDE.md`、`config/CLAUDE.md`、`components/CLAUDE.md` 这四份 L2 成员清单里都要各加一行（`assets.ts` / `series.ts` / `series.ts` / `BlogSeriesSection.tsx`），L1 的 `<config>` 段建议补一句 `config/series.ts` 的用途。这几份我没有原文，落地时你那边跑一遍检查。
