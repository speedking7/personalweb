老杨，需求收到。系列文章这事儿说白了就是"给文章加一个分组维度"，麻烦的地方不在于加字段，而在于封面图归属——封面属于"系列"这个概念，不属于某一篇文章，搞混了以后同系列多篇文章互相打架的坑迟早得填。方案如下，改 5 个既有文件、新建 2 个文件。

## 1. 核心实现

### 1.2 `app/src/lib/assetPath.ts`（新建）
`data/blogs.ts` 里原有的 `resolveCover` 只服务于文章封面，现在系列封面也要过同一套 base-path 逻辑，直接把它提出来做成共享 util，别复制一份——复制出来的第二份迟早会漂移。

```ts
/**
 * [INPUT]: 依赖 import.meta.env.BASE_URL (Vite 注入的部署 base path)
 * [OUTPUT]: 对外提供 resolveAssetPath —— 把本地相对路径补全为部署路径
 * [POS]: lib/ 层的路径解析器，供文章封面(data/blogs.ts)与系列封面(config/series.ts 消费方)共用。
 *        绝对 URL 与以 / 开头的路径原样返回：飞书文章封面是完整 URL，不能被本地 base 前缀污染
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

### 1.4 `app/src/config/series.ts`（新建）
系列封面属于系列本身，不属于任何一篇文章。塞进每篇文章的 frontmatter 会导致同系列文章互相声明、互相打架——这是数据泥团的变种。项目里已经有先例：`config/giscus.ts` 就是专门放"人工登记、代码推导不出来"的值，系列元数据完全同款，不算新范式，是照抄现有范式。

```ts
/**
 * [INPUT]: 无外部依赖
 * [OUTPUT]: 对外提供 SeriesMeta 类型、getSeriesMeta 单个查询、getAllSeriesMeta 全量查询
 * [POS]: config/ 层的系列元数据登记表，与 giscus.ts 同类——人工维护、无法从文章内容派生的信息。
 *        系列封面的唯一权威来源，杜绝多篇文章各自声明导致的漂移
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */

export interface SeriesMeta {
  name: string;
  cover: string; // 相对 app/public/ 的本地路径，如 covers/series-ai.svg
  description?: string;
}

const seriesRegistry: SeriesMeta[] = [
  {
    name: 'AI 转型指南',
    cover: 'covers/series-ai-transformation.svg',
    description: '从传统开发到 AI 辅助开发的转型笔记',
  },
];

export function getSeriesMeta(name: string): SeriesMeta | undefined {
  return seriesRegistry.find(s => s.name === name);
}

export function getAllSeriesMeta(): SeriesMeta[] {
  return seriesRegistry;
}
```

封面图片放 `app/public/covers/`，跟文章封面同一个目录——因为 `resolveAssetPath` 拼的是 `BASE_URL + 相对路径`，这套逻辑只对 `public/` 下的静态资源成立（放 `src/assets/` 就得走 import 或 `import.meta.glob`，是另一套机制，没必要为系列封面另开一条路）。

### 1.5 `app/src/data/blogs.ts`（改）
- 删除本文件内的 `resolveCover`，改用 `resolveAssetPath`：

```ts

// ... staticBlogPosts 构建处把 resolveCover 换成 resolveAssetPath
```

- 新增系列分组能力：

```ts
export interface SeriesGroup {
  name: string;
  cover: string;
  description?: string;
  posts: BlogPost[];
}

/**
 * 按系列分组，系列内部按发布时间正序（第一篇在前，符合"系列阅读顺序"直觉）
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const grouped = new Map<string, BlogPost[]>();

  posts.forEach(post => {
    if (!post.series) return;
    const list = grouped.get(post.series) ?? [];
    list.push(post);
    grouped.set(post.series, list);
  });

  return Array.from(grouped.entries()).map(([name, seriesPosts]) => {
    const meta = getSeriesMeta(name);
    return {
      name,
      // 系列未登记时兜底用系列内第一篇的封面，而不是留空——留空在列表页上就是个破图占位
      cover: meta ? resolveAssetPath(meta.cover) : seriesPosts[0].coverImage,
      description: meta?.description,
      posts: seriesPosts.sort((a, b) => a.date.localeCompare(b.date)),
    };
  });
}

/**
 * 没有系列归属的独立文章，供列表页在系列分组之外单独展示
 */
export async function getUngroupedPosts(): Promise<BlogPost[]> {
  const posts = await getBlogPosts();
  return posts.filter(post => !post.series);
}
```

## 2. 品味自检

- **DRY**：`resolveAssetPath` 只有一份，封面路径解析规则不会因为"文章封面"和"系列封面"两条路径各自演化出不同 bug。
- **数据泥团规避**：系列名+封面+简介这三个字段总是一起出现，封装成 `SeriesMeta` 而不是三个散落的可选字段，是照着已有的 `giscus.ts` 范式抄的，不是新发明。
- **兜底不是假数据**：系列未在 `series.ts` 里登记时，不会显示破图或空白，退而求其次用系列内第一篇文章的封面——这条兜底策略延续了项目 CLAUDE.md 里反复强调的原则（"兜底必须是真实数据，不能是占位假数据"）。
- **没有过度设计**：没有引入系列的"层级"、"排序权重"这类没人要求的东西，`series` 就是个字符串，分组靠字符串相等，YAGNI。
