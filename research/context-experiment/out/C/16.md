### ③ `app/src/config/series.ts`（新建）— 系列封面与排序的唯一填写位

```ts
/**
 * [INPUT]: 无外部依赖
 * [OUTPUT]: 对外提供 seriesRegistry、getSeriesCover、getSeriesOrder
 * [POS]: config/ 层，系列封面图与展示顺序的唯一填写位，与 giscus.ts 同构。
 *        文章 frontmatter 里的 series 只是一个名字字符串，封面和排序集中登记在这里，
 *        避免同一系列的封面因散落在多篇文章里而互相打架；未登记时返回空字符串，
 *        交给页面显式提示缺配置，不用占位图掩盖
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */

export interface SeriesMeta {
  /** 相对 public/ 的路径，如 'covers/series/ai-transformation.svg' */
  cover: string;
  /** 列表展示顺序，越小越靠前；不填排最后 */
  order?: number;
}

// key 必须与文章 frontmatter 里的 series 原文完全一致，新增系列在此登记即可
export const seriesRegistry: Record<string, SeriesMeta> = {
  'AI 转型指南': { cover: 'covers/series/ai-transformation.svg', order: 1 },
};

export function getSeriesCover(series: string): string {
  return seriesRegistry[series]?.cover ?? '';
}

export function getSeriesOrder(series: string): number {
  return seriesRegistry[series]?.order ?? Number.MAX_SAFE_INTEGER;
}
```

封面图实际文件放 `app/public/covers/series/ai-transformation.svg`，和文章封面同一套 `public/` 约定，`resolveCover` 会给它补同样的 base 前缀。

### ④ `app/src/data/blogs.ts` — 加分组聚合函数

顶部加一行 import：

```ts
import { getSeriesCover, getSeriesOrder } from '@/config/series';
```

文件里补一个类型和一个函数（直接复用文件内已有的 `resolveCover`，不重复造轮子）：

```ts
export interface SeriesGroup {
  series: string;
  cover: string;
  posts: BlogPost[];
}

/**
 * 按系列分组博客文章。只有带 series 字段的文章参与分组；
 * 未分组文章不在这里处理，由调用方（列表页）决定怎么展示——
 * 这个函数只管"分组"这一件事，不替页面做布局决策
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const grouped = new Map<string, BlogPost[]>();

  for (const post of posts) {
    if (!post.series) continue;
    const list = grouped.get(post.series) ?? [];
    list.push(post);
    grouped.set(post.series, list);
  }

  return Array.from(grouped.entries())
    .map(([series, seriesPosts]) => ({
      series,
      cover: resolveCover(getSeriesCover(series)),
      // 系列内部按时间正序，还原阅读顺序；跟列表页整体倒序排列相反，是有意的
      posts: seriesPosts.slice().sort((a, b) => a.date.localeCompare(b.date)),
    }))
    .sort((a, b) => getSeriesOrder(a.series) - getSeriesOrder(b.series));
}
```

同步把该文件 L3 头部的 `[OUTPUT]` 一行加上 `getSeriesGroups`。

## 2. 品味自检

- **SRP**：`markdown.ts` 只管解析、`series.ts` 只管映射、`blogs.ts` 的 `getSeriesGroups` 只管分组、页面只管渲染，四层各司其职，没有谁越界。
- **DRY**：封面路径解析复用已有的 `resolveCover`，没有重新拼一遍 `BASE_URL` 前缀逻辑。
- **数据泥团**：`cover` 和 `order` 总是一起出现，封装进了 `SeriesMeta`，没有散成两个平行的 `Record`。
- **兜底一致性**：`getSeriesCover` 未登记时返回空字符串，不是假图片路径——这跟 `blogs.ts` 里"降级必须是真文章，不能是占位假数据"是同一条原则的另一处体现，没有破坏项目自己立的规矩。
- **YAGNI**：没有做"系列内上一篇/下一篇"导航，需求没提，不主动加。
