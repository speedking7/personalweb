老杨来了。系列文章这需求不复杂，但封面这块容易埋雷——一不小心就会让"系列封面"这种应该只填一次的东西散落在每篇文章的 frontmatter 里，写歪一个字就分裂成两个系列。按你项目现有的规矩办：giscus.ts 怎么做单填写位，系列封面就怎么做。

## 1. 核心实现

**`app/src/lib/markdown.ts`** —— frontmatter 新增一个字段解析，飞书和本地文章共用这一份解析器，改这一处两条链路同时生效，不用碰 `lib/feishu.ts`


**`app/src/config/series.ts`（新建）** —— 系列封面的唯一填写位，模式抄 giscus.ts

```ts
/**
 * [INPUT]: 无外部依赖，纯数据
 * [OUTPUT]: 对外提供 SeriesInfo 类型与 seriesRegistry —— 系列名到封面/简介的映射

 */
export interface SeriesInfo {
  cover: string; // 相对路径，实际文件放在 app/public/series/ 下
  description?: string;
}

export const seriesRegistry: Record<string, SeriesInfo> = {
  'AI 转型指南': {
    cover: 'series/ai-transformation.svg',
    description: '从传统开发者到 AI 时代的转型实践',
```

封面图实际文件放 `app/public/series/ai-transformation.svg`，走 `public/` 是因为要吃 base path 前缀那一套（跟本地文章封面同一个坑，见下）。

**`app/src/data/blogs.ts`** —— 三处改动：导出 `resolveCover`（现有本地封面的 base 前缀补全逻辑，系列封面要复用，不能另起一份）、加 `SeriesGroup` 类型、加 `getSeriesGroups`

```ts
import { seriesRegistry } from '@/config/series';

// 原本是 const resolveCover，改成导出
export const resolveCover = (cover: string): string =>
  !cover || /^(https?:)?\/\//.test(cover) || cover.startsWith('/')
    ? cover
    : `${import.meta.env.BASE_URL}${cover}`;

export interface SeriesGroup {
  name: string;
  cover: string;
  description?: string;
  posts: BlogPost[];
}

/**
 * 按系列分组，只统计带 series 字段的文章；不影响未分组文章原有的展示逻辑
 */
export async function getSeriesGroups(): Promise<SeriesGroup[]> {
  const posts = await getBlogPosts();
  const grouped = new Map<string, BlogPost[]>();

  posts.forEach(post => {
    if (!post.series) return;
    const bucket = grouped.get(post.series) ?? [];
    bucket.push(post);
    grouped.set(post.series, bucket);
  });

  return Array.from(grouped.entries())
    .map(([name, seriesPosts]) => ({
      name,
      cover: resolveCover(seriesRegistry[name]?.cover ?? ''),
      description: seriesRegistry[name]?.description,
      posts: seriesPosts.sort((a, b) => b.date.localeCompare(a.date)),
    }))
    .sort((a, b) => b.posts[0].date.localeCompare(a.posts[0].date));
}
```

```tsx
import { SeriesSection } from '@/components/blog/SeriesSection';
import { getSeriesGroups, type SeriesGroup } from '@/data/blogs';

const [seriesGroups, setSeriesGroups] = useState<SeriesGroup[]>([]);
const [activeSeries, setActiveSeries] = useState<string | null>(null);

useEffect(() => {
  getSeriesGroups().then(setSeriesGroups);
}, []);

// posts 是页面里已有的、经过分类/标签筛选后的列表
const visiblePosts = activeSeries
  ? posts.filter(post => post.series === activeSeries)
  : posts;

// JSX 里，在现有分类 tab 之下、文章列表之上插入：
{!activeSeries && <SeriesSection groups={seriesGroups} onSelect={setActiveSeries} />}
{activeSeries && (
  <div className="mb-4 flex items-center gap-2">
    <button onClick={() => setActiveSeries(null)} className="text-sm text-muted-foreground">
      ← 返回全部
    </button>
    <h2 className="text-lg font-medium">{activeSeries}</h2>
  </div>
)}
// 下方原有的文章渲染把 posts 换成 visiblePosts
```

## 2. 品味自检

- **没有把封面塞进 frontmatter**：如果让"系列封面"这种一对多共享的属性挂在文章级别的 frontmatter 上，N 篇同系列文章就有 N 次写错封面路径的机会，而且没人能保证它们一致——这是数据泥团的反面教材。`config/series.ts` 单填写位是对的选择，跟 giscus.ts 同一种纪律。
- **只改了 `lib/markdown.ts` 一处**，飞书和本地两条链路自动同步获得系列能力，没有碰 `lib/feishu.ts`——这正是 CLAUDE.md 里"两源共用一份解析规则"这条约束存在的意义，改动落在契约上而不是各自实现上。
- **`resolveCover` 复用而非复制**：系列封面同样要吃 base path 前缀那个坑（本地能看见、上线 404），如果重新写一遍逻辑，以后 base path 规则一变就得改两处。导出复用，一处改全对。
- **未分组文章零回归**：`series` 是可选字段，`getSeriesGroups` 只挑有值的文章，现有分类/标签/搜索路径一行没动。

## 3. 改进建议（不在本次范围内，先不做）

- `BlogDetail` 页面可以加"本文属于《XX》系列，查看其他 N 篇"的导航条，但这属于新展示位，你没提就先不加，等你要看效果我再补。
- `seriesRegistry` 里系列名靠人工对齐字符串，量大了容易错拼；如果系列数超过一二十个，值得改成 `id + displayName` 两段式，现在体量下没必要。
