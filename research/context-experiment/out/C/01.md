### 3. `app/src/lib/assets.ts`（新增）

```ts
/**
 * [INPUT]: 依赖 vite 注入的 import.meta.env.BASE_URL
 * [OUTPUT]: 对外提供 resolveAssetPath —— 把仓库内相对路径资源补上部署 base
 * [POS]: lib/ 层的资源路径解析器，从 data/blogs.ts 抽出。
 *        被文章封面（content/posts frontmatter 的 cover）与系列封面（config/series.ts）共用，
 *        避免同一条"补 base"规则在两处各写一份
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

### 4. `app/src/config/series.ts`（新增）

```ts
/**
 * 按系列分组博客文章
 * 无 series 字段的文章不进入任何分组，交由列表页作为独立文章渲染
 */
export function groupPostsBySeries(posts: BlogPost[]): { series: SeriesGroup[]; standalone: BlogPost[] } {
  const seriesMap = new Map<string, BlogPost[]>();
  const standalone: BlogPost[] = [];

  posts.forEach(post => {
    if (!post.series) {
      standalone.push(post);
      return;
    }
    const list = seriesMap.get(post.series) ?? [];
    list.push(post);
    seriesMap.set(post.series, list);
  });

  const series = Array.from(seriesMap.entries()).map(([name, seriesPosts]) => ({
    name,
    cover: resolveAssetPath(seriesCovers[name] ?? DEFAULT_SERIES_COVER),
    posts: seriesPosts.sort((a, b) => b.date.localeCompare(a.date)),
  }));

  return { series, standalone };
}

/**
 * 获取按系列分组的博客列表
 * 分组是纯函数，数据源 feishu/static/auto 降级逻辑全在 getBlogPosts 里，这里不重复决策
 */
export async function getPostsGroupedBySeries(): Promise<{ series: SeriesGroup[]; standalone: BlogPost[] }> {
  return groupPostsBySeries(await getBlogPosts());
}
```

同时把文件头部 L3 注释的 `[OUTPUT]` 一行补上这两个新导出。

## 品味自检

- **DRY**：`resolveCover` 从私有函数升级成 `lib/assets.ts` 的公共 `resolveAssetPath`，文章封面和系列封面共用一套"补 base"规则，没有第二次发明轮子。
- **SRP**：`series.ts` 只管"名字→图片"的映射，分组逻辑在 `blogs.ts`，渲染在 `Blog.tsx`——三层各管一件事，谁改了都不连锁牵动别处。
- **YAGNI**：没给 `SeriesGroup` 加 `description`/排序权重之类还用不上的字段，等真需要系列简介的时候再加，不是现在。
- **不留假数据的一致性**：`series` 缺失时保持 `undefined` 而不是兜底成"未分类"字符串，跟你现有对"兜底必须是真文章"的态度是一致的——没有系列就是没有，不伪造一个分组出来。
- 唯一的坏味道是 `pages/Blog.tsx` 我没见着源码就给了方案，这部分你落地时要对着实际 JSX 校一遍，别我这边的假设跟你现有的卡片渲染结构对不上。

## 改进建议

1. 系列封面目前是全局唯一映射表，如果以后同名系列想换封面版本（比如改版重新设计），`seriesCovers` 直接覆盖旧值即可，不用额外加版本号字段。
2. 现在系列内文章排序用的是日期倒序，如果系列本身是有先后阅读顺序的教程类内容（第一课、第二课），未来可能需要在 frontmatter 里加 `seriesOrder: number` 覆盖默认排序——现在没这个需求就不要提前加。
3. `Blog.tsx` 抽出 `BlogCard` 之后，正好也是给系列详情页（如果以后要做「系列专题页」路由）铺路的自然切入点，但这次不需要现在做。
