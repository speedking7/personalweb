### `app/src/lib/assets.ts`（新增，从 blogs.ts 抽出来的路径补全逻辑）

```ts
/**
 * [INPUT]: 依赖 import.meta.env.BASE_URL
 * [OUTPUT]: 对外提供 resolveAssetPath —— 把 public/ 下的相对路径补全为部署路径
 * [POS]: lib/ 层的路径工具，被 data/blogs.ts 与 data/series.ts 共用。
 *        GitHub Pages 部署会在路径前多一层 base，这条规则只能有一份，
 *        否则文章封面和系列封面各写一遍迟早会漂移
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

### `app/src/data/series.ts`（新增，核心）

```ts
/**
 * [INPUT]: 依赖 @/lib/assets 的 resolveAssetPath 补全封面路径，
 *           @/types/blog 的 BlogPost/SeriesGroup 契约
 * [OUTPUT]: 对外提供 groupPostsBySeries —— 把文章列表按 frontmatter 的 series 字段分组
 * [POS]: data/ 层的系列注册表，是"系列名 -> 封面图"这条映射的唯一来源。
 *        封面挂在系列而非文章上：若塞进每篇文章的 frontmatter，同系列 N 篇文章就要
 *        重复同一张图 N 次，改封面得改 N 处。这里只登记一次，新增系列加一行即可
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import { resolveAssetPath } from '@/lib/assets';
import type { BlogPost, SeriesGroup } from '@/types/blog';

// 系列名 -> 封面图相对路径（相对 public/，图片实际放在 app/public/series-covers/ 下）
const SERIES_COVERS: Record<string, string> = {
  'AI 转型指南': 'series-covers/ai-transformation.svg',
};

export interface GroupedPosts {
  series: SeriesGroup[];
  standalone: BlogPost[]; // 未归属任何系列，原样平铺
}

export function groupPostsBySeries(posts: BlogPost[]): GroupedPosts {
  const seriesMap = new Map<string, BlogPost[]>();
  const standalone: BlogPost[] = [];

  for (const post of posts) {
    if (!post.series) {
      standalone.push(post);
      continue;
    }
    const group = seriesMap.get(post.series) ?? [];
    group.push(post);
    seriesMap.set(post.series, group);
  }

  const series: SeriesGroup[] = [];
  for (const [name, seriesPosts] of seriesMap) {
    // 系列内正序（从第一篇到最新一篇）——"系列"意味着可顺读，倒序展示会让人从结局读起
    const sorted = [...seriesPosts].sort((a, b) => a.date.localeCompare(b.date));
    series.push({
      name,
      cover: SERIES_COVERS[name] ? resolveAssetPath(SERIES_COVERS[name]) : sorted[0].coverImage,
      posts: sorted,
    });
  }

  return { series, standalone };
}
```

未登记封面的系列，退化为该系列第一篇文章的封面，而不是留白——空白图看起来像加载中，这点跟项目里 giscus 配置"缺配置就显式提示、不留空白假装加载中"是同一条原则。

## 2. 品味自检

- **SRP 分清楚了**：`series.ts` 只管"系列名→封面"和分组，不碰数据获取；`assets.ts` 只管路径补全。原来 `resolveCover` 缩在 `blogs.ts` 里是能忍的，但一旦第二处（系列封面）也要用它，不抽出来就是重复逻辑埋雷——这次改动顺手把这颗雷拆了。
- **没有制造数据泥团**：系列名和封面这两个总一起出现的字段，收进 `SERIES_COVERS` 一张表，而不是散落在每篇文章的 frontmatter 里重复写。
- **克制**：没有做系列详情页、系列描述、系列排序权重——需求只要三样东西，给三样东西。
- **一处可能被挑刺的取舍**：`SERIES_COVERS` 是硬编码在代码里的映射表，新增系列要改代码，跟 `content/posts/` "丢个 md 文件就完事"的哲学不完全一致。这是有意为之——封面是主观视觉决策，放代码里能过 review、能类型检查；不是漏洞，是选择。

## 3. 改进建议

- 如果系列数量涨到两位数，`SERIES_COVERS` 硬编码会开始烦人，可以换成约定式：文件存在于 `public/series-covers/{slug}.svg` 就自动关联，不存在则退化到首篇封面。现在不做，因为中文系列名转 slug 本身要引入一层新规则，规则数量不一定比手写映射表少——先别为假想的"系列爆炸"预铺路（YAGNI）。
- 按 GEB 协议，`app/src/data/CLAUDE.md` 和 `app/src/lib/CLAUDE.md`（如果存在）需要把 `series.ts`、`assets.ts` 补进成员清单，这个我这边看不到实际文件内容，需要你落地代码后手动过一遍 L2 检查。
