### `app/src/lib/paths.ts`（新文件）—— 把 `resolveCover` 提出来复用

`blogs.ts` 里现成的 base 路径补全逻辑，文章封面和系列封面要共用，不能各写一份：

```ts
/**
 * [INPUT]: 无外部依赖，读取 import.meta.env.BASE_URL
 * [OUTPUT]: 对外提供 resolveAssetPath —— 把本地相对路径补上部署 base
 * [POS]: lib/ 层的路径解析器，供文章封面(blogs.ts)与系列封面(series.ts)共用，
 *        避免同一条"补 base"逻辑写两份、上线时只改对一半
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
export const resolveAssetPath = (path: string): string =>
  !path || /^(https?:)?\/\//.test(path) || path.startsWith('/')
    ? path
    : `${import.meta.env.BASE_URL}${path}`;
```

### `app/src/config/series.ts`（新文件）—— 系列登记表

封面图放这里登记，图片文件本身放 `app/public/series-covers/*.svg`（和 `CNAME` 同理，走 `public/` 才能在 `emptyOutDir` 打开时不被清掉）：

```ts
/**
 * [INPUT]: 依赖 @/types/blog 的 SeriesMeta 契约
 * [OUTPUT]: 对外提供 seriesRegistry、getSeriesMeta
 * [POS]: config/ 层的系列元数据登记表，与 giscus.ts 同级——都是"需要人工填一次"的配置。
 *        文章 frontmatter 里的 series 只是个名字字符串，封面必须挂在系列本身，
 *        独立登记表是唯一不会随文章增删而漂移的地方
 * [PROTOCOL]: 变更时更新此头部，然后检查 CLAUDE.md
 */
import type { SeriesMeta } from '@/types/blog';

export const seriesRegistry: Record<string, SeriesMeta> = {
  'AI 转型指南': {
    name: 'AI 转型指南',
    cover: 'series-covers/ai-transformation.svg',
    description: '从工具使用到系统思维的转型笔记',
  },
};

export function getSeriesMeta(name: string): SeriesMeta | undefined {
  return seriesRegistry[name];
}
```

**b) 新增分组函数，紧挨着 `getPostsByCategory`/`getPostsByTag` 放（同属"筛选/整形"职责）：**

```ts
import { getSeriesMeta } from '@/config/series';
import type { SeriesGroup } from '@/types/blog';

/**
 * 按系列分组。未登记 series 字段的文章不参与分组。
 * 系列若在文章里出现却未在 config/series.ts 登记，视为配置遗漏，显式告警——
 * 不静默兜底一张假封面，那和"数据源已死"一样会在页面上无从分辨
 */
export function groupPostsBySeries(posts: BlogPost[]): SeriesGroup[] {
  const buckets = new Map<string, BlogPost[]>();
  posts.forEach(post => {
    if (!post.series) return;
    const bucket = buckets.get(post.series) ?? [];
    bucket.push(post);
    buckets.set(post.series, bucket);
  });

  return Array.from(buckets.entries()).map(([name, seriesPosts]) => {
    const meta = getSeriesMeta(name);
    if (!meta) console.warn(`系列 "${name}" 未在 config/series.ts 登记封面，请补充`);
    return {
      meta: meta
        ? { ...meta, cover: resolveAssetPath(meta.cover) }
        : { name, cover: '' },
      posts: seriesPosts.sort((a, b) => b.date.localeCompare(a.date)),
    };
  });
}
```

**c) L3 头部 `[OUTPUT]` 追加：`groupPostsBySeries` 按系列分组读取。**

## 2. 品味自检

- **数据源不漂移**：series 字段走 `parseBlogMetadata`，飞书和本地 md 共用同一份解析规则——前提是 `lib/feishu.ts` 确实调用了这个函数而不是自己单独映射字段。我没看到 `feishu.ts` 源码，这是本方案唯一没法打包票的点，落地前务必确认，否则会出现"本地文章能分系列、飞书文章不能"的分裂。
- **没有伪造数据**：未登记封面时显式 `console.warn`，不拿占位图或空字符串假装正常，呼应 CLAUDE.md 里"兜底必须是真文章"的原则。
- **DRY**：`resolveCover` 从 `blogs.ts` 私有函数升级为 `lib/paths.ts` 的公共函数，文章封面和系列封面共用一条路径规则，不是两份。
- **YAGNI 边界**：没有引入"系列排序字段""系列内文章手动排序"这类没被要求的功能，系列内部就按 date 排，够用。

## 3. 改进建议（不阻塞这次实现，但迟早要还）

- `Blog.tsx` 和新增的 `BlogSeries.tsx` 会有两份几乎一样的"文章卡片"JSX，落地时应抽成 `components/PostCard.tsx` 共享，否则以后改卡片样式要改两处——这是数据泥团的变体，重复的不是数据是标记。
- L1 `CLAUDE.md` 的 `app/` 一行提到 "config 评论系统配置"，落地后要改成 "config 评论系统配置、系列登记表"，否则地图和地形不同构，违反 SEVERE-003。
- 系列封面目前只支持一张静态图；如果以后要给系列加"进度条"（已读 x/共 y 篇）之类的动态展示，`SeriesGroup` 这个类型已经够用，不需要现在加字段。
