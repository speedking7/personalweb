# 博文同步到微信公众号

> 设计与操作合一：既记录「为什么只能做到这一步」，也记录「每次怎么发」。
> 最后更新：2026-08-28
> [PROTOCOL]: 变更时更新此文件，然后检查 CLAUDE.md

## 一、天花板在草稿箱，不在文章之外

自动化能一路做到「文章躺进草稿箱、所有字段填好」，**止步于点「发表」那一下**。

### 能到草稿箱：实测结论

`draft/add`（新增草稿）与 `material/add_material`（新增永久素材）**本账号实测可用**。
这两个接口的官方文档只写「公众号 ✔ 服务号 ✔」，不写认证要求，也没有发布模块那条回收注记；
而微信开放社区有大量个人主体账号实测报 48001。文档与社区打架，
本站于 2026-08 拿自己的账号跑过 `scripts/wechat/probe.mjs`，三步全通——**以实跑为准**。

换账号、换网络环境、或哪天调用开始报 48001 时，重跑那个探针，别翻社区帖子。

### 到不了发表：官方明文回收

微信在 2025 年 7 月回收了一批接口权限，原话是「个人主体账号、企业主体未认证账号及不支持认证的账号将被回收以上接口的调用权限」。
被回收的是 `freepublish` 全部五个接口，其中 `freepublish/submit` 正是把文章真正发出去的那个。
见 https://developers.weixin.qq.com/doc/service/guide/product/publish.html

注意这条注记**只出现在发布模块那一页**，草稿箱与素材管理两个模块都没有——
这正是「能到草稿箱、到不了发表」的由来，两者不是一回事，别混。

被回收的五个接口里有 `freepublish/batchget`（获取已发布列表），
所以**连「读回已发布文章的永久链接」也做不到**（2026-08 实测同样报 48001）。
这就是为什么 `wechat:` 字段只能手工回填：不是懒得写，是那扇门锁着。

想跨过门槛只有微信认证一条路，而认证只对企业/组织主体开放，个人主体不支持申请；
2014 年 8 月之后注册的个人号连申请入口都没有。唯一合法变通是拿个体工商户执照重新注册组织主体账号，认证费 300 元/年。

绕过去的路存在——用 Puppeteer 模拟登录后台自动填表。**不要走。**
微信 2026 年 3 月的平台规范把「通过脚本、程序托管等自动化方式批量、连续发布内容」明确列为违规，已有封号实例。
注意这与调 `draft/add` 完全是两回事：后者是官方接口的正常使用，前者是伪装成人。

### 最后那一下由人点，本来就该如此

公众号文章发出去之后正文不可修改，订阅号每天只有一次群发机会，「阅读原文」一旦推送更是永久锁死。
这种不可逆操作留一道人工闸门是对的，不是妥协。何况发布后要把永久链接回填进 frontmatter，那一步也跑不掉。

### IP 白名单是这套东西的现实约束

调用任何接口都要先拿 `access_token`，而微信强制要求调用方 IP 在白名单内，不支持通配符。
白名单填的是**你家宽带的公网 IP**，重启光猫或断线重拨都可能换，换了就报 40164，
重跑探针会把新 IP 打出来，回后台改掉即可。

这也是为什么这套东西只在本机跑：GitHub Actions 那类每次 IP 都不同的环境，这条白名单根本没法维护。

## 二、微信环境的五条硬约束

这五条决定了转换器必须做什么，不是风格偏好。

**只认内联样式。** `<style>` 标签、class 选择器、外部样式表全部被过滤，CSS 只能写在标签的 `style` 属性上。
`id` 属性也会被整个删掉，所以锚点跳转在公众号里不存在。

**正文外链点不动。** 微信按 http 匹配，非 `mp.weixin.qq.com` 域名的链接地址会被丢弃，订阅号读者点了没反应。
**但本公众号已发布文章的内链是有效的**，未认证订阅号同样可用——这是站内互指能搬过去的全部依据。

**「阅读原文」是唯一的对外出口。** 该位置不受上一条限制，认证与否都能放任意外链。
每篇文章只有这一个格子能把读者送回博客，且发布后不可修改。

**正文图片必须是腾讯域名。** 外链图片会被防盗链打成红叉，必须先传素材库换成 `mmbiz.qpic.cn` 开头的地址。
本站四篇文章正文零内嵌图片（图片只有 frontmatter 的 `cover`，而封面是在后台单独上传的，不进正文），
所以这一条目前不产生工作量。**将来正文里一旦开始放图，这条会立刻变成最脏的一块活，届时再议。**

**代码块的换行会被吃掉。** 2026-08 实测：把带真实换行符的 `<pre><code>` 送进 `draft/add`，
拉回来看标签与内联样式都完好，**但换行符被换成了 `&nbsp;`**——整段代码挤成一行。
这不是样式丢失，加 `white-space` 救不回来，是换行在内容层面就没了。
解法是在送进去之前把换行变成结构性的 `<br>`、行首缩进变成 `&nbsp;`（普通空格在 HTML 里会被折叠），
微信保留标签结构，两者都活得下来（实测 438 个 `<br>` 全存活，被规范化成 `<br />`）。

这条的普遍教训：**凡是靠「默认样式」或「原始字符」维持的东西，过微信这一道都可能没**。
只有写进标签的属性和结构本身才靠得住。

## 三、设计决策

### 公众号链接写进文章自己的 frontmatter，不另立映射表

发布后在文章头部加一行：

```
wechat: https://mp.weixin.qq.com/s/AbCdEf123
```

文章和它的公众号地址待在一起就不会失联，也不用维护第二个文件的同步。发一篇填一行，天然只增不改。

`parseBlogMetadata` 是逐字段正则提取、不做白名单校验的，未知字段被直接忽略，所以加这一行对前端完全无影响。
`wechat` 字段由转换脚本自己读，**不**加进 `parseBlogMetadata`——前端不消费它，它是发布侧的元数据，
塞进前端契约只会污染那份契约。标准字段（title/date/cover/excerpt）则复用 `parseBlogMetadata`，规则保持一份。

### 互指全部指向更早的文章，所以不存在死锁

公众号永久链接只有发布之后才存在。如果 A 引用了尚未发布的 B，而 B 又引用 A，就会卡成死锁。
现有四篇经查证是零前向引用（08-27 引 08-26，08-28 引 08-27 和 08-26），
只要按日期顺序发，轮到第 N 篇时前面几篇的链接都已就位。

**写新文章时若引用了还没发的文章，这条前提就破了。** 转换器会报错拦住，不会静默出死链。

### 列表页链接换成公众号合集

正文里指向 `/#/blog` 的「前两篇」「前三篇」在公众号里没有对应物——公众号没有文章列表页。
最接近的是「合集」功能，它有 `mp.weixin.qq.com` 的永久链接因而可点，读者点进去能看到整个系列。
合集链接填在 `scripts/wechat/config.json`，需先去后台建合集。

### 样式以 index.css 为唯一基线，另叠极小覆盖

用 postcss 从 `app/src/index.css` 抽 `.prose*` 规则做基线，丢掉 `:hover`、`transition` 这类微信环境里无意义的东西，
再叠一层十来行的手机阅读覆盖（字号、行距），juice 负责内联化。

不照搬是因为 `.prose` 那套排版是照着桌面网页写的，而公众号读者九成在手机上，字号行距直接搬会偏紧。
不另写整份是因为两份样式从第一天起就会分家——这正是 `dataflow` 和 `index.css` 注释里反复防的事。
**覆盖层每一条都必须在注释里写明理由，否则它会慢慢长成一份独立样式表。**

### 查不到就中断，绝不静默降级

引用的文章还没发、合集链接没配，脚本一律报错退出并指名缺什么，不产出半成品。
理由与 `dataflow` 里那条相同：兜底必须是真东西，否则「链接坏了」和「一切正常」在成品上分辨不出来。

### 三条通道，日常只用第一条

**`draft.mjs` 走 API，这是默认路径。** 一条命令把文章送进草稿箱，
标题、摘要、正文、封面、阅读原文全部填好。`draft/add` 的 `content` 收 HTML 标签，
所以送进去的正是内联好样式的那份——**公众号版与博客同一张脸，且全程不经过剪贴板**。
封面走 `add_material` 上传（图文封面只收永久素材的 media_id，临时素材三天过期，不行）。
草稿建失败会回滚刚传的封面，否则素材库会随每次失败堆积，而它有配额上限。

另两条是 `build.mjs` 产的文件，留作 API 不通时的退路（IP 变了懒得改、账号权限哪天收紧）：

**`.md` 走后台的「文档导入」**，支持 doc/docx/markdown、上限 15M，拖进去即可。
代价写在那个对话框自己的提示里：「不支持的样式将转为图片或无法展示」。
Markdown 不带样式，导入后走公众号默认排版，本站的正文链接色、代码块深色底一概不生效。

**`.html` 走复制粘贴**，浏览器打开、全选、复制，微信收到带内联样式的富文本。
样式与 API 通道等价，但多两步操作，且粘贴保不保得住超链接始终没验证过（见第八节）。

**三条通道的链接分流是同一份规则**（`links.mjs` 的 `classify`），只是渲染成不同格式。
HTML 与 markdown 各有一道出厂不变量：前者扫 `<a href>`，后者走 lexer 查 link token 与内嵌 HTML。
API 通道送的就是那份 HTML，因此共用前者。

markdown 里凡是「不该是链接」的地址都用反引号锁成行内代码。剥掉链接语法后地址若裸露，
GFM 的 autolink 会把它变回链接，导入公众号就成了一个点不动的可点样式——与剥它的初衷正相反。

## 四、数据流

```
app/src/content/posts/{id}.md
  → parseBlogMetadata (复用 app/src/lib/markdown.ts，标准字段规则单一来源)
  → marked                        Markdown → HTML
  → 链接改写   站内单篇 → 查目标 frontmatter 的 wechat 字段
              站内列表 → config.json 的合集链接
              其余外链 → 剥 <a> 留文字，地址收进文末「文中链接」区
  → postcss 抽 index.css 的 .prose 规则 + 手机覆盖层
  → juice                         内联化
  → 出厂不变量                    凡链接不指向 mp.weixin.qq.com 一律中止
  ↓
draft.mjs   add_material 传封面 → draft/add 送草稿（正文用上面那份 HTML）→ 人工点发表
build.mjs   写 out/{id}.html 与 out/{id}.md，另打发布清单（退路）
```

Node 24 原生剥离 TypeScript，`.mjs` 脚本可直接 `import` `markdown.ts`，无需构建步骤。

## 五、每次怎么发

```
node scripts/wechat/draft.mjs {文章 id}
```

然后去公众号后台草稿箱：预览 → 确认排版与链接 → 点「发表」 →
复制永久链接，回填进该文章 frontmatter 的 `wechat:` 字段。

送稿前的检查全在本地跑完（链接改写、标题 32 字、摘要 120 字、封面存在、正文体积），
**坏链接不会等到草稿建到一半才发现**。已经有 `wechat` 字段的文章会被拦，
那多半意味着已经发过了，确实要重送就加 `--force`。

改了样式、想刷新草稿箱里那篇（而不是新建一条）：

```
node scripts/wechat/draft.mjs {文章 id} --update
```

它按「阅读原文」匹配草稿，封面沿用原来那张不重传。
**更新会整篇覆盖正文**——如果你在后台手工调过这篇，那些调整会没。
反过来说，值得留下的调整应该固化进 `styles.mjs` 的覆盖层，而不是每篇在后台重做一遍。

发布顺序是定死的，但不必记，工具自己管着：先发两篇 `2026-08-26`（不引用任何文章），
回填链接后 `2026-08-27` 才解锁，再回填，`2026-08-28` 才解锁。

**建合集要卡在中间。** 公众号的合集需要先有已发布的文章才能创建，
而 `2026-08-27` 正文里那句「前两篇」指向的就是合集。所以顺序是：
发完两篇 `08-26` → 建合集、把这两篇归进去 → 复制合集链接填进 `config.json` 的 `collectionUrl` → 才轮到 `08-27`。

API 不通时（IP 变了、权限收紧）退回 `node scripts/wechat/build.mjs {文章 id}`，
产物两种形态任选，另按终端清单手工填后台那几个格子。

## 六、它会拦你的几种情况

工具的立场是宁可中断也不产半成品，因为公众号正文发布后不可修改，坏链接没有补救机会。
每种中断都会指名缺什么，这里只解释「为什么这也算错」：

**引用的文章还没发公众号** —— 最常见的一种，按报错列出的顺序先发那几篇。

**posts/ 里没有这个 id** —— 与上一条分开报，因为处置完全不同：这多半是互指的地址写错了一个字，
去发一篇不存在的文章只会白找一圈。

**某篇的 `wechat:` 不是公众号链接** —— 回填时贴错了，比如贴成博客地址，或先占了个 `TODO`。
公众号永久链接形如 `https://mp.weixin.qq.com/s/…`。

**站内地址没被识别** —— 对照 `config.json` 的 `blogBase` 与正文里写的地址是否完全一致，
**尾斜杠也算**。这条存在的理由：`blogBase` 配错时，全篇互指会一起掉进「外链」分支，
产出一篇互指全部消失、却 exit 0 的成品——那是最坏的一种失败。

**页内锚点 / mailto** —— 公众号里 `id` 属性被微信整个删掉，锚点没有等价物，
把 `#某标题` 印在文末让读者长按复制纯属噪音。这类要人工改稿，改成正文直述。

**正文里有图片** —— 见第二节第四条，正文图片必须先传素材库换域名，本工具不做这步。
不做转换是刻意的，但不做**检测**就会让红叉发出去，所以直接拦住。

**产物里出现站外链接** —— 出厂前的最后一道校验。正文里直接写 HTML 的 `<a>` 会绕过链接改写，
这道网兜住它。

## 七、凭据

AppID 与 AppSecret 存 `scripts/wechat/.env`，格式：

```
WECHAT_APPID=wx????????????????
WECHAT_APPSECRET=????????????????????????????????
```

**不放 `server/.env`**：那里是飞书代理运行期 `app_secret` 的归处，而公众号凭据与网站运行期毫无关系，
`server/` 线上根本不存在。两者唯一的共同点是都绝不能带 `VITE_` 前缀——
那个前缀的含义就是「交给浏览器」。`.gitignore` 的 `**/.env` 已经挡住这个文件。

AppSecret 在后台只显示一次，错过要重置。**一旦以任何方式离开过本机就当它已泄露**——
贴进聊天记录、发进 IM、截图，都算。重置一次的成本远低于被人拿去发文章。

## 八、已知未验证项

**API 通道是走通了的**（2026-08 实测：素材、草稿、清理三步全过，端到端送稿成功），
下面两条只影响两条退路，不影响日常使用。

**粘贴是否保留 `<a>` 标签**。已确认微信会保留 `mp.weixin.qq.com` 域名的链接、丢弃其他域名，
但那是就 API 传 content 而言；「浏览器复制→编辑器粘贴」这条路径上超链接的存活情况没有第一手验证。
真用到 `.html` 那条退路时顺手核对一下，结论回填到本文件。

产物页面的预览样式全部挂在 `body` 上、不另设容器 div，就是为了避开这条不确定性的近亲——
浏览器复制富文本时会把选区内元素的计算样式序列化进 `style`，多一层容器就多一个可能被带走的祖先，
它的 `max-width` 会给公众号正文套上一个固定宽度的壳。挂 body 则一般不会进片段。

**导入 `.md` 后公众号默认排版长什么样**，同样没实测过——API 通道通了之后就没有理由去试它了。
真需要那条退路时再看。
